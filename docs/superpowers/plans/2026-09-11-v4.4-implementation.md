# v4.4：真实变化与空间覆盖参考

状态：设计与实施准备；v4.3发布PR #20仍在检查。本版不新增业务Agent或执行调度平台。

## 已确认的当前差距

- DeploymentAdvisorService按成果完成时间汇集本日/本周候选，尚未比较同长度案件窗口。
- 技防摘要是窗口级数量，不能从总离线率推断某个具体设施已失去覆盖。
- GovernanceService.compare_deployment_scenarios仍采用覆盖系数乘建议分数，不是空间覆盖计算。
- JurisdictionAsset已经保存设施位置、几何、来源、有效期和属性，可复用为覆盖对象入口。

## 实施顺序与契约

1. 固定态势时间窗口与版本快照：每日使用最近完整业务日、每周使用最近完整业务周，
   以Asia/Shanghai定义边界，转UTC查询；上一窗口与本期等长，区间左闭右开。
   案件按案发时间，画像与成果进度按生成时间，分别展示。源数据有修订时形成新快照。
2. 复用已授权案件和标准画像，比较数量、类型、手法、油品及地点条件；否定/不确定不并入肯定标签。
   记录当前和对照计数、可用画像数、来源与缺口，不将处理进度增长说成案发增长。
   技防窗口须可比，不相加重叠时段的存量在线数；范围、统计方式不一致则只提示缺口。
3. 每期最多3项证据化关注建议，变化阈值为版本化规则；无明显变化不重复生成泛化建议。
   建议包含区域、时段、设施引用、资源假设、预期作用、缺口、有效期及非执行边界。
4. 真实空间覆盖计算：从受控设施与覆盖几何/半径读取数据，计算目标覆盖、未覆盖和重复覆盖。
   设备移动、停用和减少资源必须改变几何结果；重叠覆盖按集合并集计算，不叠加比例。
   缺视场或遮挡资料时明确为名义覆盖。位置、覆盖范围或有效期缺失时不补造资源方案。
5. 可达性单独使用v4.2同权限/通行约束的路由服务，保留路网、许可、车型、时间及条件版本。
   路线故障不能回退成直线通行结论；覆盖变化不能被称作已经证明防控效果提升。
6. 页面复用态势/方案比较入口，保留历史成果；旧系数接口兼容标记legacy，不用于新版覆盖排序。
   新成果按冻结输入保存；读取历史成果重新检查当前权限，不接受任意脚本或外部URL。

## 登记井点名义覆盖与方案比较接口

新增 `spatial_coverage_service` 与 `POST /api/deployment-sandbox/spatial-compare`。
默认当前授权辖区，自动选取登记井和摄像头、照明、报警、卡口，不要求逐个选择分析对象。
允许在方案中排除已有设备、假设移动已有设备，不修改资源，不创建执行任务。
圆形名义覆盖由核验的 EPSG:4326/WGS84 点位及显式 `attributes.coverage_radius_m` 计算；
设备还需明确 `operational_status=online/offline` 与带时区的 `operational_status_valid_until`。
没有登记半径、状态过期、未知坐标系、超出来源有效期的数据保留未知，不自动补默认半径或认定盲区。
同一井点被多设备覆盖只计一次，另列重复覆盖井数；停用与位置移动造成的变化可追溯至输入快照。
响应记录算法版本、计算时刻、全部参与输入、摘要指纹与要素引用。
接口最多计算200设备/2000井点，超过明确拒绝，不静默截断。仅管理员/分析员可运行，资源按当前权限校验。

当前边界：这是登记井点的名义圆形覆盖，不是区域面积、摄像机实际视场或道路可达性；
路网状态明确返回 `not_calculated`，不能替代4.2道路计算。新接口暂未接入页面或持久化历史。
旧系数接口仍保留兼容，尚需在日常页面替换并标识历史算法，不能称4.4已完成。
首次覆盖计算及同期变化相关23项检查通过；另补接口认证、授权、字段拒绝与规模上限检查。
