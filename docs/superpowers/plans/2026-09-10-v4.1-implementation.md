# v4.1 实施清单：案件理解、统一成果和内部道路

依据[4.x路线图](../specs/2026-09-10-v4x-upgrade-roadmap.md)。本文件为后续实施清单，
不表示v4.1功能已实现或已发布。v4.0发布检查期间只完成落点核对，不混入其发布提交。

## A. 案件语义画像

当前 `CasePipelineService.build_profile_payload` 已保存标准字段、质量和缺项，
但没有把原文提取位置、否定和矛盾作为版本化语义对象。
旧 `SemanticAnalysisService` 是向量/空间关联服务，不能以其名称冒充原文理解已完成。

- [ ] 复用Outbox与CaseAnalysisProfile，添加语义payload版本及抽取规则版本，不再建重复预处理Agent。
- [ ] 每项结果记录源字段、原文摘要、字符区间、原文片段、标准值和明确陈述/否定/推断/缺失类型。
- [ ] 区间按Unicode字符而非UTF-8字节，校验片段必须匹配冻结原文；原文hash与当前画像版本一起保留。
- [ ] 覆盖时间区间、地点条件、设施、油品、手法、工具、车辆及上下游线索；同义词统一，模糊地点保留候选。
- [ ] 内网模型或本地抽取处理原文。未接内网模型时清楚标注本地规则的覆盖边界，不将外部模型用作原文回退。
- [ ] 规则未知、证据冲突和否定作用范围不明时给出缺口，不生成精确坐标或肯定事实。
- [ ] 仅相关输入或抽取版本改变重算，旧画像继续可读；正式案件字段不覆盖。

验收用例必须包含同义表述、否定句、双重否定/不确定表达、同句多实体、时间冲突、
缺少来源去向、原文修改、提示注入文本，以及源片段无法验证时拒绝落入明确事实。

### 已核对的集成位置与版本风险（2026-09-11）

- `backend/app/models/case_pipeline.py` 已有JSON画像、输入hash、结构/字典版本唯一约束，
  语义对象优先扩展payload；无需再建一个平行案件画像表。
- `CasePipelineService.enqueue_case_change` 的当前画像去重核对了版本，但待处理状态去重
  只核对source_hash及状态，未核对schema/dictionary。升级语义规则时需要补充“案件不变、
  旧任务仍pending/processing/degraded”的回归，确保不会吞掉新版本请求；还要处理旧Worker晚到。
- `backend/app/api/case_pipeline.py` 保持现有latest与status入口，前端
  `frontend/src/pages/Cases/Cases.tsx` 已通过`intelligenceFlow`加载画像，语义展示在这里接入，
  不新增普通用户运行按钮。
- `CaseInsightService.enqueue_analysis` 已以profile.id、snapshot.id和算法版本形成幂等键。
  新语义画像应产生新画像版本，由既有Outbox链触发分析；不能原地修改旧画像payload，
  否则旧研判引用与后续冻结评测会失去依据。

待处理状态的版本去重已在v4.1工作分支修复：同时匹配输入hash、结构版本和字典版本。
6个参数化用例覆盖三种状态及两种版本，修复前均因新请求被丢弃而失败；修复后与
案件自动处理、融合分析共41项通过（2.61秒）。用例还验证同版本重复请求去重、旧事件
晚到被标记superseded、新事件完成且不改写案情。这里不代表多版本Worker并行部署的
并发验收已完成，也不代表语义提取功能已交付。

### 原文引用基础实现

`case_semantic_evidence.py`提供不可变原文字段快照、SHA-256、Unicode字符区间及引用校验。
不清洗冻结原文；同一快照序列化顺序稳定。否定、不确定、推断与明确陈述分别保存，
引用存在不等于内容已经证明为事实，所有结果显式`is_official_fact=false`。
11项专用测试加20项流水线回归共31项通过（1.60秒），包括篡改hash、字段、区间、
片段、原文版本、未知字段和空原文。当前仅完成契约，尚未接入流水线或页面。

源码确认`Case.vehicle_info`和`Case.involved_items`为JSON，不能整体当作字符串引用；
后续需按结构化字段路径建立来源契约。不要用JSON重新序列化位置冒充用户案情原文位置。

### 本地提取与后台接入进展

`case_semantic_service.py`已接入`build_profile_payload`的`semantics`字段，画像schema升级为4.1.0，
字典版本引用提取规则版本，因此案件原文未变、规则变更仍会生成新画像。
当前支持车辆、油品、设施、工具、手法、地点条件及时段词项同义归一；每项携带句内原文
引用、词项字符区间和表述类型。重复输入沿用现有幂等链，原文修改产生新冻结快照。

26项语义及引用测试，加流水线、自动处理、融合分析和已有出域回归共73项通过（2.77秒）。
新增集成测试通过真实数据库画像流程确认旧快照保留、原文不被改写、同版本重复请求去重。
否定只对直接简式确定作用范围；复杂否定、双重否定及疑问保留不确定。
肯定/否定并存仅提示上下文待核，不自动选择结论。

尚未完成：完整时间区间解析、结构化车辆/物品来源路径、上下游关系抽取、可信内网模型补充、
页面语义展示与实际端到端验收。本地词项基线不是完整案件理解，也未用于自动改变研判评分。

### 显式时间区间增量

`case_semantic_time.py`接入画像`semantics.time_intervals`，支持双方均给出完整日期的
中文及数字起止时间（例如2026年9月10日22时至2026年9月11日2时）。保留引用和小时/分钟精度，
仅标记`unverified_expression`，不把表达式直接当作案发时间或覆盖`occurred_time`。
非法日期、倒序区间进入信息缺口；昨晚/次日需时间锚，凌晨两点等缺日期表达需上下文，
均不读取系统当前日期自动补齐。未指定时区时保留本地墙上时间与timezone=null。
规则版本升级为`local-terms-4.1.0-2`，随既有字典版本去重机制生效。

时间专项8项，连同语义、引用和流水线共55项通过（1.54秒）。
仍需完成省略年月日的可靠锚定、明确时区与秒精度支持、事件角色区分及案发时间冲突校验；
不能把当前的有限格式解析标记为完整时间理解。

### 结构化来源与上下游字段接入

`case_semantic_structured.py`已为vehicle_info和involved_items建立JSON冻结快照及字段/数组路径引用，
区分布尔与数值，拒绝失配hash、篡改值、无效路径；不将序列化JSON的位置冒充原文位置。
每字段最多提取200个叶节点、路径最多8层、源JSON最多1MiB，超限或非法JSON生成缺口，
不修改原始案件字段。已接入后台画像；规则版本为`local-terms-4.1.0-3`。
这仍是结构化记录引用，不等于已完成车辆属性归一或实体关系推断。

已填写的upstream_source/downstream_destination增加直接原文引用与线索类别；
“无/待查/未知/不详”只生成缺口，“可能”等表述标记不确定，不自动定位或认定来源/去向。
相关结构、语义、时间、引用、流水线和融合回归共92项通过（2.76秒）。

下一步页面落点已核对：`intelligenceFlow.ts`画像payload类型尚无semantics；
`Cases.tsx`详情目前只显示critical_gaps。需增加明确的原文表述/待核/缺口及引用展开，
保留旧画像兼容，不新增必需用户操作。

本批后端全量回归：1054通过、1项专用PostGIS连接测试跳过（37.47秒）。
尚无本版前端改动和界面验收，不能据此标记整个v4.1完成。

### 案件详情语义面板实现

`CaseSemanticProfile.tsx`已接入案件详情，类型契约扩展现有intelligenceFlow画像payload。
沿用办公页面现有主题和字体，以分隔列表和原生details按需展开，不新增必填操作或弹窗。
默认展示前6项表述，其余条目、时间、结构化资料和缺口可展开；原文陈述、否定、待核与推断
分别标识。引用包含来源字段及字符范围，时间保留精度，结构化引用显示真实字段路径。
旧画像无semantics、加载、读取失败和后台更新分别说明；失败时不继续展示缓存画像内容。
组件以案件ID设key，避免不同案件沿用展开状态。404未生成不当作系统读取故障。

6项服务端渲染/展示测试通过，前端全量44文件210项通过；类型检查和生产构建通过。
保留既有大包体积警告。测试覆盖未知类型、否定、转义、无词项、小时精度及状态文案；
它们不替代真实浏览器交互、响应式视觉和真实后台画像到详情的端到端验收，后者仍待完成。

已补做真实鉴权API到页面验证：桌面和420px窄屏通过，修复窄屏父级网格撑宽；
合成画像、引用展开、时间及结构化资料可读，查看前后原文不变。前端210项及构建通过。
见[真实页面验证](../../validation/v4.1-semantic-profile-ui.md)。该场景预先处理画像任务，
实际Redis Worker触发与恢复仍未纳入本版此项验证，不与已有v4.0故障演练混算。

## B. 一个成果对象贯通页面与导出

当前 `reports` 主要是会议报告，案件画像与候选另有读取契约；保留历史接口与含义。

- [x] 定义冻结成果快照：事实摘要、关联条件、候选、支持证据、反向证据/缺口、边界和版本引用。
- [ ] 案件详情、分析工作台、报告中心读取同一对象，不由各页面重新组织不同结论。
- [ ] Word/PDF从同一冻结快照生成；地图、表格、引用与页面一致，保存输入版本而非导出时读取最新值。
- [ ] 导出与历史读取重新校验当前权限；越权或撤权证据不能通过旧快照泄露。
- [ ] 生成文件使用受控目录与服务端文件名，不接受外部URL、任意路径或任意命令。
- [ ] 验证中文、跨页表格、地图和引用的实际导出可读性；不只检查文件存在。

## B阶段实现进展：统一内容组装

`case_result_snapshot.py`新增统一成果组装契约，读取调用方已经授权取得的画像、运行和候选，
不额外调用模型或再次研判。内容包含原始记录摘要、关联条件、语义表述、候选及支持/反向证据、
信息缺口、边界和画像/地图/算法版本。规范JSON复制后计算SHA-256，输入对象后续变化不影响旧内容。
分数明确为规则支持度而非概率；没有运行时保留not_generated和缺口。
拒绝案件/画像/运行串用、无支持证据、无反向证据或缺口、候选排名异常及非有限数值。

本阶段尚未建立持久化表、HTTP接口或Word/PDF导出；内容hash仅证明完整性，不证明访问权限。
下一步必须在当前授权范围内解析每条证据，再持久化并在历史读取/导出时重新授权。
组装专项14项及画像/融合回归合计43项通过（1.83秒），未用组装测试替代权限或导出验收。

### 统一成果当前权限校验（服务层已实现）

`case_result_access.py`要求交付会话显式绑定当前主体范围，每次通过带辖区过滤的数据库查询
核对主案件、画像版本、运行与地图版本，以及每条案件/画像/地图要素引用；不复用已加载实体的
访问判断。未知引用、版本串用、无权或已不存在的证据统一拒绝交付，不在错误中暴露引用详情。
源地图要素转移到无权访问的辖区或被删除后，即使历史快照仍存在，也拒绝交付整个成果。
这个保守处理不会删除历史快照；后续如需对已删除来源授权查看，必须另行建立明确的档案授权契约。

16项内存SQLite真实查询用例覆盖未绑定主体、显式管理员范围、范围收缩、身份缓存、关联案件及
画像越权、地图与案件辖区变化、源要素删除、内容篡改和未知引用；连同组装、范围过滤、画像流水线
共55项通过（1.86秒）。hash只用于完整性，不是签名，也不允许接收用户上传的任意成果作为可信数据。
该服务尚未接入持久化/HTTP读取/导出，不能据此宣称最终接口权限门禁已通过；下一步接入时需补做
真实鉴权接口与导出路径验证。

### 后台自动生成与升级补齐（已接入）

画像任务完成时在同一事务冻结基础成果；融合任务完成/复用既有运行时冻结含候选的成果。
保存原始案件仍只提交原有Outbox，不等待成果；后台失败回滚画像/成果，沿原任务重试恢复。
内部冻结方法只返回编号，不向用户输出内容，也不通过临时赋予管理员范围绕过读取权限。

新增只读`GET /api/cases/{case_id}/results/latest`，优先读取当前画像和当前地图匹配的融合成果，
否则读取当前画像的基础成果。旧地图成果只可按历史编号读取，不冒充当前分析。案件修改或画像规则
已升级但新画像尚未生成时，返回`freshness=pending_update`；匹配源摘要、结构和字典版本时为`current`。
GET不会隐式保存数据；页面后续必须呈现等待更新状态，不仅展示内容。

新增常规后台任务`aicommander.case_results.reconcile`（60秒），复用Outbox分批补齐升级前已有的
当前画像及已完成融合运行，每轮最多两批各50个待补对象，单次消费50个事件。版本化幂等键去重，
失败/待处理事件不会反复占据扫描首批；过期租约可恢复，三次失败保留failed供运维查看。
此任务仅汇总已有画像，不替代管理员的历史原文画像回填；没有画像的老案件仍走原回填流程。
部署需先执行迁移再更新Web、Worker和Beat，停止后台时案件保存仍可用。

数据库服务链验证了无生成接口调用的自动产出、原文更新标记、旧地图隔离、任务失败回滚及重试、
幂等补齐、失效租约、旧规则任务终止和实际注册任务函数消费；真实鉴权测试补验latest撤权。
全量后端1101通过/1跳过（39.12秒）；随后新增任务注册/latest规则新鲜度等专项17通过（2.05秒），
自动成果后的案件删除另1项通过（0.70秒）。这些测试未启动真实Redis Worker，不冒充队列部署演练。
页面统一展示、Word/PDF、PostgreSQL实库并发和本版隔离部署继续待办。
