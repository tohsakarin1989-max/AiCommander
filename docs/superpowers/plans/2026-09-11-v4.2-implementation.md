# v4.2 实施清单：机动车真实道路融合研判

基线：v4.1.0-stable，0b7e94f95ac96ec2908e8e166ba6e06804a17a94。VERSION暂不提升。
本文件不表示机动车业务路由已完成。按既定4.x路线图交付，不以直线代替道路结果。

## 实施顺序

1. 统一通行条件、独立道路许可和版本契约；原始道路/入口与计算图分层。
2. 持久化道路及条件版本、权限组有效路网、来源与构建记录；PostGIS管理，SQLite仅测试兼容。
3. 固定Valhalla版本与内网运行包；公共道路源加经授权内部道路形成有效图，硬排除在构图前执行。
4. 后端统一调用路径、矩阵与可达范围；关联位置距离必须核验，不让引擎默默远距离吸附。
5. 案件画像自动粗筛和道路精算，返回版本化参考路径/绕行/条件假设；前端地图和冻结报告使用同一成果。
6. 实际道路与合成限制共同回归、权限变更/过期/故障、迁移及隔离部署，验收后一次GitHub发布。

不改变物理车型约束。计算绑定缓存与仅用于目录读取的无车型绑定缓存分离。

新增图文件库存校验，兼容已有来源约束验证脚本的SHA-256格式。
拒绝空图、符号链接、非图文件、无效资源键和摘要不一致；资源根目录仅由部署配置指定。

`vehicle_router.py`固定pyvalhalla3.8.3，仅内部接受位置和显式车型；不接受任意引擎JSON。

## 已实现：路由子进程超时隔离

业务编排通过`road_worker_process.py`启动固定模块`road_router_worker.py`，
只经标准输入传递已验证的位置、车型与服务端图路径，不接受外部命令。
默认120秒路由子进程预算，超时或调用中断清理拥有的进程组并回收子进程。
子进程输出文件上限4MiB，原生错误文字不进入业务响应；缺少可选引擎返回不可用，
不要求核心案件环境安装Valhalla。生产使用Linux/POSIX进程管理。
12项隔离与编排测试通过，包含真实子进程超时后PID不存在、真实冻结图禁转路径成功、
异常退出及非法响应拒绝、计算期间撤权和图损坏阻断。
子进程隔离不是容器权限隔离；当前预算不包含前置数据库查询和图库存校验，
队列并发限制、用户取消入口、部署只读挂载及端到端总预算仍待接通，不能声称完整故障门禁已通过。

### 距离范围执行链与真实几何回归

新增`calculate_distance_reachability`、私有worker操作及`VehicleRouter.distance_reachability`，
只接收起点、车型和距离预算，不接收原始引擎参数。授权编排测试扩展到路线、矩阵、范围三类操作，
覆盖撤权、坏图、模型绑定缺失/不符及引擎失败。该接口仍是内部服务，未开放用户调用。

实际公共片区发现默认expansion简化线形导致3个边界点离开道路（4—8.4米）。
核对[固定3.8.3源码](https://github.com/valhalla/valhalla/blob/3.8.3/src/thor/expansion_action.cc)
后显式设置`generalize=0`，保留完整道路线形再裁剪。
10项范围适配测试通过，包含真实隔离进程封路图和固定两市公共图；后者83段道路端点全部重新调用
原生route，3米搜索限制下均能计算，返回距离不超过505米（500米预算，允许5米序列化/插值误差）。
这验证该片区边界，不证明全域所有限制与最短距离完备性。

本轮相关回归45通过、3条件跳过；另一次worker/范围测试16通过、1条件跳过。
最新10项范围测试已启用两类真实图，无跳过；这些数字存在重叠，不累加作为独立覆盖数量。
源码显示expansion会吞掉底层异常并返回已收集轨迹，完整性确认仍需补齐，不能仅凭有GeoJSON就标为完整成功。
暂不开放页面或声称完整可达范围上线；下一步处理计算完整性与时间预算，再接用户流程。

## 已实现：普通强制转向的唯一出口关闭后继续构图

单来路/单路口节点/单目标、在端点连接的only_right_turn、only_left_turn、only_straight_on，

同来路回转编译为no_u_turn；不封闭整条来路或整个路口，不改变其他来向的许可。
生成关系使用不碰撞的稳定顺序编号，清单记录原关系编号、新成员和标签，源PBF保持不变。
