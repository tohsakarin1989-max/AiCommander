# v4.3：可追问专题研判助手

状态：v4.2 PR #19已合并发布，当前在codex/v4.3.0-stable实施；不表示本版已完成。最终目标仍为v4.5。

## 实现顺序

1. 在既有AgentRun查询任务上增加父查询引用和有界上下文，不新建聊天/案件数据库。
   仅本人已完成或有有效部分结果的任务可追问；创建、消费和读取时重新检查当前授权。
   范围、时间、标签和来源版本显式保存，界面显示继承条件；变更条件必须记录变化及依据。
   不把上一轮原始回答当成可执行指令，不把历史结果描述成当前统计。
2. 扩展现有五类工具：读取已授权案件语义画像、已有道路比较/绕行及统一冻结成果。
   复用业务服务，不重新计算已有道路；查询不同任务形成不同轨迹。
   新计算确有必要时走既有后台队列，不让聊天接口同步执行大型路网构图。
3. 连续追问页面、证据卡和专题报告。沿用现有查询页面及统一导出结构，
   每项事实均来自工具卡或冻结成果，模型只选择工具及整理有引用的内容。
   不足时展示部分结果和缺口，不拼凑结论；不要求用户重新挑选资源。
4. 集中验证继承/变更条件、权限撤销、数据版本变化、不同问题的不同轨迹、取消及导出一致。
   默认8步、120秒；模型未配置明确降级，配置前不声称真实模型端到端已验收。

## 不变边界

- 不开放任意SQL、脚本、URL、文件路径和引擎忽略限制参数。
- 用户问题和案件原文只进入可信内网模型；外部兼容协议不构成出域授权。
- 不自动认定身份、居住地、实际轨迹或正式案件关系，不创建执行任务。
- 条件变化不扩大用户权限，授权变化使旧上下文和缓存失效。
- 不重复建设复核、质疑或多智能体辩论。

完成本版业务闭环后一次集中GitHub更新。复用4.2运行包、地图、数据库恢复证据；

## 已接通：带条件的连续追问

- 现有创建接口增加可选parent_query_id；上下文只由服务端从本人已完成/有效部分结果生成，不接受客户端旧答案。
- 上下文保存上一轮问题、结果摘要、范围版本及有界条件，不复制历史事实冒充本轮结果。
- 查找/统计/周期比较之间继承能表达的条件；工具不能表达原筛选项时拒绝本步并反馈规划器，不静默丢弃。
- 条件变更须引用本轮问题原句，实际变化写入轨迹并在页面显示。引文是可追溯的模型解释，不是意图验证或授权。
- 创建、领取、读取、执行中及完成时复查权限/父结果；取消仍不返回历史敏感内容。
- 页面自动显示“继续追问”，保留“新查询”和“查看上一轮”；继承条件、变化及未执行步骤明确展示。

道路筛选不能被普通案件计数表达时，拒绝该工具调用，避免将“绕行筛选后的成果”误计为所有案件。
页面显示留存距离、绕行参考、来源和版本；不会把过去的通行条件说成当前可通行。
