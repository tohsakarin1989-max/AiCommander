# AiCommander 7.x 上线与实用化升级路线图

## 从 v6.5.0-stable 到 v7.5.0-stable

规划修订日期：2026-09-30。实施状态更新：2026-10-08，**v7.0—v7.5 工作包及指定范围验证完成，统一收口为 v7.5.0-stable；用户已明确接受严格编辑 P95 +8.20%（+2.058ms）的本次例外，并授权提交及 GitHub 发布。原 5% 性能门槛未通过的证据保留，不代表已部署或员工已认可。** 逐项证据见[实施索引](../../validation/2026-10-01-v7x-implementation.md)，发布及例外见[v7.5 说明](../../releases/v7.5.0-stable.md)。

本次按用户最新要求重排：**可上线、能上线、有用、实用、可用，并让员工有意愿持续使用。** 用户进一步明确，当前最费时间的两项工作是：

1. 案件录入。
2. 基础数据底座的整理与录入。

因此，本系列不再以“来源治理、增量计算、情景分析”等技术主题安排版本，改为围绕员工任务交付。技术重构只作为这些任务的支撑，不独占一个看不到实际收益的版本。

本规划起点为 v6.5.0-stable；实际源码版本以根目录 `VERSION` 与发布说明为准。此前[技术导向初稿](2026-09-30-v7x-upgrade-roadmap-initial-draft.md)存档供细节参考；本稿是后续实施的主路线，不要求把两份规划都执行一遍。

**范围说明：** 此处“7.0 大版本路线图”指整个 **7.x 系列**，首个发布节点仍为 v7.0.0-stable。以下把两轮发散审查中可升级、可整合和可简化的事项纳入同一计划，不把全部事项压进首版，也不以重新规划为由推倒已有系统。

**本轮整理内容：** 新增现有功能保留清单、升级与精简事项总表、不可遗漏的共用契约、有条件专项，以及首版与后续版本的边界。所有条目仍是计划，不是已完成状态。

## 零、现有功能保留，不推翻重来

### 处理原则

- **保留：** 当前有效且有独立业务价值的能力、历史数据和人工记录继续可用。
- **整合：** 合并重复页面、重复选案和重复计算，但原有独有业务必须有明确承接位置。
- **增强：** 在现有服务上补可靠性、操作便利和分析深度，不另造一套案件、地图或材料系统。
- **按需后置：** 已有能力保持原权限下可用；尚未实现的扩展登记条件，不成为所有员工的必经步骤。
- **真正停用：** 必须先列明现状、独有能力、替代方式、历史访问与影响，取得用户确认；本路线图不自动授权删除独立业务功能。

“保留”以当前 v6.5 有效业务基线为准，不重新恢复过去已经明确淘汰的执行型模块。被证实不可靠的算法不能因保留历史而继续冒充有效建议：先显式标记问题、保留历史，再说明拟采取的替代或停用措施。

### 既有能力去向清单

| 既有能力 | 7.x 的处理 | 不得丢失的内容 |
|---|---|---|
| 案件新增、编辑、预检、导入、批量修正 | 保留并优先增强录入和恢复体验 | 原始字段、来源、原件、修订和权限 |
| 画像、过程片段、历史案例与经验检索 | 整合读取及后台处理，逐步深化对照 | 原文引用、未知与否定、历史版本 |
| 离线地图、设施档案、区域与时空视图 | 共用查找与上下文，保留不同业务视图 | 地图包、来源、设施身份、历史条件和旧快照 |
| 真实道路、候选比较和已有覆盖/方案比较 | 保留并在资料就绪时使用，复杂扩展按需 | 通行硬限制、当前权限、车型/时间条件和解释 |
| 专题、分析案组与关系图谱 | 保留，作为同一专题或案件的不同视图贯通 | 查询条件、来源关系、人工确认，不把分析案组变为正式串并案 |
| 日周态势、工作部署参考和指挥大屏 | 保留；共享事实口径，减少重复统计和噪声 | 有效建议、证据、适用边界；不增加执行调度 |
| 材料、报告、Word/PDF、历史结论 | 共用目录和阅读出口，旧链接兼容 | 正文、来源、版本、地图及历史人工判断 |
| 多模型会议、经验卡与独立事件 | 保留独立价值，按需使用，不强制进入日常流程 | 会议记录、已确认经验、事件来源及独有权限 |
| 已有奖励测算和涉油计量记录 | 保留当前可用能力及开关，不扩大为财务库存平台 | 数量口径、来源、历史记录及人工决定 |
| 管理员重建、失败重试、重放和运行轨迹 | 保留并收敛到既有运行体系 | 排错、可恢复性、审批边界与审计 |
| 认证、账号、辖区授权、备份与恢复 | 保留并补实际启用闭环 | 当前访问权限、原件、配置与相容恢复点 |

高级功能不是一律改为“仅管理员能用”。业务高级入口保留原有授权角色，运维操作仍由管理员执行；菜单简化不能悄悄收回已有业务权限。

### 每次合并入口必须留下的对照

实施前登记“旧入口/接口 → 当前使用角色 → 独有业务 → 新承接位置 → 历史链接/数据 → 验证方式”。新承接路径验证通过后，才切换重复入口或退出重复写入。未完成承接就保留原路径，不以删除旧代码证明精简成功。

## 一、成功标准先改变

### 不是功能更多，而是两笔账算得过来

**员工的账：** 少填了多少内容，少整理了多少行表格，失败后少返工多少，录完以后能立即得到什么。

**管理员的账：** 能否按一份手册装好，能否配置实际人员范围，是否容易导入和更新台账，故障后能否恢复，是否需要开发人员天天在场。

如果只是把员工原来的 Excel 工作再复制到系统里，同时增加预处理、选择资源、审核画像和管理 Agent，功能再多也不符合本轮目标。

目前尚未确认本系统是否能替代单位其他必用系统。因此：

- 不承诺“一次录入即可替代所有系统”。
- 先支持复用已有表格、文字和系统内已知资料，避免在本系统内部重复录入。
- 需要继续填报的固定表格，可在明确模板后复用本系统数据导出。
- 不擅自接入、代填或自动回写外部业务系统。

### 区分三种状态，避免版本号代替上线

| 状态 | 含义 | 必要证据 |
|---|---|---|
| 源码可发布 | 功能及相关回归、迁移、恢复路径达到本版要求 | 源码、测试和隔离集成记录 |
| 可以向员工开放 | 实际内网地址、账号范围、地图与基本资料、备份及责任人到位 | 目标环境启用清单与实际任务验证 |
| 有人愿意持续使用 | 员工在有真实任务时主动使用，且比原方式更省事 | 同任务对照、实际操作观察和自愿反馈 |

取消目标服务器作为“源码 Stable 门槛”，不意味着可以省略实际开放前的连接、安全和数据检查。也不重新设置 30 天、固定人数或固定真实样本量作为源码发布条件。

“员工愿意用”当前是待验证目标，不能根据测试通过、演示顺利、登录次数或自动生成报告数量直接宣布实现。

## 二、从七个角度发散，但只保留主业务上的价值

| 角度 | 应问的问题 | 本轮重点 |
|---|---|---|
| 能安装 | 内网无公网时，拿到交付物能否启动？ | 可核验离线镜像与资源包、单一当前版安装说明 |
| 能开始 | 空系统第一次打开，管理员和员工下一步做什么？ | 厂区、账号范围、地图、首份台账的短启用流程 |
| 录得省 | 是否能复用原文和已有表格，是否被迫补全未知？ | 辅助填表、模板记忆、未知可保留、失败不丢输入 |
| 整得动 | 一张生产台账是否每次都要重新清洗？ | 首次映射复用、稳定编号更新、仅处理异常行 |
| 用得上 | 录完后能否找到、看图、查依据、拿材料？ | 保存后直达本案、井名查找、现成果阅读与导出 |
| 信得过 | 数据错了、旧了、不完整时能否发现和更正？ | 原文出处、来源日期、差异预览、事实与候选分开 |
| 养得起 | 后台积压、磁盘不足、备份失败时谁来处理？ | 简明运行状态、可恢复任务、维护责任与可控成本 |

不向巡逻执行、通用组织管理、库存财务、视频分析或外部系统集成扩张。四项既有业务智能体能力继续保留，不新增多 Agent 复核网络。

## 三、先把两个最费时的流程做好

### A. 案件录入：从“填写一张复杂表”变成“把已有资料交给系统”

目标流程：

**粘贴已有案情或导入现有 Excel → 形成可核对的录入草稿 → 只补必要内容 → 保存 → 立即查看本案及已有可用资料。**

具体设计：

- 手工录入、文字辅助录入、Excel 导入使用同一字段定义和时间口径。
- 原文辅助提取先生成草稿，显示哪些来自原文、哪些未知；员工可修改后保存，不直接替人确认事实。
- 能从已授权设施目录选择的井名、编号、地址和厂区，不重复逐项填写；同名设施必须区分，不能自动认定为同一口井。
- 提供近期使用对象、常用模板和必要默认范围；不得把上次案发时间、人物、数量等业务事实自动沿用为新案事实。
- 保留未知时间、模糊区间、未定位地点，不要求为了保存编造信息。
- 不增加扫描识别、Word/PDF 资料导入或新的外部系统接入；先做好已有文字、Excel/CSV。
- 规则可提取内容先直接使用；真正需要内网模型的深层提取独立启用，模型不可用不阻断手工和表格录入。

录入可靠性必须先于智能性：

- 保存失败明确说明原因，保留已输入内容并定位可修正字段。
- 区分“确定失败”和“提交结果尚未确认”；超时不能简单要求再建一次。
- 一个逻辑提交保持同一幂等标识，安全重试不重复建案；不能按内容相同自动合并两起真实案件。
- 提供受控的私有草稿和离开提醒。草稿不进入正式案件、统计、分析和普通目录。
- 敏感案情不默认长期存入浏览器本地存储。草稿权限、保留期限、撤权及清理按单位策略配置；退出和账号切换不暴露前一个人的内容。
- 编辑冲突保留双方输入，让用户比较，不静默覆盖他人更正。

保存之后立刻有回报：

- 成功后可以直接查看刚录的案件，不用在列表重新查找。
- 立即可见的是已保存记录、已有地图对象和确定性检查。
- 后台分析分别显示待处理、部分可用、完成或失败，不让员工等待全部 Agent 完成才能继续工作。
- 分析结果是新增帮助，不再要求员工另录一份画像。

### B. 基础数据整理：从“每次重新清表”变成“首次教一次，以后复用”

目标流程：

**选择已有台账 → 自动识别已有模板 → 预览新增与变更 → 正常行按已批准规则处理 → 只处理少量异常 → 地图和档案更新。**

管理员或资料维护员负责首次配置，普通员工不维护坐标转换、字段映射和来源优先级。

- 保留来源登记、工作表、表头、字段映射、时区、坐标系、单位、稳定编号和默认范围。
- 后续同来源表格优先复用模板；表头或单位变化要提示，不静默套错。
- 中文别名、空格、日期和数值格式可按可追溯规则规范化；原始文件与单元格原值保留。
- 生产属性映射补全至现有后端已支持的油品、含水率、状态和有效期，而不只录成地图上的点。
- 同编号更新与新设施分开，同名不同编号不自动合并；没有可靠编号的记录进入待对应范围。
- 一次坏行不拖垮整份台账；返回“新增、更新、未变、待对应、冲突、失败”的清晰结果。
- 无变化的行不重写、不重复生成要素、不重复触发分析。
- 批次可以找回，失败修正可以续做，不靠重新上传文件才能找到上次结果。
- 对正常派生数据按已确认模板和来源规则自动处理；涉及事实冲突、设施身份、正式坐标等改变时沿用相应人工确认边界，不扩大自动写入。
- 公共地图参考、内部生产资料、人工核验分层保存；公共地图更新不能覆盖内部已核验属性。
- 缺含水率、道路入口或技防资料不阻断基础设施查询，但也不能自动补成已知。

收益不能只算点击减少，还要计算：首次模板设置时间、以后每次更新的人工清洗量、错误修正返工、更新后发现错误的成本。

## 四、重新排列六个版本

| 版本 | 用户任务定位 | 主要交付 | 与上一版规划的差别 |
|---|---|---|---|
| **v7.0.0-stable** | 可靠首用与内网启用 | 能安装、能配置范围、能录入并找回、已有地图和材料可用 | 上线可靠性与基础启用前移 |
| **v7.1.0-stable** | 案件录入省力 | 草稿、文字辅助、字段复用、导入续做、一套保存处理链 | 案件录入成为第一项专项升级 |
| **v7.2.0-stable** | 基础台账整理省力 | 完整映射、模板复用、更新对照、异常行处理、来源追溯 | 来源治理服务于“少整理表格”，不是独立平台 |
| **v7.3.0-stable** | 录后即用，找案找井 | 案件与设施统一查找、历史条件一致、录入资料自动关联到现有成果 | 先兑现录入收益，不先扩复杂分析 |
| **v7.4.0-stable** | 现成材料与按需关注 | 常用材料、保留查询条件、对象变化归并、同源周期内容 | 复用已有材料和专题，减少复制整理 |
| **v7.5.0-stable** | 有依据的深入分析与规模化常用 | 环节对照、关键缺口、可解释候选、按影响更新和长期维护 | 不再由数量核对独占收口版 |

这些是逐版增量，不是说查案、地图或导报告要等到 v7.3/v7.4 才能使用。**v7.0 就要兑现现有基本能力**，后续版本提升便利程度和深度。

不必等 v7.5 完成才让员工使用。v7.0 达到实际开放条件后即可从明确范围开始；后续根据日常任务调整，避免“始终升级、始终未用”。

## 五、每版具体做什么、怎么做、如何验收

### v7.0：可靠首用与内网启用

**目标：从“有源码”变成“管理员装得好，员工第一次能做成事情”。**

交付范围：

1. **当前版交付入口。** 整理一份与当前版本一致的安装、启用、备份和恢复说明；旧版本证据移为参考，不要求部署人员在多代手册中拼接答案。
2. **复用离线部署。** 现有预构建镜像模式已有“不自动下载”能力；补齐应用、数据库扩展、前端、必要 Worker、字体、文档导出和选定地图资源的版本/架构清单及校验。地图构建、路由和模型按所开能力配套，不强制全部同时启用。
3. **最小启用向导。** 复用已有接口完成厂区、默认范围、账号辖区、地图版本与首份资料状态配置；新账号不会因默认厂区变更而悄悄取得额外范围。
4. **录入底线。** 先修明确失败反馈、输入保留、离开提醒、提交状态确认与安全重试；保存成功直达本案。
5. **立即可用入口。** 普通首页用业务动作表达“录案件、查案件、查井场、取材料”；技术运行状态放管理员页。
6. **现存问题修复。** 区间时间漏检、来源/附件分页、材料回跳丢条件；检索、统计与报告统一时间口径。
7. **恢复对象完整。** 数据库、原件、地图、必要配置与密钥恢复材料分别纳入清单；数据库备份成功不等于所有资料可以恢复。

特别注意：当前部署预检对 PostGIS 与 pgvector 的增强校验按 5.x/6.x 版本分支执行。进入 7.x 时必须改为能力契约检查或覆盖新版，不能只改版本号后退回较弱的检查。

验收以四件实际工作为主：

- 员工登录后录入一案，遇到一次保存错误仍可继续，不丢输入、不重复建案。
- 保存后能找到本案，能按区间时间查回。
- 断公网后按已发布地图查看已授权设施；未发布地图明确提示，不偷偷请求公网。
- 能打开已有材料并导出；管理员能在独立环境恢复相容数据和所需文件。

本版不承诺道路资料齐全、模型已接通或全厂数据已整理。所开放能力必须与真实就绪状态一致。

### v7.1：案件录入省力

**目标：同样一份案情，更少重复填写、更少返工。**

- 在现有表单与原文辅助基础上，整理最短常用路径和按需展开的补充字段。
- 完成私有草稿恢复、并发编辑冲突提示、草稿转正式记录的幂等提交；不把草稿纳入正式统计。
- 借助设施目录选择地点，复用可靠已知信息；不填充没有证据的时间、油量、人员或车型。
- 复用已有 Excel 工作表、字段映射、模板、预览、防重与失败行修正；新增“最近导入批次”及失败修正输入保留。
- 模板明确时间解释。国内无时区表格经首次确认采用单位业务时区，不能直接按当前导入默认 UTC 解释；旧数据不静默批量改时区。
- 后台预处理收敛到同一来源版本链。旧预处理消费者逐一适配后退出旧写入，历史结果与独有业务不删除。
- 原文提取结果有出处、可修改，未知可保留；本地规则与实际内网模型能力分别标注。

验收：

- 员工可从已有文字或常见表格完成录入，不被要求重填系统已有可靠信息。
- 关闭页面、请求失败、重新登录或导入修正失败，不会未经提示丢掉应保留的工作。
- 同一逻辑提交重试不产生重复案件；两起内容相似的真实案件不会被强行合并。
- 时间、坐标不确定仍可按既有规则保存，来源修订和人工更正可追溯。
- 用同一份输入与旧流程对照，记录耗时、重复填项、求助次数与返工；没有实际观察时只报告功能通过。

### v7.2：基础台账整理省力

**目标：第一次配置之后，下一次更新不用重新清洗整张表。**

- 地图资料管理补齐已有后端支持的生产字段映射，提供可下载的中文示例及每个字段的解释。
- 统一导入体验和批次状态，但不新建通用数据中台；案件与设施保留各自校验规则。
- 提交前列出新增、更新、无变化、身份待对应、冲突和失败；异常定位到行与字段。
- 同来源模板复用并版本化；结构变化先提示，避免旧模板错误套入新表。
- 来源职责先覆盖确有冲突的关键字段/字段组，不为全部字段建立复杂审批。经纬度与坐标系、含水率与测量口径等耦合字段不得跨来源乱拼。
- 保留有效时间、接收时间、台账原件和行号；明确未知、未提供、清空、撤销的差别。
- 复用现有地图分片上传、后台验包、发布和回滚，补“继续上传、查看失败、保留当前版”的可操作页面。
- 员工或维护员可提交有来源的问题标注；正式设施变更仍由获授权人员处理，不让普通员工维护坐标体系。

验收：

- 用同一来源初次导入、再次更新、第三次原样导入验证：模板不用重配、旧值可对照、无变化不重复写入。
- 异常行不会阻止正常记录按既有规则处理；批次关闭后仍能找回续做。
- 同名不同编号设施不合并；未知坐标系或越界坐标不自动发布。
- 公共地名与登记设施分开，外部更新不覆盖内网核验数据。
- 更新或地图构建失败继续使用上一有效版本；来源与变更能追到具体行。
- 首次模板配置成本与后续每次整理成本分别记录，不能只展示“导入耗时”。

### v7.3：录后即用，找案找井与资料贯通

**目标：员工刚录进去的内容，不只是存起来，而是马上能帮助查找和了解情况。**

- 地图直接支持授权内井名、别名、编号、地址和公共地名查询；分类显示生产设施与公共参考，不必先进入聊天或记 ID。
- 完整搜索不受当前地图首屏数量或列表当前页限制，点击后定位并打开已有档案。
- 案件可从原文、编号、地点条件与已有标准标签查找；规则和词项检索在未配置模型时也能使用。
- 案件、设施、专题、材料跳转保留当前对象、时间范围、来源版本和返回位置。
- 同一设施在案件与档案中使用统一历史条件：区分当时有效、后来补录、当前状态与未知。
- 支持“当时知道什么”和“现在回看历史”两种明确口径；案发区间内条件变化时不取中点冒充确定事实。
- 保存后自动读取已有历史参考和设施资料，不重新要求选择一批案件/井点；没有匹配与索引故障分别提示。
- 关联分清明确记载、空间邻近和候选解释，不因为附近有案件就认定设施涉案。

验收：

- 能找到较早案件、旧井名、同名不同井；权限范围内搜索完整且无越权摘要/数量。
- 新增、更正、删除与撤权后，搜索和资料页面不会继续把失效内容当现行。
- 同一时间上下文下，各入口使用同一适用资料。
- 从案件到设施再到材料，能返回原位置；搜索不需要用户理解画像、向量或 Agent。

### v7.4：现成材料与按需关注

**目标：减少复制、拼表和每次重新组织材料，而不是增加报告生成流程。**

- 在现有统一材料和 Word/PDF 导出上，适配少量确实经常使用的单位格式；优先选择实际样表，不开发通用模板设计平台。
- 可先围绕案件资料摘要、设施资料单和周期情况材料验证价值；具体纳入哪些由实际用途决定。
- 同一成果供页面、地图、表格和导出复用；“换一种格式”不再次分析全部案件。
- 文件名使用业务标题、日期和版本，保留来源回跳；分享或导出仍按当前权限。
- 原始数据、系统推断、人工编辑文字分开。导出后在办公软件中的修改不会自动写回事实，也不冒充仍与系统实时同步。
- 复用已有持续专题，把关注对象或条件保存一次；重要变化按对象归并，无变化不重复提示。
- 提供少量可直接理解的专题模板，例如“同类手法的地点条件差异”“设施的明确关联、邻近与候选对照”“关键资料缺口”。展示实际条件、工具和范围，标题本身不当作已执行的查询。
- 提醒服务于“资料已补充、依据已过期、关注对象出现相关新增”等任务，不要求用户把未知、未读和后台排队全部清零。
- 新提醒默认系统内可见，允许减少或关闭低价值提示；不擅自新增外部消息、邮件或推送。
- 大屏仅复用同一口径的统计和成果，不另算一套分数，不把员工操作次数作为排行榜。

验收：

- 员工能拿到格式和内容可用的材料；减少了哪些复制和调整步骤有明确对照。
- 图、表、正文和引用同版，缺资料明确，不用示例内容填空。
- 关注条件不丢失、不扩大权限；重复后台更新不重复制造工作量。
- 不出报告、不建立专题、不确认所有候选，不影响案件正常使用。

### v7.5：有依据的深入分析与规模化常用

**目标：在录入和底座已能维护后，让积累的数据产生更深入的实用价值。**

- 复用已有过程片段，比较当前案与历史案相似在什么环节、有哪些差异、经验为何可能不适用。
- 明确否定、不确定、反向条件与缺口，不为了完整展示补造盗取、运输、囤储或销赃链条。
- 将生产属性、入口、道路和历史条件放在同一份候选解释中，继续保留最多三项主要展示。
- 关键缺口从“一般缺项”深化为“该缺口影响哪些候选”；有实际计算依据才排序，不靠模型想象补充收益。
- 按实际重复工作量推进内容哈希复用、失败隔离、范围依赖与材料目录投影；不是先做全库重构再交付价值。
- 依赖包括选中对象、检索范围、新增设施/道路和条件到期，不能只更新旧路径引用。
- 大任务冻结范围并分批续跑，说明扫描、入口核验与道路计算完成度，不把有限预算称为全域最优。
- 多员工同时录入、导入、检索或生成材料时，后台任务不得挤占核心保存；给管理员清晰的积压、失败和容量状态。
- 管理员可对已确定失败的派生任务安全重试；不自动反复重放正式写入或批准动作。

验收：

- 相似、差异与每项候选可回到准确来源；无证据时允许空结果。
- 固定输入下增量与完整计算一致；无关变化不反复处理未变原文。
- 失败隔离、取消、续跑、源版本变化及当前权限复核有效。
- 同一冻结环境与负载下验证核心录入、并发查询及后台积压恢复，分别报告源码/组件/现场结果。
- 展示使用真实业务链，不能用演示算法代替日常服务。

## 六、管理员能维护，才算真的能上线

### 上线前只做必要启用，不先填满全厂数据

最小启用顺序：

1. 明确使用范围、资料负责人和运维负责人，复用已有角色，不新建组织流程平台。
2. 确认可访问的内网地址、HTTPS、备份位置、可用磁盘和服务器架构。
3. 建立实际厂区与账号可见范围，用普通员工账号核对权限。
4. 导入并发布一份经过校验的现有离线地图及必要地名资源。
5. 用已有真实资料建立第一份可复用的设施模板，核对编号、坐标系、所属范围和资料日期。
6. 员工完成本轮准备开放的实际任务；没就绪的高级能力明确关闭或受限。
7. 交付“怎样录入、怎样导入、怎样找回、怎样报错”和管理员恢复清单。

不要求一次收齐全部道路、油品属性、技防资料。可从明确资料范围开始，但不能把局部可用说成全厂覆盖。

### 运行成本要看得见

- 复用现有预构建部署、备份、地图和模型包装能力，不重复建设。
- 交付清单区分核心可用包、道路能力、语义能力与高级模型，明确各自依赖和真实验证状态。
- 不默认必须买 GPU 或云服务器；是否需要由目标机器资源、实际模型和负载决定。本计划不采购、不下载大型资源、不启用外部服务。
- 已有地图和路网未变时不重下载、重制图或重编译。
- 备份覆盖实际恢复需要的数据库与文件；分开保管必要密钥，避免备份泄露原始案件。
- 管理员看到队列积压、备份时间、可用空间、地图版本和已开能力状态；普通员工不看到一堆技术告警。
- 磁盘不足、大导入超预算或模型不可用时明确限制相应能力，保护原始数据和核心保存，不能靠默默丢任务维持“健康”。
- 诊断导出仅含必要脱敏运行信息，不默认包含案情、提示词、坐标或密钥。

## 七、员工为什么会愿意用：用真实任务验证

### 不用登录次数证明价值

优先观察以下指标，先记录基线，再确定合理的改善目标；这里不编造当前耗时或收益百分比。

| 工作 | 观察指标 | 防止自欺的核对 |
|---|---|---|
| 录一案 | 有效操作时间、重复填项、错误次数、失败后恢复成本 | 不能通过少记必要事实来假装更快 |
| 导一份案件表 | 首次配置与后续导入耗时、修正行数、失败续做成功率 | 首次人工清洗和模板准备也算成本 |
| 更新一份生产台账 | 人工整理行数、需人工判断的冲突数、重复设施与错误更新 | 不以错合并、猜坐标换取自动化率 |
| 找一口井或旧案 | 是否找到正确对象、耗时、求助次数 | “没有匹配”和“未完整检索”分开 |
| 取一份材料 | 复制拼接次数、格式调整时间、引用核对成本 | 能下载文件不等于材料可直接使用 |
| 持续使用 | 有真实任务时是否自愿再次使用、放弃在哪一步 | 低频任务不以每日活跃衡量，也不强制签到 |

这些数据尽量通过代表性任务观察、用户自愿反馈和必要的聚合运行记录取得。不得用个人操作排名、强制活跃或暗中采集敏感案情来推动使用。

### 最小试用方式

- 请实际录入人员、资料维护人员分别独立完成自己熟悉的工作；这两种职责可以是同一个人。
- 先不给长培训，观察哪里找不到、看不懂、怕出错；必要说明直接改进页面和短指引。
- 对照原来的文字/Excel方式，包含出错和中断场景，不只演示顺利路径。
- 优先修复阻碍完成任务的问题，再决定是否投入高级分析。
- 不等待固定天数或人数才发布源码；若实际任务尚未验证，诚实记录“使用价值待确认”。

### 首次使用的即时回报

案件录入后：记录没有丢、能找回来、已有井场资料不用再抄、可看到相关历史参考。

底座导入后：不再只是一张表，而是可按井名查找、定位、追溯来源、下次按模板更新的资料。

这两项收益应在前期版本发生，不等待后台资料攒满或高级模型接通。

## 八、原规划的取舍：明确减少，不继续加码

| 原想法 | 调整后处理 | 原因 |
|---|---|---|
| 复杂情景与多条件方案模拟 | 保留已有能力，后续按明确业务需求开展专项 | 不是当前最费时的工作，不应挤占录入与台账治理 |
| 油品批次与数量核对独占 v7.5 | 降为可选专项；已有测量事实和单位字段继续保留 | 尚未证实日常频率和资料完备度，不为了功能增加必填数据 |
| 全字段来源治理平台 | 先做实际生产字段和冲突字段组 | 不把资料整理人员变成数据建模人员 |
| 一次性重构全部依赖和索引 | 按影响与真实瓶颈逐步实施，保留安全回退 | 不用长期基础工程推迟员工受益 |
| 重做地图引擎、重新采集两市 | 复用已有离线包与校验证据，完成启用和维护 | 当前重点是导入自己的资料并能找到，而非再次制图 |
| 更多 Agent 页面、复杂运行中心 | 管理员按需使用，普通入口保持业务任务 | 员工不应承担管理智能体的成本 |
| 报告工厂、每案必建经验卡 | 复用已有材料，按需导出和沉淀 | 不增加形式性工作 |
| 绩效式使用排名、强制每日清零 | 不建设 | “愿意用”不能靠制造额外考核实现 |

后续专项仍须遵守来源、权限、道路硬限制和原始事实保护，不因“仅做假设”放开限制。

## 九、共同技术与发布规则

- 页面读取不触发模型、道路计算或正式数据写入；用户明确录入时的草稿保存与正式提交各自有独立契约。
- 原始事实、派生画像、冻结成果和人工判断分层；旧入口收拢前清点消费者，历史材料与独有功能不丢失。
- 原文指令仅是资料，不得控制工具；不提供任意 SQL、Shell、文件路径或外部 URL 执行。
- 外部模型只接收按政策审核的脱敏特征；原始案情和精确生产信息留在内网。模型协议兼容不等于允许原文外发。
- 未配置真实模型时明确标记相关能力未启用；模拟响应和聊天模型不替代系统真实配置验收。
- 缺资料、未配置、待处理、部分完成、失败、过期、受限分别显示，不能一律变成零或“没有问题”。
- 当前权限在读取、缓存、后台发布和导出时复查；历史权限不绕过当前撤权。
- 开发期间按影响验证；每版集中执行核心回归和本版任务链。高风险保存、权限、迁移和道路规则补对应真实组件验证，复用无变化组件的有效证据。
- 功能合并必须验证第零章保留清单中受影响的独有业务、历史读取和角色权限；不能只验证新页面。无可靠迁移或兼容路径时保留原入口。
- 工作区已有界面、演示和文档修改单独核定，不覆盖、不自动混入版本工作包；不把用户原有修复计作本轮新成果。
- 案件保存 P95 沿用固定负载下相对基线退化不超过 5% 的目标；地图冷启动沿用 5 秒目标，并记录实际环境。不能拿本机服务调用时间冒充员工端性能。
- 30 天试用、固定真实样本量、全厂道路收齐和全部现场确认不恢复为源码 Stable 门槛；实际开放仍完成所开放能力的现场确认。
- 每个 v7.x.0-stable 完成后，在授权范围内统一发布一次代码、迁移、验证、恢复与未验证能力说明；普通修正不逐次建立 Release。
- 保留上一 Stable 相容恢复点；应用回退与数据库恢复分开，保护升级后新增原件、资料和人工判断。不清空现用库通过迁移。
- 本稿最初的整理仅修订路线图并保留初稿；后续按用户授权实施，实际版本、验证和发布分别记入实施索引，不因规划条目存在就认定已经完成。

## 十、当前源码核对依据

以下是本轮有针对性的源码检查，不是全面实机验收，也不证明员工采用意愿。

## 十三、从技术初稿保留的共用契约

业务优先不等于省略数据正确性。以下细节纳入对应版本的实现与验收，防止简化操作后产生错误结果：

1. **时间口径（7.0）。** 查询窗口起点包含、终点不包含；区间按相交检索，未知单列。跨周期可能涉及的案件数不能直接相加为唯一总数。保留精度与时区；起止相等的旧区间有明确匹配规则，不悄悄丢弃。
2. **来源与明细身份（7.2）。** 保存导入批次、工作表、行、修订与对象引用。地点、车辆、人员、计量明细的跨版本对应使用稳定 ID 或可验证映射，不凭数组位置、姓名或数值认定同一记录。重排、同值重复、删除再新增须可区分。现有计量原值、单位、毛净口径、时间、环节和来源继续保留，不能因数量核对专项后置而丢弃或延后保护已有事实。
3. **字段职责（7.2）。** 同级冲突不自动选最新；空值、未知、明确清空和撤销分开。耦合字段整体解析，人工裁决版本化；只隔离受冲突影响的字段和计算，不无故隐藏整份对象。
4. **历史条件（7.3）。** 业务有效时间与系统获知时间分别记录；冻结回放不能带入未来才知道的资料，使用现有资料回看历史须标明迟到补充。模糊时间区间保留全区间支持、部分支持和未知；历史阅读仍按当前权限。
5. **模型与提取（7.1 起）。** 自动提取、规则支持、模型表达和人工事实分开。保留原文位置，结构或引用校验失败保留未知；外部模型不接原始案情与精确生产坐标，原文不能发号施令。真实模型能力与无模型预设分别验收。
6. **智能查询与专题（7.3—7.5）。** 工具白名单、取消、步骤与时间预算沿用既有契约；追问继承明确条件和版本。统计来自授权全集，不从典型案例或当前页推算。大型工作进入既有后台，不能悄悄扩大查询范围。
7. **内容复用与增量（7.5）。** 向量复用绑定规范化内容、模型和配置，但来源修订仍独立留痕；A→B→A 不能抹去历史。依赖包含未入选但可能影响结果的范围及自然到期。可靠范围依赖尚未验证前，保留现有防混版保护；不能精准判断时保守失效。
8. **路由与覆盖（全系列）。** 资料可见性与道路许可分别核验；禁行、未知门禁、车型限制等硬约束先执行。路由失败不以直线冒充道路；新增道路可能产生捷径，不能只重算引用旧道路的结果。假设不能成为新授权依据。
9. **目录与缓存（7.4—7.5）。** 可重建索引不是事实库或授权凭证；范围、条件、内容和授权版本共同约束缓存。正确鉴权再计数分页，交付前复核，不能泄露受限对象的存在、摘要或数量。
10. **材料与人工判断（全系列）。** 页面、地图、导出引用同版；正式确认针对具体版本。新结果不继承旧确认，旧结果不拼接当前资料；只读页面不暗中发起业务写入或新分析。

### 每版收口如何证明“简化但没丢功能”

- 对应第十二章 A—F 项目登记实际状态：未开始、开发中、已验证、受阻、按需后置；文档条目不能直接标成已实现。
- 给出旧入口到新承接位置的映射、减少的重复操作、仍可访问的历史记录和未改变的角色权限。
- 用当前版用户任务验证新路径，并针对受影响的旧独有功能与历史读取补回归，不重跑所有无关模块。
- 区分源码、隔离集成、目标服务器与员工使用证据；没有实机或业务观察的不填成通过。
- 真实停用、删除或业务范围缩减单独呈现，先确认后实施；暂未承接的有用能力保留原路径。

**本轮最终方向：先让员工少录、少整、少返工，让管理员能装、能养、能恢复；再用已经积累起来的数据提供更好的分析。技术亮点来自这些真实收益，而不是功能数量。**
