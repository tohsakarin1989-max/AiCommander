# 离线公共地图包集 schema 2：传输完整性契约

本契约服务于 v4.0 两市离线地图。当前只实现清单和分片一致性校验，不改变 schema 1 栅格导入，不构成可发布地图验收。

## 资源组织

清单文件固定 `manifest.json`，UTF-8 JSON，上限 2 MiB。根字段：

- `schema_version`: `2.0`
- `bundle_id`: 受控版本标识；`source_version`、`provider`、`license`、`attribution`: 来源和许可声明。
- `contains_internal_data`: 必须为布尔 `false`。此声明不替代数据出域检查。
- `bounds`: 西南东北经纬度；`min_zoom`、`max_zoom`: 原生层级；`display_max_zoom`: 显示放大上限。v4.0 最终内容验收仍须确认原生 6—16、显示至 19，通用传输校验不把清单层级当成实测层级。
- `assets`: 最多 1024 个逻辑资产。必须覆盖 `vector`、`gazetteer`、`style`、`glyphs`、`sprite`、`road_source`、`boundaries` 七类，可包含多个同类资产。
- 可选 `license` 资产保存字体OFL等完整许可文本，不替代七类必需资产，也不伪装成地理边界。旧包不含该可选角色时继续可读；分发时仍须满足各来源许可要求。

每个资产使用唯一 `name`，包含 `role`、独立的 `license`/`attribution`、`size_bytes`、整文件 `sha256`，以及按重组顺序排列的 `chunks`。

字形资产名称为`glyphs-起点-终点.pbf`。内容验收继续要求完整的256段BMP基础资源，同时允许按需追加Unicode补充平面分段；每段固定256个码位、起点256对齐、终点不超过U+10FFFF。所有追加分段仍受总资产上限约束，必须登记、核对摘要及嵌入的范围/字体组标识，不凭合法范围自动生成或访问公网资源。

每个分片声明 `file`、`size_bytes`、`sha256`。文件名只允许小写字母、数字、下划线和短横线加 `.part`，不接受路径或 URL。不同资产不能重复声明同一分片名。

单分片最多 16 MiB，最多 8192 分片，全包资产合计最多 8 GiB；大文件不一次性载入内存。未知字段、重复 JSON 键、空资产、非有限坐标、布尔数值、缺失资源类型均拒绝。

## 续传与完整性报告

`verify_directory` 打开受控暂存目录，拒绝分片符号链接和非普通文件。每次重新读取分片、核对大小和摘要，再按声明顺序计算整资产摘要。

报告提供已验证分片名、通过整文件校验的资产和错误列表，用于下一阶段上传续传逻辑。缺片、坏片或整文件摘要不一致时状态为 `incomplete_or_invalid`；全部一致为 `integrity_verified`。

两种结果的 `publish_ready` 均为 `false`。旧进度记录不能作为跳过复检的依据；暂存目录可能变化，发布流程不能直接根据旧报告重新打开可变文件。

## 后续必须衔接的内容校验

1. 重组到独占暂存位置，以已验证内容建立不可变资产。
2. 深度检查 MVT、MBTiles 元数据和层级，绑定地名索引的原始源/边界摘要。
3. 校验本地样式引用闭包、字体字形及 sprite，不允许浏览器依赖公网资源。
4. 保留完整公共道路对象、节点和限制关系，检查引用及实际覆盖；不可用显示瓦片替代道路原始源。
5. 数据库登记整个包集；原子发布、回滚及历史包读取均绑定同一完整版本。

当前传输清单通过，不代表字体可显示、地图范围无缺失、路网可通行或许可已审定。

## 已实现的受控重组

`materialize_package` 在服务器指定暂存根目录内独占创建 `map-assembly-*` 目录，冻结并重新校验清单，逐片重新读取、校验并写入同一份字节。每项资产同时校验整文件摘要，写入后刷新到磁盘并设为只读。

资产名映射为受控 `asset-NNNN.bin`，避免清单名称与完成标记相撞。全部成功后写入冻结的 `manifest.json` 和包含资产映射、摘要的 `assembled.json`，结果始终声明 `publish_ready=false`。

常规异常及可捕获中断清理本次独占目录，不清理任何旧地图或输入。进程被强制终止/主机掉电可能留下孤立暂存目录，后续运行服务不得扫描目录后直接发布；只能消费成功任务返回、再次核验过的资产。只读文件权限防止误改，不声称能阻止目录所有者或管理员修改。

此步骤不改业务数据库和 current 指针。尚需内容校验、不可变正式存储登记、断电恢复与发布事务验收。

## 已登记包集的版本一致性检查

schema 2 的 `PublicMapBundle.package_hash` 固定为已校验清单的规范 JSON 摘要（UTF-8、保留 Unicode、键排序、紧凑分隔符）。数据库来源、版本、许可和边界必须与该清单一致，不能独立修改后继续使用原包身份。

登记存储键为 `bundles/{package_hash}/assets/{asset.name}`。字形例外：清单名 `glyphs-{start}-{end}.pbf` 对应 `bundles/{package_hash}/glyphs/noto-sans-cjk-sc-regular/{start}-{end}.pbf`，范围按 256 对齐且属于 BMP。该约定与授权字形接口一致。

登记记录使用同一 `public_bundle_id`、`snapshot_id=NULL`；`vector` 映射为现有 `artifact_kind=mbtiles`，其他角色原样保留。检查完整登记集合、类型、大小、摘要和每个文件，拒绝额外或缺失记录、跨包登记、文件及父目录符号链接。

构建、发布及回滚前调用完整摘要检查；健康检查跟随所请求检查级别。任一配套资产不一致时不得切换 current，继续保留上一版本。schema 1 兼容分支要求明确 `1.0` 声明、来源字段和唯一文件声明一致，且 MBTiles 位于旧规范路径 `bundles/{package_hash}.mbtiles`。未知、缺失或与资产布局不一致的版本拒绝，不能通过修改 schema 字段降级为单文件检查。

这一检查只证明已声明/登记资产的一致性，不证明清单包含全部必要字形、样式引用闭包或道路来源正确。`accepted` 必须由后续完整内容验收产生；本轮没有新增允许绕过内容验收直接接受 schema 2 的 API，也没有把测试注入的传输样本当成可发布地图。

## 只读检查入口

`backend/venv/bin/python scripts/verify-map-package-set.py <受控分片目录>`

退出 0 表示分片完整性通过；1 表示缺失或不一致；2 表示清单无效或目录读取失败。命令不联网、不写数据库、不生成地图、不发布版本，也不会改写分片目录。
