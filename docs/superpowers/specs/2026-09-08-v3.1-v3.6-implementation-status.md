## 3. 用户工作流

普通用户不再进入 Agent Center，也不需要选择案件、井点、半径或运行工具：

```text
正常录入或导入案件
→ 案件立即保存
→ 后台生成标准画像和最多三项关键缺失
→ 自动绑定当前厂区离线地图版本
→ 自动生成最多三项双域候选
→ 自动汇入每日/每周态势简报
→ 用户只判断候选和部署参考是否有用
```

管理员只负责地图来源首次模板、异常隔离、离线地图发布/回滚、技防聚合入口、运行版本和脱敏评测。
旧 Agent Lab 的手工选数、任务参数和重放能力只保留为管理员兼容工具，不作为一线业务入口。

## 4. 数据与执行边界

- 原始案件、生产台账、真实井名、精确生产坐标、原图和完整车牌不发送外部模型；旧模型工厂默认只允许受信任内网端点处理原始数据。
- 后端只连接隔离公网的应用网和数据网；前端通过独立入口网仅向宿主机回环地址发布页面端口。任何额外内网模型通道必须由部署侧显式开放。
- 确定性服务计算事实、距离、评分和证据引用；外部模型不是核心依赖。
- 自动能力只写地图标准层、案件画像、候选推断、简报和运行/评测记录。
- 自动修改正式案件字段、把候选写成正式事实、创建巡逻/调查/抓捕/处置任务均被禁止。
- 已认证的非管理员查询由数据库会话统一施加厂区范围；只读授权不能写入，案件子表、结论、知识资产、链条、会议和反馈随所属案件或厂区过滤。
- 内网公共地图与精确坐标外发接口默认返回 `410`，公共地图通过受控更新包进入。
- 生产配置拒绝重新开启旧公网地图拉取、旧外部地理查询、巡逻物化以及未纳入厂区隔离的旧业务模块。

## 5. 发布和 GitHub 更新

1. 本次统一冻结 `VERSION=3.6.0-stable`，应用、前端标识与部署配置同步更新。
2. v3.1—v3.6 合并为一次 GitHub 发布；以后仍按大版本门禁通过后统一更新。
3. 普通修正进入下一大版本候选，不单独发布 Release；生产阻断或高危安全问题走 hotfix。
4. 发布标签必须对应通过最终验证的提交，不把工作区状态或现场待验事项伪装为发布证据。

### Stable 门槛调整（2026-09-09）

- 取消“必须完成30天试用”后才能发布 Stable 的要求。
- 取消“必须积累30起案件、20次业务评价或达到固定采纳率”作为发布前置条件；业务数据按实际工作节奏持续积累。
- 取消“必须先在目标测试服务器复验”作为源码 Stable 发布前置条件；目标服务器上的域名、HTTPS、单位网络、备份恢复和终端体验改为部署后的现场确认，未确认前不得表述为正式投产。
- 真实样本数量、Top-3命中率、建议采纳率、节省时间和4/5实用性评分改为上线后的持续观察指标，用于后续算法校准和版本优化。
- Stable发布仍必须满足：全量回归通过、隔离PostgreSQL/PostGIS迁移成功、权限与数据出域测试通过、核心功能可降级、真实离线地图在受控断网环境可用、备份恢复与v3.0回滚成功、未经人工确认写入正式事实或执行任务为0。
- 在真实数据不足时，使用固定脱敏回归集验证功能正确性，但不把模拟数据成绩包装成真实业务效果。
