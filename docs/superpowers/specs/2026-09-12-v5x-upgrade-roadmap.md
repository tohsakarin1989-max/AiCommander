# AiCommander 5.x 大版本升级路线图

## 从 v4.5.0-stable 到 v5.4.0-stable

确认日期：2026-09-12。

文档性质：用户已确认的升级规格，不是实现完成证明或发布说明。当前实施状态见 [v5.0 集成进度记录](../../validation/2026-09-12-v50-integration-progress.md)。

本路线图完整替换上一版 5.x 规划：取消“反馈改进与交付展示”独占 v5.4 的安排，v5.4 改为“重点设施与区域综合研判”。反馈、评测、回滚和展示随各版本完成。

## 一、总体目标与调整原则

5.x 不再以增加页面、智能体或审批环节为主要升级方式，而是围绕三个目标推进：

1. **精简操作**：合并重复入口、重复选案和重复生成，让用户正常录入后直接使用分析结果。
2. **深化研判**：利用全部授权历史案件、生产资料和真实道路条件，形成有依据的关联分析。
3. **贯通业务**：既能从案件查设施，也能从井场、区域查看历史案件、相关条件和已有成果。

升级基线为 `v4.5.0-stable`。实施前先核定工作区已有界面、权限和历史业务修复，形成升级基线清单；不覆盖其他任务改动，也不把未发布修复算作 5.x 新增功能。

### 保留与精简的边界

- 精简重复入口和计算，不按页面名称直接删除业务功能。
- 独立事件、历史会议、报告、经验卡、人工确认记录全部保留。
- 多模型会议保留为高级可选功能，不进入日常必经流程。
- 管理员批量重建、失败重试和历史重放保留。
- 模拟告警、未来设备联动说明和旧 Agent 实验流程移入展示或实验入口，不混入正常业务。
- 不要求每起案件都生成经验卡、单独出报告或完成多轮复核。
- 原始案件事实不被自动改写；分析完成不等于案件办结。

数据范围继续限定为：现有案件、地图、Excel 生产台账、已有事件及已确认经验。本系列不增加扫描识别、文档资料导入、连续视频或新的外部业务系统接入。

## 二、五个版本的建设内容

| 版本 | 定位 | 主要交付 |
|---|---|---|
| v5.0.0-stable | 日常业务整合与减负 | 一个工作入口、一个案件工作界面、一套成果生成流程 |
| v5.1.0-stable | 案件理解与历史经验检索 | 深化语义画像，统一检索全部授权历史案件与经验 |
| v5.2.0-stable | 道路与生产条件融合研判 | 道路参与候选选择，而非只为既定候选补画路线 |
| v5.3.0-stable | 专题研判与周期材料 | 相似条件案组、持续专题、全库统计及可引用的周期报告 |
| v5.4.0-stable | 重点设施与区域综合研判 | 设施综合档案、全域条件对照、统一地图与区域时间线 |

### v5.0：日常业务整合与减负

**解决的问题**

现有首页、今日工作、待办和闭环工作台相互重叠；预处理、画像、经验卡、结论和报告之间存在重复选案、重复生成和不必要的流程要求。

**升级功能**

- 将首页、今日工作和待办组织为一个日常工作台，展示近期案件、必要补充、待判断成果和重要变化。
- 将闭环工作台的处理卡、缺项提示合入案件工作界面。
- 案件详情统一展示原始记录、自动画像、历史关联、地图道路、候选依据和报告。
- 案件、地图、图谱、助手和报告之间继承当前案件与筛选条件，不反复选案。
- 普通用户不再手动运行预处理；管理员仍可进行批量回填、重建和失败重试。
- 报告和结论草稿复用已有成果，不为不同页面重新分析同一份案情。
- 经验卡按需沉淀，报告按需导出；人工确认仍保留，但不再构成每案必经流水线。

**实现方式**

复用现有服务增加轻量聚合接口，不另建案件或待办系统。聚合接口只读取，各模块独立加载；后台分析继续由案件保存事件触发。

“统一成果”与“正式确认”分开：草稿可以自动形成，正式确认沿用现有权限和记录。历史会议报告保持原来源，不强行转换成新案件成果。

旧页面转为兼容入口或详情标签，保留稳定深链接。日常页面没有数据或读取失败时显示真实状态，不使用示例案件填充。

**验收重点**

- 正常录入、查看依据和导出报告不再强制跨页或重复生成。
- 页面读取不触发业务写入。
- 不生成经验卡、不开报告，不会被判定为案件业务未完成。
- 原有独立功能、历史记录及权限不因整合丢失。

### v5.1：案件理解与统一历史检索

**解决的问题**

现有语义抽取较依赖词典和规则；历史检索分散，部分入口仅检查最近若干案件，不能充分利用长期积累的数据。

**升级功能**

- 在标准画像中增加事件片段：时间、行为、设施、油品、地点条件和上下游线索。
- 区分明确陈述、否定、不确定、矛盾和信息缺失。
- 统一检索案件原文、标准画像和已确认经验卡，覆盖全部授权历史数据。
- 自动提供少量相关历史案例，说明相似条件、关键差异及经验适用边界。
- 优先比较作案手法、地点条件和链条线索，不机械依赖同人同车。
- 将检索结果直接用于案件工作界面和研判助手，不新建独立“知识库操作流程”。

**实现方式**

采用“结构条件＋中文词项＋本地语义”的联合检索。生产检索使用现有 PostgreSQL 增加 pgvector，统一业务权限与版本管理；旧向量接口兼容迁移，不长期维护两套生产索引。

- 中文分词、业务同义词及嵌入在内网完成，模型和依赖离线打包。
- 初版使用授权集合内精确向量检索，结合词项排名融合；相似度不称为准确概率。
- 从原始业务数据重建版本化索引，不直接信任旧索引中的过期内容。
- 案件修改、删除及权限变化触发更新或失效；索引更新不阻塞保存。
- 深层抽取通过可替换的内网模型适配器实现；原文位置和结构校验失败时保留未知，不补造关系。
- 模型未接通时继续使用规则，并明确显示相应能力未启用。

**验收重点**

- 较早的历史案件能够检索，不再以最近 N 条冒充全库。
- 同义表达、否定句、修改删除及撤权有固定验证场景。
- 每条关联可回到对应原文与版本。
- 索引不可用与没有匹配分别显示。
- 历史相似案例不能自动成为当前案件事实。

### v5.2：道路与生产条件融合研判

**解决的问题**

当前先按距离等条件选少量候选，再对其补算道路。道路条件尚未充分影响候选召回和排序。

**升级功能**

- 在最终选出候选前，比较更多设施的道路可达条件。
- 综合设施用途、油品、生产属性、历史条件、可信入口和通行限制。
- 解释候选排名变化：绕行、封路、入口缺失、属性匹配或证据变化。
- 建立案件地点与设施稳定编号、别名和台账来源的对应关系。
- 保留最多三项最终展示，减少用户阅读负担，但不把后台计算限制为三个目标。

**实现方式**

继续使用 PostGIS 和现有 Valhalla，不更换路由引擎：

```text
权限内多条件召回 → 设施与入口核验 → 批量道路计算 → 确定性排序 → 候选与依据
```

新增版本化评分器，保留旧算法用于固定输入对比。通行硬限制先执行，不能用低分替代禁止通行。

未知入口、路网缺失、权限受限和计算失败分别记录。分批计算受预算限制，结果必须说明召回范围和完成度；未完成不能宣称得到全域最优候选。

设施名称相同不自动合并，公共地名点不当作可信入口。历史通行资料不足时，不宣称还原了案发时路线。

**验收重点**

- “直线近但绕行明显”与“稍远但通行条件更相关”的候选能够产生有依据的排序差异。
- 路径、矩阵和可达范围执行相同限制。
- 缺入口、路由失败时，不以直线估算冒充道路结果。
- 结果绑定画像、地图、路网、授权、车辆假设和算法版本。

**版本价值：回答“这起案件，哪些设施候选更有依据”。**

### v5.3：专题研判与周期材料

**解决的问题**

现有全局分析、相似条件组、关系图谱和报告分散，用户需要重复选择数据、拼接统计和重新生成材料。

**升级功能**

- 将相似条件组、跨案关联图谱和专题报告组织为同一专题的不同视图。
- 支持按手法、油品、设施、地点条件和时间窗口进行全库组合分析。
- 将有共同条件的案件组织为“分析案组”，明确不等于正式串并案或真实团伙。
- 用户可保存一次查询形成持续专题，后续直接查看新增依据和变化。
- 将已有日、周态势和专题统计整理为同一来源的周期材料，按需导出，不重复分析。
- 输出总体统计、典型案例、反向情况、信息缺失比例及适用边界。
- 没有实质变化不新增待办、不反复提示。

**实现方式**

扩展现有智能查询工具，增加标准画像全库聚合与统一历史检索。模型选择受控工具、整理表达，不能根据一页案例推算总体。

专题只保存条件、版本、人工备注和成果引用，不复制案件。复用 v5.1 画像及关联结果、v5.2 道路依据，不重新抽取全部原文。

独立事件作为来源明确的补充层保留；已关联案件的事件按来源关系防止重复计数，不能仅凭文本相似去重。

**验收重点**

- 分页大小不改变总体统计，代表案例不冒充全部数据。
- 否定、不确定与肯定条件分开。
- 专题跨次追问不丢条件、不扩大权限。
- 图表、报告和地图引用同一冻结成果。
- 分析案组不能自动成为正式案件关系。

**版本价值：回答“一组案件有哪些共同条件、有什么变化，如何形成可用材料”。**

### v5.4：重点设施与区域综合研判

**解决的问题**

目前已有井位画像，但生产资料、案件、事件、附近环境和研判成果仍然分散；旧点位评分主要依赖邻近关系，难以支撑完整的设施侧分析。

**升级功能一：重点设施综合档案**

从案件、地图或大屏点开一口井，统一查看：

- 生产属性、台账来源、历史名称和版本。
- 有明确记录或人工确认的关联案件。
- 空间邻近案件。
- 系统提出的候选关联及反向依据。
- 已有关联事件、历史研判和报告。
- 已知入口、道路条件、技防资料及缺失项。

以上类别分开呈现。附近发生过案件，不等于该设施涉案；未找到技防资料，不等于没有技防。

**升级功能二：全域生产设施条件对照**

复用历史案件中的已知手法、地点条件和设施属性，对授权范围内的生产设施形成条件对照：

- 有哪些历史案例可参考。
- 哪些条件相似、哪些不同。
- 哪些资料未知或过期。
- 哪些关联已有明确事实，哪些仅是候选。

不强制为每口井打风险分，不预测哪里会发案，不直接继承旧版“邻近案数＋缺少技防”评分。

**升级功能三：统一区域研判地图**

案件地图、辖区底座、区域分析和时空视图共享授权范围、时间条件及选择状态。保留设施、案件、独立事件和时间线等不同视图，不再新增一张孤立地图。

大屏只读取同一批结果和统计口径，不另建评分与分析算法。

**实现方式**

以现有稳定设施 ID 为中心，复用生产台账、地图版本、事件关系和已有成果。新增设施派生摘要及版本绑定，不另建资产主库。

案件画像、台账、设施或道路条件变化后，更新受影响的设施摘要；没有可靠依赖范围时采用明确记录的保守重算，不宣称精准增量。

跨区域资料和历史成果读取仍核验当前权限。设施档案不可访问某项资料时，显示受限状态，不泄露摘要或数量。

**验收重点**

- 同一设施从不同入口打开，资料与关联结果一致。
- 明确关联、空间邻近和候选关联不混合。
- 名称相同但编号不同的设施不误合并。
- 缺失、过期和受限数据不被解释为低风险或没有问题。
- 一处资料更新能够解释相关档案为什么变化。

**版本价值：回答“这口井、这片生产区域，已有资料和历史案件反映了什么”。**

## 三、共用架构、接口与兼容

继续保持“四项业务智能体能力＋确定性编排器”，不增加新的业务智能体。

三类分析共用同一底座：

- 案件视角：利用历史经验和道路条件比较候选。
- 专题视角：组合案件，观察条件分布和变化。
- 设施视角：汇集生产资料、案件关联及历史条件。

三者复用版本化画像、检索和计算结果，不各自重新读取原文分析。

### 主要接口变化

| 接口或契约 | 变化 |
|---|---|
| `GET /api/cases/{id}/workspace` | 只读聚合案件工作界面，返回各模块状态、成果引用及更新状态 |
| 现有画像与成果接口 | 增加事件片段、原文引用、匹配差异、排序依据及计算完整度；兼容旧版 |
| 统一检索服务 | 提供授权内结构、词项和语义检索，返回覆盖范围、来源版本和降级状态 |
| 现有智能查询接口 | 扩展全库标准画像聚合与历史检索，沿用取消、预算及追问契约 |
| 专题接口 | 创建、读取、暂停、查看变化及导出已有成果 |
| 设施综合档案接口 | 按稳定设施 ID 返回资料、分类关联、道路依据、成果及缺口 |
| 区域条件对照接口 | 返回设施条件对照和统计，不返回未经校准的犯罪风险概率 |

新增持久化仅用于检索索引版本、专题及变化记录、设施派生摘要。优先扩展已有画像、成果、反馈和事件对象。

### 数据与兼容规则

- 原始事实、派生分析、人工判断分层保存。
- 案件保存事务只增加必要事件，不同步等待模型或道路计算。
- 所有派生对象绑定来源、算法、模型及权限范围；读取历史内容仍重新鉴权。
- 原文中的指令作为资料内容处理，不能控制工具执行。
- 不提供任意 SQL、Shell、文件路径或外部 URL 执行。
- 地图、字体、检索模型和运行依赖保持离线可用。
- 旧链接和历史成果保持可读；模块整合不批量删除原始数据。
- 大模型不自动认定嫌疑人、具体住址、实际轨迹、正式案件链条，也不创建执法执行任务。

## 四、实施、验收与发布节奏

### 实施顺序

1. 核定 v4.5 基线及工作区已有修复。
2. v5.0 先整合入口和生成流程，确认没有丢失独有功能。
3. v5.1 建设共用画像与检索，供后续版本复用。
4. v5.2 将道路前移到候选选择。
5. v5.3 组织专题、案组与周期材料。
6. v5.4 完成设施和区域侧贯通。

不以固定日期强行发布，也不为凑版本增加功能。

### 验证策略

- 开发期间只运行受影响模块的针对性验证。
- 每版收口统一执行一次核心回归和本版完整业务流程。
- 权限、迁移、索引、道路限制等高风险变化补充对应真实组件验证。
- 地图源、路由引擎和构建依赖未变化时复用已有证据，不重复下载、制图和编译。
- 发现新问题先定位影响范围，不反复重跑无关全项目检查。

共同门槛包括：核心录入和地图可用、原始事实不被自动覆盖、越权与敏感外发为零、失败和缺失明确显示、页面与报告依据一致、迁移和回退不丢新增业务数据。

性能在冻结环境和数据规模下记录；沿用案件保存 P95 相对基线退化不超过 5% 的目标，现场表现单独记录。

### 模型与现场边界

源码、离线集成、目标服务器和正式业务效果分别记录，不能互相替代。

真实模型未接通时，明确显示相应能力未启用；模拟响应和当前聊天模型不能充当系统真实模型验收。现场模型配置不阻塞其他功能推进，但未验证效果不能计入已交付能力。

不恢复 30 天试用、固定真实样本量、完整内部道路或全部现场确认等源码 Stable 门槛。

### GitHub 与回退

每个 `v5.x.0-stable` 完成后统一更新一次代码、发布说明、迁移步骤和回滚材料。普通修正随版本积累，仅生产阻断或高危安全问题发布 hotfix。

保留上一 Stable 恢复点。数据库恢复与应用回退分别处理，保护升级后新增的原始案件、事件及生产资料。

## 五、最终业务效果与竞赛亮点

到 `v5.4.0-stable`，系统应形成三条相互贯通的业务路径：

1. 从案件出发：录入一次，自动得到画像、历史参考、道路条件和候选依据。
2. 从专题出发：比较一组案件的手法、地点条件及变化，直接形成可引用的周期材料。
3. 从设施出发：点开井场或区域，查看生产资料、明确关联、邻近案件、候选解释与已有成果。

普通用户主要面对日常工作、案件研判、地图区域、专题和成果入口；大屏保持直接进入，高级会议与运维不干扰主流程。

竞赛展示集中在真实业务变化：

- 用不同表述录入案件，仍能找到有依据的历史相似条件。
- 调整道路条件，候选选择及解释随之变化。
- 从案件跳到井场，再展开相关历史与区域情况。
- 增加一条资料，准确展示哪些分析发生变化。
- 证据不足时明确保留未知，服务故障时核心业务仍可使用。

**5.x 的最终成果不是更多模块，而是把已有案件、生产设施、地图和报告真正连成一套好用的研判系统。**
