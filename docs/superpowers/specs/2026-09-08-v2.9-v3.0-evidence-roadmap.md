# AiCommander v2.9—v3.4 业务实用与竞赛路线图

> 更新日期：2026-09-08
> 当前基线：`v3.0.0-stable`
> 当前进度：v2.9 证据图谱作为解释底座保留；v3.0 双域态势研判工作台已经完成 stable 门禁。
> 总原则：功能必须减少业务步骤、发现新增规律或直接形成可用成果；不以增加 Agent 数量作为亮点。

## 一、路线纠偏

v2.9 解决“这条结论依据什么”。v3.0 不再建设质疑 Agent、复核 Agent 或多智能体辩论网络，也不围绕
同一份数据反复审核。后续主线改为：

`新增案件进入 → 比较相邻时间窗口 → 发现热点和手法变化 → 联动重点井 → 输出三项核查重点与一页简报`

证据图谱退到按需解释的位置；只有用户需要核对依据时才进入，不成为日常研判的额外步骤。

## 二、版本路线

| 版本 | 业务定位 | 日常实用产出 | 竞赛亮点 | stable 门槛 |
| --- | --- | --- | --- | --- |
| `v2.9` | 单案证据图谱 | 按需查看来源、推断和空间参考边界 | 一屏展开证据路径 | 已完成 |
| `v3.0` | 双域态势研判工作台 | 增量变化、热点演化、重点井关注顺序、三项核查重点、一页简报 | 离线可运行的双域时空态势沙盘 | 只读、无模型可运行、不预测、不调度、相邻窗口可重复验证 |
| `v3.1` | 时空态势沙盘增强 | 7/30/90 天切换、历史同期、区域专题保存与批量简报 | 时间轴播放和条件变化即时重算 | 真实业务样本不少于 30 次，重点建议采纳率和节时可统计 |
| `v3.2` | 作案条件与链条线索发现 | 围绕手法、设施、地点条件和上下游环节形成候选线索 | 从新增案件自动展开可解释候选链 | 不以同人同车机械串案；候选必须人工确认 |

| `v3.4` | 受控跨系统读取 | 安全评审后的白名单证据摘要接入 | 来源签名、跨系统回执和可追踪工具目录 | 不开放任意 SQL、Shell、URL 或自动外部写入 |

## 三、v3.0 交付范围

### 1. 相邻窗口增量分析

- 支持 7、14、30、90 天窗口，并与紧邻的等长上一窗口比较。
- 统计案件数量、案件类型、作案手法和相对集中时点变化。
- 支持区域关键词收窄范围；未来时间和窗口外案件不进入结果。
- 使用稳定数据摘要，相同范围和数据重复运行得到相同版本号。

### 2. 历史热点变化

- 只对当前窗口中具备坐标的案件计算空间聚集。
- 对每个聚集点计算上一窗口同半径案件数量和变化量。
- 使用“历史聚集热点”口径，不写成未来风险或犯罪预测。

### 3. 重点井空间关注顺序

- 计算活动井点与当前窗口案件的限定半径距离。
- 综合本期案件数、较上期变化、高产井标记和坐标核验状态形成关注度排序。
- 未核验井点降低可信表达；空间接近不能作为事实关联。

### 4. 今日核查重点与简报

- 每次最多输出三项，优先覆盖热点变化、重点井空间参考和手法变化。
- 每项必须带案件/井点证据编号、发现内容、建议核查动作和适用边界。
- 生成可下载的一页 Markdown 简报，明确区分事实、发现和建议。
- 当前窗口没有案件时不制造热点、井点排序或泛化建议。

### 5. 运行机制

v3.0 使用一个确定性研判流程串联现有计算工具，不依赖 OpenAI、DeepSeek 或其他模型，也不要求 Agent
Worker 运行。后续如果引入模型，只能负责理解自然语言范围和润色简报，事实计算仍由内网工具完成。

## 四、竞赛演示主线

1. 导入一批历史案件、近期新增案件和重点井数据。
2. 选择 30 天窗口，系统自动与上一窗口比较。
3. 态势沙盘显示新增聚集、主要手法变化和井点空间参考线。
4. 系统只突出三项核查重点，点击即可查看案件和井点依据。
5. 调整时间窗口、区域关键词或井点半径，结果即时重算并生成新版本摘要。
6. 导出一页研判简报，再进入 v2.9 证据图谱核对某一结论来源。
7. 断开外部网络并关闭 Agent，完整流程仍然工作。

竞赛亮点是“新数据进入后，态势和业务重点随之变化”，不是让多个 Agent 反复评论同一份数据。

## 五、v3.0 验收指标

- 正式数据自动修改：0 次。
- 当前窗口、上一窗口和区域筛选边界正确率：100%。
- 优先事项证据引用覆盖率：100%。
- 单次建议数量：不超过 3 项。
- 无数据时虚构热点、井点关联或建议：0 项。
- 预测性、自动调度或自动串案越界表述：0 项。
- 人员、电话、证件号和车辆身份字段进入态势响应：0 项。
- 外部模型不可用时态势功能可用率：100%。
- 图谱或态势接口失败时核心案件、地图和报告流程继续可用。
- 后端、前端、类型检查、生产构建、依赖审计、数据库迁移和隔离部署演练全部通过。

## 六、发布节奏

继续采用“一个大版本一次 GitHub 更新”。开发修正保留在本地发布分支；stable 门禁全部通过后，一次性
创建 PR、合并、标签和 Release。常规修正并入下一里程碑，只有生产阻断或高危安全问题单独发布 hotfix。
