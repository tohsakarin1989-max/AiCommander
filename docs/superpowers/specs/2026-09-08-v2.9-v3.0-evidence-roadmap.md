# AiCommander v2.9—v3.0 证据智能升级路线图

> 更新日期：2026-09-08
> 当前基线：`v2.9.0-stable`
> 当前进度：v2.9 证据关系图谱已完成并通过 stable 门禁；v3.0 证据孪生与质疑智能体为下一阶段。
> 总原则：第一优先可用、实用；第二优先形成可演示、可复核、令人眼前一亮的竞赛能力。

## 一、路线判断

v2.8 已解决“今天先做什么”的问题。后续不继续横向堆模块，而是沿一条主线升级：

`明确下一步 → 看清依据链 → 质疑薄弱环节 → 固化可重放研判快照`

这条路线同时服务日常使用和竞赛展示：日常人员能快速判断结论是否有依据、哪里还缺材料；竞赛现场能直观
展示智能体不是自由生成答案，而是在证据网络内工作，任何推断都能追到来源、任何断链都能被指出。

## 二、版本路线

| 版本 | 定位 | 日常实用能力 | 竞赛亮点 | 进入 stable 的门槛 |
| --- | --- | --- | --- | --- |
| `v2.9` | 证据关系图谱 | 单案证据走廊、来源追溯、断链清单、重点井空间参考、知识资产与 Agent 轨迹汇聚 | 一屏区分来源事实、派生分析、人工确认、未确认推断和信息缺口 | 图谱只读；敏感材料正文和文件路径不输出；推断与空间接近绝不伪装成事实；核心系统不依赖图谱 |
| `v3.0` | 证据孪生与质疑智能体 | 报告生成前自动质疑薄弱依据、对比数据版本、固定可复核快照 | “主研判 Agent 给方案、质疑 Agent 找漏洞、人工作最终决定”的可视化对抗链 | 质疑只生成问题清单；不得自动推翻或确认结论；快照可重放；模型故障时规则质疑仍可运行 |
| `v3.1` | 现场试用加固 | 大样本性能、权限细化、批量证据缺口治理、真实节时指标 | 展示真实采纳率和闭环时间，而非演示数据 | 指定用户累计不少于 50 次任务；高优先级缺陷清零；越权和敏感泄漏为 0 |
| `v3.2` | 受控跨系统协作 | 经安全评审后读取白名单业务系统的只读证据摘要 | 受控 MCP 工具目录、来源签名和跨系统证据回执 | 不开放任意 SQL、Shell、URL；外部写入仍需现有业务接口和人工审批 |

## 三、v2.9 交付范围

### 1. 单案证据走廊

围绕一个案件，按六层组织节点：案件主体、原始来源、空间与链条背景、规则/Agent 分析、人工确认成果、
信息缺口。节点必须标明来源编号、状态、置信口径和是否人工确认。

### 2. 证据路径与断链检测

- 已确认经验卡和报告必须能够回溯到案件或材料证据。
- 草稿知识资产、未确认链条关系、无证据引用的 Agent 成果进入“待复核”。
- 无坐标、缺少核心字段、引用不存在、井点未核验等进入断链清单。
- 输出来源版本摘要，相同数据重复生成应得到相同版本号。

### 3. 双域空间参考

案件与重点井只计算限定半径内的距离，展示为“空间参考”，不输出“案件与井点存在事实关联”等越界表述。
井点是否高产、坐标是否核验分别标注；未核验井点不得提升为确定证据。

### 4. 可视化与操作边界

- 使用从“来源”到“结论”的横向证据走廊，不与已有案件相似关系图混用。
- 支持隐藏/显示未确认推断、空间参考和信息缺口，并可点击节点查看来源摘要。
- 从今日工作台可直接查看对应案件证据图谱。
- 首期只有读取接口，不新增修改、确认、删除或自动补证接口。

## 四、v2.9 验收指标

- 正式数据自动修改：0 次。
- 已展示结论节点的来源引用覆盖率：100%，否则必须进入断链清单。
- 材料文件路径、人员姓名、电话、证件号、车牌原文输出：0 项。
- 未确认链条和空间参考被标记为事实：0 项。
- 相同数据版本重复生成的摘要一致率：100%。
- 图谱接口失败时案件、地图、知识资产、报告和工作台仍可使用。
- 后端、前端、类型检查、生产构建、依赖审计、数据库迁移和隔离部署演练全部通过。

## 五、v3.0 预留接口

v2.9 的断链清单将成为 v3.0 质疑智能体的唯一输入之一。v3.0 只能针对已有节点和来源提出“哪里证据不足、
哪里存在相互矛盾、结论适用边界是什么”，不能访问任意数据库或自行创造新事实。报告确认前展示质疑结果，
由人工选择补证、保留说明或退回，不把智能体意见直接写成正式结论。

## 六、发布节奏

继续采用“一套业务底座、两条发布轨道”和“一个大版本一次 GitHub 更新”：开发修正留在本地发布分支，
完成全部门槛后一次性创建 PR、合并、标签和 Release。`v2.9` 发布后，中间修正并入 `v3.0`；只有阻断
生产或高危安全问题才单独发布 hotfix。
