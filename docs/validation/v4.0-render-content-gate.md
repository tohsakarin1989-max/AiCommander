# v4.0 地图包渲染内容验收

日期：2026-09-10。正式版本仍为 v3.6.0-stable；尚未登记或发布真实 schema 2 包。

## 新增内容

`map_render_bundle_validation.validate_render_bundle` 面向服务端重组目录，串联：

1. 严格解析 schema 2 清单，对读取的渲染资源重新核对字节数与摘要，不信任旧检查回执。
2. 实际扫描并解码 MBTiles，用观察到的图层集合检查样式引用，不接受调用者自报图层。
3. 解码全部 256 个字体分段，校验字体名、Unicode 范围、重复字形、指标和位图尺寸；支持空格省略位图。
4. 校验 PNG 结构与实际解码、图标裁切范围、1x/2x 名称和逻辑尺寸一致性。
5. 复用已有样式本地依赖闭包验证，禁止外部资源引用。

字形协议依据 [fontnik glyphs.proto](https://github.com/mapbox/fontnik/blob/master/proto/glyphs.proto)，三像素边框同时核对当前安装的 MapLibre `parse_glyph_pbf.ts`。固定离线图标格式暂不接受 SDF、伸缩图标等扩展；遇到这些格式明确拒绝，不静默忽略。

## 调用方式

在已安装地图构建依赖的隔离工作环境执行：

```sh
python scripts/verify-map-render-bundle.py /受控目录/已重组地图包
```

输入是 `materialize_package` 生成的服务端目录，不是浏览器提交的任意路径。该命令不访问业务数据库、不发起网络请求、不登记包，也不改变 current。

失败返回非零退出码和简洁错误，不输出内部路径。成功状态为 `render_content_validated`，但 `publish_ready` 始终为 false：尚未覆盖地理完整性、路网、地名字典内容、地名字形覆盖和官方 MapLibre 完整语法等其他验收环节。

## 验证证据

- 字形与图标专项 38 项通过，两个校验模块合计覆盖率 91%。
- 包级 7 项集成测试使用真实 MVT 编码/解码、真实 PNG 与 protobuf 载荷，包含摘要正确但语义错误的资源拒绝、修改后的组装目录重检，以及命令行成功/失败路径。
- 实际公开中文资产 `glyphs-cjk-v1`：按生成清单逐文件核对摘要，并用新解析器读取全部 256 分段、42,220 字形，全部通过。
- 上述字形数不等于所有语言或所有未来业务文字都已覆盖；空分段合法，不虚报覆盖完整。
- 最新完整后端回归：752 项通过、1 项跳过，29.12 秒；隔离地图构建脚本测试 67 项通过，1.29 秒；包含所需链条回归。
- 独立复审通过，45 项相关测试通过，未发现高优先级问题；另做 2,000 组 PNG 字节变异未发现未捕获异常，不将变异测试视为穷尽证明。

当前实现用于后续后台导入的渲染内容阶段。待办仍包括正式导入任务、其余内容门禁、资产登记、发布与回滚端到端验证；不得仅凭命令成功把候选包标成 accepted。

后续进展：持久化导入任务已实现，见 [后台导入](v4.0-map-import-queue.md)；地名字典内容与主名称可绘制字形已纳入联合检查，见 [地名联合验收](v4.0-place-content-validation.md)。地域、道路与正式注册发布仍未完成。

## 全标签字形检查接入后台（2026-09-10 后续）

不再只检查地名索引：后台根据包内实际样式的 `text-field` 提取图层和字段顺序，
在同一次全瓦片解码中检查道路、兴趣点和地名标签；固定标签文字也纳入检查。
支持当前交付样式使用的 `get`、末项为空字符串的 `coalesce` 和普通常量文字。
其他表达式、字符串模板、文本转换及同源不同字段链会明确拒绝，不能略过检查后声称通过。
忽略可见性筛选进行保守检查，不将字形码位齐全表述为复杂文字排版正确。

本轮真实包 `daqing-qiqihar-20260908-candidate-v3` 重新验收，退出 0：

- 全部 1,128,893 张瓦片解码，检查 394,909 次标签出现。
- 实际样式引用的 2,608 个非空白码位全部存在可绘制字形。
- 257 字形分段、42,853 字形以及 21,666 个地点索引联合校验通过。
- `label_codepoint_coverage_verified=true`，`text_shaping_verified=false`。
- `publish_ready=false`；地域覆盖、道路约束及完整样式语法仍需验收，不自动登记或切换地图。

测试：后端全量 914 通过、1 跳过（独立 PostGIS 环境未提供）；
地图联合解码及矢量专项 63 通过。新增用例涵盖地名索引不缺字但常量标签/瓦片标签缺字的拒绝。
标签契约与样式、后台专项 49 通过，新增契约模块首次覆盖率检查 97%。只读复核无阻断问题。

## 官方样式语法校验接入后台（2026-09-10 后续）

后台联合验包现在调用本地 `@maplibre/maplibre-gl-style-spec`，而非信任制包阶段的报告。
固定脚本只从标准输入接收至多 1 MiB JSON，不接收文件路径、命令或网络地址。
Python 启动器不使用 shell，不继承业务凭据和 `NODE_OPTIONS`；10 秒超时、
缺少运行时/依赖、非零退出或无效回执都拒绝验收。失败仍不切换旧地图。

两市完整候选重新联合检查通过，退出 0；官方校验器版本 26.4.2，
`style_syntax_verified=true`，2,608 个标签码位检查仍通过，`publish_ready=false`。
该回执证明语法，不证明地域、道路、文字成形或实际浏览器显示。

专项 51 项通过，Python 启动器覆盖率 100%；真实解码集成 17 项通过，
包括摘要正确但颜色语法非法的拒绝。Python/JavaScript 独立只读复核无阻断问题。
本轮最终后端全量回归 928 通过、1 跳过，35.80 秒；跳过项仍为独立 PostGIS 环境验证。

部署前提仍待完成：隔离地图 Worker 必须包含 Node、`frontend/scripts/validate-map-style.cjs`
及按 `frontend/package-lock.json` 安装的依赖。当前纯后端 Dockerfile 不包含这些资源，
不能声称该镜像已能执行完整地图验包。Node 的 `--max-old-space-size=128` 只是 V8 老生代限制，
不是进程总内存硬上限；容器内存与断网隔离需在地图 Worker 部署阶段落实。
