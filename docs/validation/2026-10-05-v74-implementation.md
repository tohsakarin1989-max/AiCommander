状态更新：2026-10-08。三个工作包及其后端、前端、迁移、恢复与指定隔离浏览器流程已完成，随 [v7.5.0-stable](../releases/v7.5.0-stable.md) 统一交付，不代表曾单独发布 v7.4。用户已明确“接受例外并发布”：严格编辑 P95 25.107→27.165 毫秒（+8.20%，+2.058 毫秒）的单版例外及本轮 Git 发布已获授权，原 5% 门槛失败证据保留。远端发布状态以 GitHub Release 为准，不证明目标部署或真实业务效果。

主范围仍是[7.x 路线图](../superpowers/specs/2026-09-30-v7x-upgrade-roadmap.md)，此处不新增业务平台。以下保留 2026-10-05 的过程证据；早期失败与未验证边界不因发布批准而改写。

## 已有能力，不重复建设

- 8 类材料已有统一读取、当前权限、固定版本地图和 Word/PDF 出口；前端已有业务标题、日期及版本文件名。
- 专题已有三种业务问题、固定或滚动窗口、版本化定义、持久分块、实质变化过滤和原对象来源。
- 自动日周简报已有统一材料读者；高级会议、历史结论、经验卡和旧深链接继续保留。

## 三个小包

| 工作包 | 真正要补的内容 | 不做的事 |
| --- | --- | --- |
| 常用材料和旧入口 | 现有冻结正文的通用展示格式、服务端下载文件名、周期材料直达；旧部署页标明未校准和直线口径，承接到现行材料 | 不伪称已适配单位实际样表，不重新分析，不删除独有统计或执行新任务 |
| 目录与反向引用 | 可重建元数据及来源引用；不为列目录构造每份完整文档；授权在筛选、分页和摘要前 | 不把投影当事实或权限凭证，不把正文查询悄悄变成仅查标题；GET 不回填索引 |
| 专题和首页减负 | 使用已有三类问题的明确预设；同对象变化归并；继续计算但减少提示；显式暂不显示某次变化 | 不增加外部通知，不把读页面当已读，不把静音当暂停计算，不增加案件完成要求 |

设施当前“重新读取并保存资料”已准确说明重新读取的行为。若增加与刚才画面一致的保存，需要单独的服务端版本比较，不能只收浏览器正文或比较设施单行更新时间；尚未实现前不改成“冻结当前画面”。

## 验证与兼容约束

- 复用当前材料/专题回归；只为新增格式、下载名称、目录权限、静音与变化归并补定向验证。
- 原始资料、候选解释、人工判断保持分层；格式变换不改变内容版本或生成新分析。
- 新持久化沿唯一增量迁移链 `v72m01 → v74n01 → v74c01` 承接；模型注册、权限、新库与升级/恢复一起核对，不清空旧库。
- 没有实际单位样表，不将通用格式宣称为单位材料适配完成；真实员工节时另行记录。
- 前版保存性能仍未达既定门槛；2026-10-08 用户接受上述单版例外并授权本轮 Git 发布，不把失败结果改称性能通过。

## 已实现和实际验证

- 材料 reader 与 Word/PDF 统一使用冻结正文的 `full/case_summary/facility_sheet/period_brief` 格式；请求可绑定 `expected_content_sha256`，下载返回内容和格式双响应头及中文业务文件名。新增格式须连同 `backend/document-renderer/render-docx.cjs` 一起交付；旧渲染镜像不会凭后端代码自动支持它们。
- 三种专题预设沿用现有问题类型；静音不暂停后台；显式忽略绑定具体专题/快照/修订/内容摘要，超过 100 来源分批而不是时间戳笼统清除。同对象合并前先取每专题最新版本并重核权限。
- 八类材料目录不再构造文档、地图和不必要的专题视图；正文搜索语义不缩为标题。可重建投影、显式反向引用及独立批量巡检已接入，GET 不回填，不接受已有事务或用户保存 Session。来源验证仍可能读取冻结 JSON，不宣称零正文读取。
- 旧部署页保留六类统计，移除硬编码置信/共识数字，标明旧直线/未校准口径并承接当前态势与材料；未删除历史功能或创建执行任务。
- A 包：新增格式 **7 项通过**，随后与生产配置/可观测性合跑 **38 通过（2.40 秒）**。早期失败分别暴露新文档 schema 未注册、JSON 行结构和时间序列化差异，修正后页面与实际 Word 结构一致，不将失败尝试计为通过。
