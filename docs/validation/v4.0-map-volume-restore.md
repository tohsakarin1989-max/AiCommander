# 离线地图文件与快照恢复验证

2026-09-10，在既有隔离合成数据容器中完成。此项补充数据库升级恢复验证，
不代表正式服务器、完整生产镜像或 PostgreSQL 与地图卷联合恢复已通过。

## 实际验证

入口：`scripts/verify-isolated-map-restore.py`，仅允许固定隔离数据库、目录及合成案件。
脚本通过 SQLite 在线备份复制数据库，逐文件复制已安装地图包并记录 SHA-256，
打包后恢复到全新临时目录，不覆盖现有数据库或 current 地图。

- 地图文件及安装元数据共272项，357,067,669字节；其中正式地图资产270项。
- 恢复前后全部文件摘要和数据库备份字节一致。
- 使用现有地图服务读取恢复库：14层样式、查询“大庆”返回20项、实际矢量瓦片读取通过。
- 在恢复副本中故意损坏样式，库存验证和样式读取均拒绝；修复副本后再次通过。
- 最终重新检查源地图全部文件摘要及 current 标识，确认没有变化。

快照：`bac4827d-f543-44a0-8d92-e65e61a27937`。
归档 SHA-256：`a12ea8c60f0ad85b7f8c20c533e6f1abbacb30783e52a6653eb24b217b1c94cb`。
导出后在宿主机再次核对归档摘要一致。

证据保留在 `output/validation/map-volume-restore/report.json` 和同目录
`synthetic-map-backup.tar`。备份含合成账号的数据库，属于本地验证产物，不上传 GitHub。

首次两次运行分别遇到验证脚本误判矢量 MIME 类型、比较压缩存储字节与解压返回字节的问题。
按已有服务契约修正断言后完整运行通过，未改变业务地图服务来迎合测试。

## 边界

这是文件完整性和恢复后服务读取验证，不是全部瓦片重新渲染或目标服务器压测。
原始公共地图包的全量解码、浏览器断网显示和 PostgreSQL 带数据迁移分别使用既有专项证据。
数据库 dump 不能替代地图文件备份；现场恢复仍须保护对应地图文件、数据库和配置，
并在独立目录验证后再执行受控切换。
