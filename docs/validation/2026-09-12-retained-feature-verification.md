## 实际发现与修复

| 留存功能 | 原有故障 | 修复及验证 |
| --- | --- | --- |
| 圆桌会议/历史消息 | 数据库时间对象与响应字符串声明不符，读取详情或消息返回 500 | 统一时间响应类型；真实 ORM 到 HTTP 读取通过 |
| 模型选型与发起会议 | 分析员不能读管理员模型列表，下拉为空；不存在、停用、角色错误或重复模型也能提交会议 | 增加只含身份四字段的安全目录；创建前校验模型。真实登录验证目录可读、管理仍拒绝、越区会议拒绝 |
| 多模型执行失败 | 模型错误、非法 JSON、空 JSON 可被当成成功，并发布报告 | 检查有效阶段输出及报告摘要；失败不发布 completed 报告。本地模型传输故障注入覆盖各阶段 |
| 会议最终保存 | 报告提前提交，总结保存失败后留下可下载的半成品，进度却已到 100% | 报告、总结、终态同事务；提交后才推送成功。独立注入最终提交失败，确认无报告残留 |
| 报告转结论 | 报告内容为字典时，降级摘要按字符串切片报错 | 字典摘要与文本兼容；报告生成、人工确认结论、发布串联通过 |
| 模型编辑/重名 | “密钥留空保持不变”实际清空密文；新建/改名冲突返回 500 | 空值保留密文；名称冲突回滚并返回可读 409，包含历史停用名称。新增/改名失败后仍可继续保存其他配置 |
| 历史会议与报告跳转 | 会议必须出现在前 100 条列表中才能打开；前端再次反转已倒序列表 | 指定 ID 独立读取、保留正确排序；以 102 条持久化历史会议验证最早记录的报告和会议深链接 |
| 事件关联确认 | 分析只返回临时候选，没有保存，因此列表与人工确认无法继续 | 接入现有关系持久化，按事件对及类型去重；重复分析保留人工确认和否决 |
| 油量与奖金口径 | 事件的“升”直接写入案件“吨”；抽取将升简单除以 1000 当作吨 | 保留原始升数，核定吨数未知则留空；阻止规则及模型候选误换算，页面明确仅填核定吨值 |
| 旧巡逻兼容接口 | 终态可回退覆盖；效果 0 分被当成 70 分；调整后风险分数和等级不符 | 约束状态流转，区分 0 与缺失值，按调整后分数确定等级；创建→开始→完成→风险历史及失败边界通过 |
| 旧角色和错误状态 | 只读页面展示必被拒绝的写操作；接口失败呈现为成功空态；复核后详情不刷新 | 会议、事件、结论、关系图谱、条件组、辖区按现有权限显示操作；补错误态及缓存失效 |
| Agent 历史入口 | `/agents` 已是 3.6 运行中心，却误受旧 Lab 开关控制；旧案件管家跳转到错误页面 | 3.6 运行中心保持独立；已有 Lab 组件恢复到管理员且显式启用的 `/agent-lab`，按 runId 打开任务 |
| 旧图表和占位动作 | 条件组新参数被用于解释旧结果，且“新建档案”实际只开详情；固定巡逻示意被称为 AI 路线 | 参数与已生成结果绑定；准确命名查看动作；固定示意明确标记待配置，不冒充可通行路线 |
| 设置表单 | 人员和重点部位等弹窗复用 DOM 字段 ID，标签可指向已隐藏的另一表单 | 为三张表单设置独立名称，实际依次打开并保存人员和重点部位验证 |
| 2.x/3.x 验收脚本 | 四个脚本迁移到当前 head 后，却仍断言旧迁移号 | 共用只读检查器，比对当前仓库 head 且保留各模块必需表；旧版本、空库、缺库仍被拒绝 |

上述会议失败状态还经过独立复核：先复现“空 JSON 假成功”和“最终提交失败残留报告”，修复后原复现通过；不是仅由修改者阅读代码确认。
