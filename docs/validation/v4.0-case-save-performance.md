# 案件保存性能基线与优化

2026-09-10，本机合成数据验证，不代表目标服务器或PostgreSQL现场性能。

## 固定比较条件

- 基线：`v3.6.0-stable`，提交 `0b12876ce14687d1466be38f7c568063ef52c611`。
- 当前版本与基线都复制为临时源码快照；同一Python和已安装依赖，非两套原始发布依赖比较。
- 每轮独立文件SQLite，预置1,000条合成历史案件，同样的时间、文本、位置和辖区分布。
- 全应用TestClient，真实分析员登录、辖区授权、POST保存、自动编号、质量计算、Outbox及原有同步后处理，不替换业务服务。
- 每轮10次预热、100次计时，基线/当前/当前/基线/基线/当前，共600次计时保存；六轮均保留，无择优删除。
- 每轮断言110条新增案件、110个画像请求事件、编号无重复，返回原文未改变。
- 使用临时数据库、合成账号、内存队列，禁止socket连接；未读取正式数据库或发送业务数据。
- P95采用最近秩法，合并各版本300个样本。主机未独占，非并发压测，也不包含真实HTTP网络或浏览器时间。

## 首次失败与原因

首次基线P95为17.221084毫秒，当前18.247208毫秒，退化5.96%，超过5%门槛。
记录保留在 `output/validation/case-save-performance/report.json`。
该初版只冻结基线源码；审查后已改为两侧冻结，后续每次生成独立结果目录。

检查发现同一请求内每次SELECT都重复构造37项辖区过滤表达式。
新增测试先得到1失败、2通过：六次同范围查询构造222项，而不是一次37项。

优化仅在当前数据库Session内复用过滤表达式，不缓存查询结果、案件ID集合或授权决定。
每次SELECT仍读取授权范围；范围变化立即重建，管理员范围清除缓存。
表达式里的子查询仍读取当前数据库，案件移动辖区后不会残留旧成员。
保留全部模型过滤、别名过滤、编号防重、原有业务后处理及Outbox事务。
