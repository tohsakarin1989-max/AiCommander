## 通过的场景

1. 真实Redis、实际Celery任务注册和prefork池，2个进程并发执行。

3. 查询只领取1次、开始事件1条、完成结果由真实count_cases工具产生，数量为1。
4. 真正停止本次Redis容器；Worker日志出现连接丢失和拒绝连接。
5. 断连期间另一个进程仍通过同一服务创建查询，持久状态queued、领取次数0。
6. 重启同一Redis容器，再发送8条唤醒；原Worker重新连接并完成第二个查询。
7. 最终两个查询均completed，各只有1次领取和1条开始事件，统计结果正确。

## 测试与生产路径的区别

按照ai-regression-testing技能明确保留差异：模型是固定测试替身，
依次返回count_cases与finish，等待1秒以提供并发领取窗口。
任务、权限、事件、工具、数据库和Celery传输均为当前项目代码，未模拟。
这证明队列故障恢复及重复唤醒幂等，不证明现场模型理解能力或网络协议联通。

未启动Beat，因此恢复后的唤醒由脚本发送，不声称定时调度已完整演练。
