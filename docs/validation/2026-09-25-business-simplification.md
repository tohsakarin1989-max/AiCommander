# 现有业务审查与精简记录

日期：2026-09-25。基线：当前 `v5.4.0-stable` 工作区。

更新说明：一至五、七记录首轮审查及当时证据；按用户“继续第六部分”的指令，后续适配结果现记录于六、八。首轮“未停任务/未退役旧入口”的说明不代表第二轮仍未处理。

本轮是业务审查与安全精简，不是 6.x 功能开发、版本发布或生产部署。未修改 VERSION，未提交、推送或发布。保留原有 AGENTS.md、历史计划、6.x 草案以及演示脚本等未提交文件。

## 一、结论

现有系统主要问题不是“智能体数量过多”，而是新统一流程与旧即时流程并存：入口重复、相同分析重复计算、未接通的实验展示仍像正式业务。实际后台画像、检索、道路、成果和设施任务维护不同的派生对象，不能一起停掉。

本轮按三类处理：

- **合并重复入口与计算**：区域条件/时间规律、单案旧入口、模型上下文、旧相似检索。
- **删除已无消费者的源码**：9 个前端文件、1 个后端嵌入包装文件、2 个结论服务死方法。
- **保留独有业务与历史兼容**：会议、独立事件、人工确认、图谱、经验卡、历史工作记录、奖金等，不删表、不删数据。

## 三、已落实的计算与接口精简

### 1. 同一份旧研判只计算一次

`CaseIntelligenceService.build_workbench` 返回原有结构及新增 `context_pack`。页面不再同时请求 workbench 与 llm-context；旧 `/llm-context` 接口保留兼容。

同次调用的中间结果仅在调用栈内共享，键包含方法及完整参数，不使用全局或跨用户缓存。

| 默认参数下一次 workbench 的内部计算 | 精简前 | 精简后 |
|---|---:|---:|
| 相似案件检索 | 8 次 | 1 次 |
| 时空统计 | 4 次 | 1 次 |
| 区域计算 | 4 次 | 1 次 |

以上为固定测试计数，不是线上耗时改善百分比。经验卡仍使用 365 天、场景参考仍取 8 条；非默认参数不同的计算不会错误共用。除生成时刻外，固定输入内容等价；共享统计列表不会被报告追加内容污染。

### 2. 案件读取不再附带用不到的旧相似分析

`GET /api/cases/{id}/profile` 新增可选 `include_similar`，默认 true 保持已有契约。日常案件工作界面明确传 false，历史参考继续由现有统一检索组件提供。

跳过的响应标记为 `not_requested`，不是“没有相似案件”。案件事实、证据、车辆/人员、人工结论、经验记录及来源读取仍保留；错误和权限检查不改变。

### 3. 停止实验页污染业务数据

- 页面初始化与刷新改为 `GET /api/automation-alerts/`，明确只展示最近 100 条，不冒充全量统计。
- `POST /api/automation-alerts/simulated` 有意退役为 410，不获取数据库 Session。
- 普通告警创建拒绝 `is_simulated=true`，普通告警契约保留。
- “生成事件”和原“核查建议”原本调用同一方法，保留一个实际操作；已有核查建议直接展示。
- 历史告警、人工归档、关联事件、转案件及研判包仍保留。未删除历史模拟数据；内部种子函数仅剩隔离测试夹具使用。
- 这是旧模拟写入接口的明确不兼容退役，不声称所有旧写 API 行为完全不变。

## 五、后台任务：保留而不误删

| 任务组 | 包含任务 | 保留原因 |
|---|---|---|
| 案件派生链路 | Outbox、双域分析消费、画像/地图配对补偿、统一成果补齐 | 处理不同阶段，补偿不是重复业务 Agent |

| 地图 | 地图包验证和发布 | 保持异步验包及原子发布 |
| 交互 Agent | 智能查询消费、审批过期清理 | 查询可选；关闭能力后历史审批仍需失效处理 |
| 周期态势 | 每日、每周生成 | 时间窗不同，结果与临时探索不同 |

本轮不改这些排程。会议任务、管理员手工重建、Lab 重放等仍有实际生产者；不能仅因非普通函数调用就删除。

## 八、后续适配的验证与注意事项

- 已删除 `assistant_service.py` 的旧同步问答实现；`AgentService` 仅保留仍有调用的模型选择辅助，不删除旧任务表。源码可从 Git 基线恢复，不能整库还原或覆盖用户其他未提交改动。
