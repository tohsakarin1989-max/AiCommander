| 保存查询、持续专题及新增依据变化 | 实际浏览器从助手保存原文否定条件，后台形成修订；已有结果读取不触发分析；暂停/恢复、备注、历史深链接、来源新增/更新/移出测试 |

| 统计、典型/反向案例、缺项比例、边界 | 实际浏览器 4 起授权案件：否定条件匹配 1、相反 1、资料不足 2；未计入隐藏辖区；规则与模型候选分开 |
| 无变化不新增待办或反复提示 | 同输入 `unchanged`、不新增修订；没有待办写入；自动刷新不替换用户当前阅读修订 |

| 独立事件补充与来源去重 | `test_analysis_topics.py`：独立/案件关联事件分开，不按相似文字合并，不把关联事件重复计为案件 |
| 后台不依赖可选 Agent Lab | 专题任务及 Beat 使用普通默认队列；真实 PostgreSQL/Redis/Beat/Worker、`ENABLE_AGENT_LAB=false`、无人消费 Agent 队列时自动生成；生产条目 15 秒未缩短，不用手动投递冒充周期验收 |

## 冻结规模性能

`scripts/verify-v53-topic-performance.py`：本机 Python 3.13、内存 SQLite，500 起种子，每版三轮、每轮预热 10 次后测 100 次保存；交替顺序，基线为实际 `v5.2.0-stable` 归档。

| 指标 | 实测 |
|---|---|
| 基线三轮保存 P95 | 7.338458 / 6.610041 / 7.368667 毫秒 |
| 候选三轮保存 P95 | 6.707708 / 6.704875 / 7.296458 毫秒 |
| P95 中位数相对变化 | -8.595%，该冻结环境未超过 5% 退化门槛 |
| 2000 案件/画像完整专题生成 | 1429.910875 毫秒 |
| 20 页读取 P95 | 219.094 毫秒；每页总体均为 2000 |

这是服务级固定输入测量，不是 HTTP、目标服务器、PostgreSQL 生产吞吐或业务准确率承诺。队列和界面状态修正不改变保存/聚合算法，复用该证据。
