# v6.1 资料与案件骨架实施验证

日期：2026-09-27。用户授权：推进至 v6.1 Stable。范围以[未投产重构方案](../superpowers/specs/2026-09-27-predeployment-refactor-review.md)的 v6.1 为准，保留已有 v6.0 成果归一及权限边界。

## 实施内容

1. 类型化案发时间、原文、时区和发现时间；允许未知及区间，精确时刻与区间不能同时填写。
2. 地点角色与几何校验；唯一精确案发点才可作为主坐标，未知/区域/多个案发点清除过期主点。
3. 带单位和业务环节的油品测量；人员/车辆正式明细单源，不与旧 JSON 叠加计数。
4. 三层质量契约及最多三项关键缺口；否定、不确定、业务阶段和版本化时限分开处理。
5. 案件修订、原件、出处、变更事实与投递状态分离；普通页面读取不生成修订或发起分析。
6. 独立案件、事件与线索采集；事件转案件原子提交、幂等，原来源保留。
7. 案件档案、原件上传/下载/撤销、来源阅读；旧首页与手工会话壳退出运行包，保留独有业务内容。
8. 新建空库显式初始化；SQLite 与 PostgreSQL 增量迁移和恢复，不修改现用数据库。

### 隔离浏览器业务流程

使用现有隔离验证服务与临时 SQLite，24 条合成记录、测试账号、本机回环端口，无外部模型。完成：

- 登录后进入案件资料，统一记录入口可选择案件、独立事件、独立线索。
- 新增明确标注“非真实案件”的记录，仅填写案情和“昨晚，具体时刻尚待核实”，不填精确时间、坐标、数量即可保存。
- 列表显示时间原文及“时间未明确”，没有补出今天或零点。
- 案件档案显示五个业务分组、最多三项补充提示；“未发现车辆、未抓获人员”不生成补牌照/人员要求。
- 来源第 1 版可回读原始提交，未提供测量明确显示“尚无测量记录，不等于数量为零”。
- 来源原文以业务卡片呈现，完整 JSON 默认折叠；1280×720 下选案后档案占满内容区，不与窄列表、筛选栏争宽度。可返回工作台及案件列表，筛选与分页状态保留。

此流程验证的是本地合成数据读写，不代表正式业务、全量浏览器兼容或服务器部署。

### 数据库和安全边界

- SQLite：空库到当前迁移头；v6.0 升 v6.1；已有原始字段和人工确认保留；单位未知不推断；来源历史不伪造；第二次空库初始化拒绝。
- PostgreSQL：本机可丢弃数据库验证升级、原始数据保留、新原件二进制备份恢复、独立新库初始化与非空拒绝、来源外键下合法全案删除、同内容不同修订对应独立画像。另以非默认 schema 的表、物化视图分别验证初始化拒绝，原对象未动、未新增应用表。不使用真实业务库。
- API：案件及历史出处均重新检查当前辖区权限；撤权后不可读；文件下载检验摘要和可用状态；不提供任意文件路径读取。
- 文件：只声明类型/大小/摘要校验，没有开展恶意文件扫描。
- 事件：排队失败时事务回滚，不留下已建案但未关联来源的半成品。
