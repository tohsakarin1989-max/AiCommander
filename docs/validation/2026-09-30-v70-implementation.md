## 遇到的失败与处置

1. 旧运行镜像缺当前 pgvector/numpy 依赖：构建失败即停，受控构建侧准备公开轮子后无网络装入，不跳过依赖检查；未把任何业务数据用于下载。
2. 裸 image ID 被构建器解释为远程镜像名：改为已核对的本地标签；明确 `--network none` 不约束 BuildKit 元数据查找，目标机仍只导入预构建镜像。
3. 中文渲染探针第一次缺测试 SECRET_KEY：仅给隔离容器补合成配置后通过，未读取现用密钥。
4. PostgreSQL 窄测试最初直接建 ORM 表缺 vector 扩展：DDL 已回滚，改走实际 Alembic 迁移后通过，失败日志保留。
5. 隔离浏览器测试期间曾出现 SQLite 审计写入锁等待失败；当时另有后台处理与合成修订写入，未证明精确争用方。不得将这批 SQLite 结果称为生产并发审计验收；正式部署使用 PostgreSQL。本版 PostgreSQL 提交并发验证另行记录。
6. 预检与部署可能受终端残留版本/能力变量影响：共享入口统一使用批准配置；documents 的新装构建补齐消费者 core 镜像。定向回归通过。
