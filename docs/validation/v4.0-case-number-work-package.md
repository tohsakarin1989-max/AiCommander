# v4.0 第五工作包：全局编号与并发事务

日期：2026-09-10。当前仍为 v3.6.0-stable 发布基线，本文件不声明 v4.0 发布完成。

## 已修复

- 编号全库唯一但生成器原先只看授权辖区，导致与隐藏辖区编号冲突。内部生成器现仅读全局已占用编号元数据；没有新增公共接口或放宽案件业务查询。
- 自动生成编号的唯一约束冲突最多尝试 8 次分配，只识别 SQLite / PostgreSQL 的案件编号唯一约束；其他错误直接保留失败，用户明确填写的编号不自动改写。
- 写权限检查先于编号分配，拒绝请求不读取全局编号。
- SQLite 在保存点前建立真实外层事务；避免保存点释放时提前提交案件，确保后续画像事件失败能整体回滚。
- 首次导入与失败行批量重试按编号所采用的源时区日期排序，避免不同批次反序日期互相等待。原始行号、内容、预览和响应顺序保持不变。

## 证据

1. 跨辖区冲突、模拟过期编号及权限顺序测试先失败，再修复通过。
2. SQLite 保存点提前提交问题先通过注入画像事件异常复现；修复后回滚案件数为零。
3. 真实 PostgreSQL 反序日期批次先出现一批仅成功 1 行；临时数据库日志确认 deadlock detected。
4. 排序修复后在全新临时 PostgreSQL 库验证：两个辖区反序日期首次导入、两个失败批次反序纠错，均每批成功 2 行且无错误。
5. 单测覆盖 +14 / -12 时区使 UTC 时间顺序相反的边界，排序仍与编号日期一致。

| 验证 | 结果 |
| --- | --- |
| 后端全量 | 548 passed，1 skipped（需独立测试库的 PostGIS 项） |
| 独立真实 PostGIS | 6 passed，含旧并发回执及新增反序批次两条路径 |
| 编号专项 | 11 passed；新编号辅助模块语句覆盖率 100% |
| 浏览器 | 13 组通过，含模板、导入、纠错、丢失响应恢复与换账号权限隔离 |
| 代码复核 | 事务、错误分类、元数据边界、源时区排序通过 |

本轮没有新增数据库迁移；全新 PostGIS 测试库从现有迁移链升级到 d619e0f20373。
临时数据库容器和浏览器服务均已停止，只清理了合成测试数据。没有修改正式案件、地图或模型配置。

## 边界及剩余工作

- 自动编号重试有 8 次上限；达到上限时明确失败，不假称成功，也不会自动改写已保存案件。
- 现有编号格式和删除后空号复用规则不变；新增辅助模块不返回他区案件内容。
- 本地合成并发测试不等于目标服务器性能验证，P95 性能门禁仍待整版完成。
