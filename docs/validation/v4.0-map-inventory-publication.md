# v4.0 地图包集发布一致性检查

2026-09-10。此工作包为完整 schema 2 导入登记和发布做准备，未登记或发布真实两市候选，未更改正式案件数据、版本号或 GitHub Release。

## 实现结果

- 新增 `map_bundle_inventory.py`：验证规范清单摘要、来源字段、边界及所有登记资产。字形规范路径与已实现的授权字形接口一致。
- 检查同一包的完整资产集合，包括底图、地名、字形、样式及其他声明资源；错误包归属、类型、大小、摘要、缺失或额外记录均拒绝。
- 逐级以目录描述符打开规范路径，拒绝文件及父目录符号链接，不接受请求提供的路径。
- 构建、发布、回滚使用完整摘要检查。损坏配套资产不能切换 current，旧地图仍保持当前状态。
- 新旧版本共用身份判断：旧包须有明确 schema 1 声明、来源与文件信息一致、唯一 MBTiles 及旧规范存储路径。未知或被篡改的 schema 不能退回较弱检查。

## 验证证据

专项 19 项通过，包含登记错配、完整性损坏、父目录符号链接、构建阻断、发布失败保持旧版本、恢复后发布、损坏旧包禁止回滚，以及三个 schema 降级绕过复现用例。地图相关回归合计 69 项通过；新增库存服务覆盖率此前专项测得 94%。

发布流程测试使用隔离数据库注入的 accepted/ready 传输样本，只证明库存检查和状态切换，不冒充真实地图内容验收。现有栅格导入、快照、地名和字形接口回归保持通过。

修复后全量后端回归：650 项通过、1 项跳过，用时 24.33 秒。独立复核再次确认相关 69 项通过，此前高优先级问题已收口。

独立 Python 评审指出 schema 变化可能降级到旧 MBTiles 检查；已先复现，再统一新旧包身份判断并补回归。文件注册一致性检查不能替代内容校验，特别不能证明所有必要字形、样式引用闭包、公共道路引用或实际地图覆盖已完整。
