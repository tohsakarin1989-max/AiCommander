## 接口与持久化

新增管理员接口，沿用现有认证及管理员检查，普通用户不增加操作：

| 接口 | 内容 |
|---|---|
| `POST /api/map-package-imports` | 接收严格 schema 2 JSON 清单，摘要去重，返回任务与 Location |
| `GET /api/map-package-imports/{id}` | 已接收分片数和缺片清单；明确进度来自持久化回执，不代表磁盘当前内容已再次验证 |
| `PUT /api/map-package-imports/{id}/chunks/{name}` | 接收原始分片字节，限 16 MiB，校验声明名称、长度和摘要后原子保存 |
| `POST /api/map-package-imports/{id}/submit` | 完整回执入队，重复提交保持同一任务；缺片返回 409 |

清单限 2 MiB。禁止请求指定磁盘路径；任务编号使用 UUID，分片名称必须来自该清单。临时分片和最终文件均通过服务端目录描述符操作，拒绝符号链接目录。上传异常由 API 回滚事务，磁盘暂不可用返回 503 及重试提示，不泄漏文件路径。

新增 `map_package_imports` 与 `map_package_import_chunks`，迁移 `e72af1041484`，前序 `d619e0f20373`。任务和回执在数据库中，不依赖向 Redis 即时投递成功。SQLite 使用实际 UPDATE 串行同任务写入；PostgreSQL 使用同一更新获得行锁。

## 后台处理

专用任务路由 `map_build`，不在 API 或案件保存事务中解码。消费器从数据库领取 queued 或过期 validating 任务，领取后先提交短事务，再重新读取所有分片、校验重组并运行联合渲染内容校验。

流程为 `receiving → queued → validating → render_validated`，内容或存储失败为 `failed`。失败后可重传修正分片再提交。35 分钟租约，任务软/硬时限 30/31 分钟；完成提交必须同时匹配当前租约 token 且未过期。过期或旧 Worker 不能覆盖新的处理结果。

`render_validated` 只表示渲染内容阶段完成，`publish_ready=false`。地域覆盖、道路引用、地名字典与完整正式验收、注册及发布尚需继续完成，不能把这个状态转述成地图已经上线。
