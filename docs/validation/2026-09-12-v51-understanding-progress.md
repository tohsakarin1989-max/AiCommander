# v5.1 案件理解与统一检索实施记录

状态更新：v5.1 事件片段、统一历史索引及可选内网模型适配随 [v5.2 源码收口](../releases/v5.2.0-stable.md) 交付。真实模型未接通，保持未启用边界。下方是过程记录，较早待办以最新收口证据为准，不代表已经部署目标服务器。

## 最新进展：可信内网深层提取与后台事务隔离

- 新增可选 `CASE_SEMANTIC_MODEL_ID`，复用现有模型登记和原文出域规则。默认关闭；只接受可信内网 OpenAI 兼容协议，不绑定供应商，不提供外部降级、任意工具或命令执行。
- 后台在调用前冻结输入并释放数据库事务，返回后重新核对来源和配置版本；模型等待不持有案件编辑锁。来源或模型变化时旧输出作废，最新任务续建；正常保存不等待模型。
- 模型最多返回 30 个受结构约束的原文片段，逐字核对来源、字符范围和引用；无依据内容不采用，否定/不确定上下文不能因截取局部词语变成肯定事实。规则与模型片段分开保存，后者暂不自动加入设施评分或正式案件关系。
- 现有案件画像与冻结报告展示同一批模型片段、原文出处、状态及配置版本；未启用、不可用、部分结果、空提取分别说明。模型故障仍产出规则画像，不把技术完成当案件办结。
- 画像配置版本适配已有 30 字符字段，无新迁移。工作界面和最新成果会重新校验版本；历史检索继续复用有相同来源与规则版本的确定性条件，不将新增模型候选偷换成事实。
- 重建与部署边界见 [内网案件提取说明](../local-case-extraction.zh-CN.md)。配置更换后旧数据使用现有管理员分批回填；暂不可用的已完成画像目前需更新 `config.revision` 后回填，不另加一线必经操作。

- 原有任意 `Case.features` JSON 与质量 JSON 不再整体作为相似事实搜索；原数据、独立经验管理和页面展示保留。统一检索使用案件原文、明确元数据、当前语义条件及已确认经验；未确认派生内容不能因旧入口检索而变成事实依据。

## 前一工作包：持久化词项索引与后台续建

- 新增增量迁移 `c61d20a75e91`（上版 `b508c42fd75b`），只增加历史检索派生索引和后台断点表，不修改原始案件、经验或画像。
- 索引存储内网中文词项、业务条件、源内容摘要和规则版本。查询批量读取当前授权集合内的索引，仍核对当前源摘要；匹配时不重新抽取候选原文。缺失、过期、规则变化或结构损坏时使用明确的词项降级，不返回旧条件。
- 每 15 秒独立调度一批（默认 100 起），使用数据库内持久游标循环扫描全库，不限制为最近案件。断点与本批索引同事务提交，后台中断不会跳过未提交案件；并发任务串行领取断点。相同资料/规则不重建，未确认/删除的经验索引在轮询时清理，案件删除由外键级联清理。
- 轮询不进入案件保存事务，不要求 Redis 或模型在线才能保存。当前尚未加入事务 Outbox 的即时索引通知，大库更新延迟取决于完整轮询周期；查询会识别未更新项，不把旧索引当当前依据。后续即时事件与轮询兜底共用本索引，不另建生产索引。
- 授权以当前案件范围为准，索引本身不保存可复用权限。独立经验仍逐次检查当前人工状态、内容和证据访问，不因有缓存而跳过。
- 返回实际 `indexed_sources` 与 `fallback_sources`；语义向量仍为 `not_enabled`。**本工作包是持久化词项索引，不是 pgvector 或本地嵌入的替代验收。**
