# 9.1 旧设施写入口专项集成

## 完成范围

- 手工新增、按 ID 编辑、批量新增、GeoJSON 和旧 CSV/Excel 入口通过 `map_feature_adoption` 接入现有来源、模板、声明行、来源身份、字段组采用决定和要素历史版本。
- 兼容来源由服务器按厂区、入口及来源标签注册，调用者不能通过属性冒充另一受管来源或指定信任等级。同名不同编号不合并；无编号保留来源内精确指纹。手工按 ID 修改记录明确人工采用，旧值保留。
- GeoJSON 保留点、线、面及其多段形式。显示位置只是几何定位辅助，不是可信道路入口；不能用线面中心点替代完整几何。
- 旧表格入口接收既有标准经纬度契约，非 WGS84 声明必须改走显式坐标模板。中文生产字段接入同一字段组，保留原行、文件名、行号；失败行保留隔离记录。
- 新增记录不自动填写风险等级或置信度；未登记仍为未知。手工界面也移除原先默认一级、默认满置信度。
- 当前账号及厂区维护权限在写入时重新核对。普通 write 不等于 manage。前端依据当前厂区授权控制入口，切换厂区或撤权关闭编辑；后端仍是最终权限边界。
- 保留旧审批事务：调用方使用 `commit=False` 时，业务修改及来源版本共同回滚。

## 验证

- 新增 8 项专项验证，包含实际 AuthMiddleware、登录、范围绑定和真实设施 API 的完整调用路径：维护厂区成功、普通写入失败、跨区失败、撤权失败；旧公网同步仍不开放。
- 设施身份、双时间历史、辖区业务、旧地图导入范围、Agent 审批事务及查询/地图时间口径组合：135 项全部通过。
- 前端范围权限与查询组合 18 项通过；构建通过。
- 原先“手工修改不产生来源声明”的旧断言升级为“原值与新值均保留且新值关联采用声明”，没有删除历史兼容和事务回滚检查。

## 未计为验收

这些证据来自本地隔离 SQLite 和前端构建。不是目标服务器、真实台账批量效率、实际道路拓扑质量或正式业务投产验收。旧兼容接口仍主要用于小批量操作，大文件、复杂投影和模板管理应使用已建设的后台地图批次入口。
