# v4.0 公共地图源数据检查工作包

日期：2026-09-10。状态：完成源数据诊断，**不是离线矢量地图或 Stable 发布**。

## 新增能力

- `scripts/audit-public-osm.py`：两遍读取原始 OSM，检查所有 way 的节点引用及转向限制直属成员引用；记录道路属性存在数量、目标城市边界关系及缺失样本。
- 不要求文件按节点、道路、关系排序；不把瞬时 pyosmium 对象保存到下一轮。
- 报告绑定源文件 SHA-256，前后哈希不同拒绝输出；输出只允许新文件，不覆盖旧证据。
- 引用门禁、边界几何和可通行性分别表述；报告永远不自动设为可发布，不连接业务数据库，不修改地图版本。
- 解析器仅安装于独立公共地图构建环境，没有增加核心后端依赖。

## 两市边界固化（后续推进）

新增 `scripts/prepare-public-map-region.py`，用独立构建依赖 `scripts/map-build-requirements.txt` 运行。不是核心后端运行依赖。

- 固定目标 OSM ID、城市名称与行政代码，三者一致才接受。
- 组装前检查原始关系成员及引用；`subarea` 仅作为元数据，必须存在，不把它拼成外轮廓。未支持的嵌套几何直接失败。
- 检查外环/内环、标签与行政中心节点角色；缺失成员、无法组装或无效几何不写成功标记，不自动修补几何。
- 使用真实 MultiPolygon，不用包围盒替代城市边界，保留不连通的外环。
- 采用以两市联合几何中心为原点的等距方位投影，生成 30 km 提取缓冲；明确不是道路可达范围，也未证明覆盖全部合理绕行。

## 本地地名索引与查询底层（后续推进）

已新增 `backend/app/services/public_place_index.py` 和隔离构建脚本 `scripts/build-public-place-index.py`。
本模块不读取业务数据库、不调用网络，尚未注册地图查询 API，也没有修改现行地图或地图页面。

- 从同一公共 PBF 与已校验提取范围生成命名节点、道路和区域索引；不同 OSM 对象保留 `n/w/r` 类型前缀，不按同名合并。
- 中文片段、别名和 NFKC 全半角英文归一化查询；2/3 字符倒排索引缩小候选，再做字面子串检查。未采用任意 SQL、用户表达式或公网地理编码。
- 默认地名类型优先，随后按精确/前缀/包含匹配排序；固定查询算法为 `literal-ngram-place-priority-v1`。
- 查询只读、有步数预算、输入及返回条数上限；未找到数据库不创建空库。
- 构建失败不写目标文件；同目录临时库完成后通过硬链接排他发布。输入对象上限在收集和写入两阶段检查。
- 点位只称 `name_reference_point`，道路、区域上的名称参考点不等于入口、门牌、道路吸附点或可通行目的地。
