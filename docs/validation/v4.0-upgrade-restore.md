## 实际执行与结果

1. 从冻结旧版迁移到 `a3e6b7c8d940`，创建合成管理员、登记井、案件、会议及关联报告。
   案件通过真实鉴权保存API写入，同时形成Outbox和流水线状态。
2. 保存逐表原字段清单、行数与内容摘要，执行 `pg_dump -Fc` 生成升级前备份。
3. 当前源码执行增量迁移到 `f830b2152595`。在应用启动和新业务写入之前，核对全部旧表原字段行数和摘要完全一致。
4. 当前源码通过真实鉴权API新增第二条合成案件，验证旧案件原文和旧报告可读，再生成升级后备份。
5. 升级前备份用 `pg_restore --exit-on-error` 恢复到另一个新库；先核对原字段摘要，再由v3.6程序实际登录、读取原案件和报告。
6. 升级后备份恢复到第三个新库；先核对升级后摘要，再由当前程序登录读取。
7. 最后重新核对仍保留的升级原库，确认两条案件及其他保存内容与升级后备份时一致。

## 适用边界

- 证明带合成业务数据的数据库增量升级、数据库备份恢复和旧源码读取兼容备份。
- 未覆盖完整生产镜像、地图文件卷、真实模型密钥解密、真实数据规模及目标服务器。
- 地图文件及对应快照必须另外保护；仅有数据库dump不能恢复离线地图文件。
- 地图文件和SQLite快照的独立恢复已由[地图恢复专项](v4.0-map-volume-restore.md)验证；两项独立演练不能合称完整生产部署恢复。
- 不执行破坏性降级，不将新库直接交给旧程序，也不自动把升级后数据覆盖或回灌到旧库。
- 正式回退时必须先保护升级后的业务库与新增原始数据，再恢复兼容备份；新增数据后续经核对迁回。
