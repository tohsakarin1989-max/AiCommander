## 二、当前 v5.0 已形成的实现

### 1. 日常工作台后端

- 新增 `GET /api/workbench/daily`，契约版本为 `daily-workbench-5.0-1`。
- 返回完整授权范围的案件总数、关键缺项数、画像待形成数和画像就绪数；分页默认 20、上限 100，支持 offset。
- 汇总与当前页分别查询，不再把最近 500 条或一页案件冒充总体。
- 画像就绪要求流水线完成，且当前画像与流水线的源 hash、结构版本、字典版本一致。
- 关键缺项仅按案发时间、地点文字或合法坐标、案情描述判断。缺项与画像状态可重叠；画像就绪不代表案件办结。
- 读取不启动模型、生成经验卡或报告，也不会自动 flush 其他待保存对象。
- 旧 `/today` 与会话字段保留；缺少经验卡或报告、资产已归档均不再产生必办生成任务。已有草稿仍可进入人工确认。
- 旧 `completed` 字段为兼容保留，界面口径改为“无待确认事项”，不表示案件办结。历史活动会话仍可读取和结束。

### 2. 案件工作界面与统一成果

- 新增只读案件 workspace 聚合，集中返回案件、流水线、画像、已有成果及上下文链接。
- 返回明确的就绪、更新中和不可用状态，不在 GET 中生成画像或成果。
- 现有成果交付仍逐项核对当前权限；来源缺失与撤权不通过摘要泄漏细节。
- 前端已接入 workspace / 成果面板的组件级路径与测试；实际浏览器全流程和最终组合构建尚待主线程补记。

### 3. 单案结论复用与人工确认边界

- 单案结论只重新排版已有冻结 CaseResult 的事实、候选、反向依据和缺口，不再次检索、调用模型或生成建议。
- 新结论保存 `evidence.source_result`：成果 ID、内容 hash、结构版本和来源版本。
- 同一成果重复生成复用同一条结论，不抹掉已经发布、驳回或标记的人工决定；后续成果另建草稿，保留历史。
- 未形成当前成果返回 409，等待后台更新；不可访问的来源返回不泄漏细节的 404；无目标辖区写权限返回 403。
- 列表、详情、确认和会议关联在交付或操作前核对冻结来源。列表不显示撤权来源摘要，确认与关联也不能绕过校验。
- `model_status=reused_case_result`，`confidence_available=false`。旧 Float 字段中的 0 仅为兼容占位，不触发“低置信度”提示，也不匹配置信度筛选。
- 历史会议来源保持原路径，不要求补造 CaseResult。
- 案件 profile / processing card 已消除“没有经验卡就必须复核”的条件，并对带新来源引用的结论核验权限后再序列化。

### 4. 日常前端整合阶段

- 新日常工作台展示只读指标、案件分页、关键缺项和后台状态；失败时提供进入案件入口，不用演示数据填空。
- 根路由统一到日常工作入口；旧独立路径保留兼容。
- 特征处理入口按管理员权限处理，实验展示入口使用既有门控。
- 旧案件闭环入口转向案件页面，保留原案件上下文。
- Suggestions、CaseIntelligence、ConclusionFactory 的补充减负正在并行推进，不能凭前一轮前端测试宣称这些新改动已经验证。
