# v6.5 R10：统一成果与材料后端验证记录

日期：2026-09-30。范围为 R10 后端及其必要兼容修改；本文件不单独宣布全版 Stable、目标服务器验收或正式业务效果。

## 已实现

- 统一目录、类型化阅读、Word/PDF、受控地图 PNG 与版本绑定人工判断。来源覆盖案件成果、专题快照、设施冻结材料、日/周态势、会议报告、查询成果、经验卡及原历史结论；历史案件报告保留在知识资产读取分支，按原 `asset_type` 明确展示，不冒充经验。
- 阅读和列举不生成画像、重算统计或写入业务记录。设施材料仅通过显式冻结请求生成；人工判断为可选记录，不成为案件必经审批，不改原始事实或办结状态。
- 阅读、导出和地图资源均重新校验当前权限及原来源版本；前端 PNG 与导出图片使用冻结地图引用，响应带 `X-Result-Content-SHA256`。缺地图版本不回退至当前地图冒充原版。
- 新会议消费冻结案件成果；旧会议未保存输入版本时明确标为历史未版本化。会议讨论不能转成已核实事实；原报告审稿能力保留。新会议原始资料仅允许可信内网模型策略，未配置时拒绝，不用外部模型代验。
- 按需经验由冻结案件成果整理，确认和归档沿用原生命周期。`experience_review` 与冻结正文分离：`draft` 为草稿/待确认，`confirmed` 为已确认，`archived` 为已归档；确认状态改变不改变正文校验。
- 旧结论生成 API 和工厂退出运行；`Conclusion`、`ConclusionReview` 及独有人工历史不删。旧草稿不再形成每案必须生成结论的待办，已人工标记的历史事项保留。
- 大专题阅读与完整导出预算分离。阅读概览最多约 4,000 个表格字段行、每节 800 行，超出明确标注并可回专题分页，全集统计不裁剪；完整导出保持 10,000 行预算，超限明确拒绝，不让有效专题从目录消失。统计、来源和权限仍按完整冻结集合校验。

## 接口及主体约定

- `GET /api/results`：关键词、类型及主体过滤；权限过滤先于返回分页，不泄露隐藏条目数量。
- `GET /api/results/{kind}/{id}`：同版正文、来源、边界、地图状态和人工判断。
- `GET /api/results/{kind}/{id}/document.docx|pdf`、`/map`、`/map.png`：同源导出与受控地图。
- `POST /api/results/facilities/{asset_id}`：显式冻结；请求必须有幂等键。
- `POST /api/results/{kind}/{id}/judgments`：精确内容校验、人工决定、意见、可选附加来源及幂等键。
- 会议材料 ID 为 `Report.id`，主体为 `meeting/Meeting.meeting_id`。旧会议链接可按主体定位，不将会议 ID 猜成报告 ID。
- 只读工具使用 `include_judgments=False`；查询工具列目录使用 `exclude_kinds=('query',)`，避免历史查询嵌套递归。

## 迁移与回退注意事项

- 新迁移为 `v65r01`，前驱必须为 `v64t01`。新增 `facility_materials`、`result_judgments`、`meeting_frozen_inputs`，不修改原始案件、设施、会议、旧结论和旧人工记录的数据含义。
- `(created_by, idempotency_key)` 是设施冻结及判断的请求唯一键。同一正文使用不同显式请求键允许形成不同保存记录；不能只按正文摘要合并，否则旧请求重试可能串到另一请求。
- 任何新表有记录时，自动 downgrade 会以 `v65_materials_require_backup_before_downgrade` 拒绝删除。应先保全升级后的完整库及新增原始资料/人工意见，再在独立库恢复与上一应用版本兼容的备份，核对后切换。
- 不把“直接替换旧程序”当成数据库恢复；不删除新记录来强行通过降级。隔离验证库仅含合成资料，可在整个版本验收完毕后统一清理测试容器。
- 设施来源采用明确记录的保守依赖集；授权集合或相关来源失效会拒绝旧材料。未宣称精准增量或历史全量路况重建。
