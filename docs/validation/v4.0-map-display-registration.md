# v4.0 离线显示登记与发布链路

## 交付边界

新增管理员接口 `POST /api/map-package-imports/{id}/register`，只接收任务 ID。
使用服务端 Worker 的已完成报告和冻结清单，再次校验已安装全资产摘要，
事务登记 PublicMapBundle 与 MapPackageArtifact；重复调用返回同一登记。
未完成任务、报告不匹配或文件改变均拒绝，不修改 current。

登记的 accepted 仅指离线显示内容可用于既有快照构建，**不代表路网已验收，也不代表 v4.0 Stable**。
快照 manifest 明确 `motor_vehicle_routing=false`，保留复杂文字排版和来源完整性边界。
道路真实构图、地域覆盖和浏览器断网验收仍属于原定发布门槛。

管理员可依次调用现有 build、publish、rollback；普通用户不参与包处理。
自动登记/发布编排已完成服务级实物验证，见 [自动发布闭环](v4.0-map-auto-publication.md)；新版容器及正式页面联调仍需收口。
真实HTTP四类地图组件已完成独立验证，见 [真实地图HTTP记录](v4.0-real-map-http.md)。

## 数据库升级

新增迁移 `f830b2152595`：资产大小使用 BigInteger，来源/版本/许可文字扩至512字符，
组合地图版本扩至1024字符，以匹配既有传输契约。SQLite天然支持64位整数且不限制VARCHAR长度，
此迁移在SQLite不重建表。禁止向旧容量降级截断新数据；需恢复对应版本兼容备份，先保护新增数据。
PostgreSQL空库完整升级及备份恢复已验证，详见下节；已有业务库升级与旧版本兼容备份恢复仍需独立验收。

3. 插入标记为staging的容量测试记录：三个字段各512个中文字符，资产大小元数据8589934592，成功读回。
   此项只测数据库容量，不声称生成或校验了8GiB地图文件，也没有发布此记录。
4. 使用 `pg_dump -Fc` 导出测试库，通过 `pg_restore --exit-on-error` 恢复到新库 `aic_map_restore`。
5. 新库读回77张public表、PostGIS3.4、迁移版本f830b2152595，以及完整512字符和8589934592大小值。

实际镜像为amd64，在本机arm64通过兼容运行；不将本次速度作为目标服务器性能结论。
全程没有生产凭据或案件数据。验证结束回收测试容器及其匿名卷，测试样本可重新生成。
