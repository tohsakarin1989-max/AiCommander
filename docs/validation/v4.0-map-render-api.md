## 私有副本与 Linux 文件替换

SQLite 在 Linux 上可能将 `/dev/fd` 重新解析为文件路径，因此源文件描述符校验不能保证 SQLite 最后查询同一文件。运行服务已不采用该方案。

当前方法：按目录描述符无符号链接地打开已登记源文件，流式复制到服务私有临时目录，对实际复制字节计算摘要，通过后将副本设为只读，SQLite 只查询该副本。

每个进程最多保留两个缓存条目；正在查询的引用继续持有被淘汰副本，最后引用释放后清理。并发首次读取串行填充，防止重复复制。源身份变化重新校验；私有缓存丢失或变化时重建，不因此永久失败。

独立隔离 Linux 核心函数验证：8 并发只生成一份；原包父目录替换后仍读取已校验内容；两项 LRU 淘汰及活动引用保活、引用释放清理和缓存丢失重建均通过。该验证不是 Linux 完整 API 或目标服务器验收。

`scripts/verify-sqlite-fd-contract.py` 仅保留为历史直接文件替换诊断，明确不证明运行安全，也不覆盖父目录替换。

## 验证范围与剩余门槛

API 使用隔离数据库、直接登记的测试包验证运输和授权契约；测试包不代表已通过真实地图内容验收。未修改正式地图 current、原始业务数据或版本号。

仍需完成：真实 schema 2 分片导入与后台语义验收、资产登记与原子发布；真实后端加浏览器断公网冷启动；道路引用闭包及构图；启用模型能力真实端到端验证；v4.0 其他发布门禁。

私有副本会消耗临时磁盘，缓存数按进程计算，活动查询可短暂持有已淘汰条目。真实包冷启动耗时、工作进程数和临时空间容量需纳入部署性能记录，不能用小样本专项替代。强制终止后的临时目录清理尚需运维闭环。

当前填充锁覆盖复制过程，其他版本冷读可能暂时阻塞热缓存查找；2 秒 SQL 预算不包含复制及锁等待。后续真实包并发验证应明确记录该项，不把 SQL 预算写成请求总预算。
