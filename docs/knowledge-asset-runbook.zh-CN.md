# AiCommander v2.6 知识资产运行与验收手册

## 1. 业务目标

v2.6 把已有的即时研判能力收敛为一条可用于实际工作的闭环：

```text
案件事实与证据
  -> 生成经验卡草稿版本
  -> 人工核对事实、依据和适用边界
  -> 确认后进入历史经验资产
  -> 系统按作案条件推荐相似经验
  -> 人工标记采纳或不适用
  -> 只把主动选择的经验作为引用写入报告草稿
  -> 人工确认报告版本
```

经验卡和报告均为内部知识资产，不改变案件事实。系统不因“相似”自动确认串并案，不复制旧案
结论，不生成巡逻或处置任务。

## 2. 页面操作

进入“案件研判 -> 复盘报告”并选择具体案件：

1. 查看即时复盘卡，点击“保存经验卡版本”。
2. 在版本记录中检查证据数量和内容，点击“人工确认”；如果案件事实已经变化，系统要求重新生成。
3. 在“历史优秀案例复用”中查看相似度、适用依据和差异提示。
4. 对每张经验卡选择“采纳并选入”或“不适用”。两种决定都会留痕，但都不修改当前案件。
5. 点击“保存报告快照”。只有主动选中且仍处于已确认状态的经验卡会进入“历史经验参考”章节。
6. 检查报告版本和证据引用后，再对报告执行“人工确认”。

同一源数据重复生成会返回同一版本；案件事实、统计范围或生成器版本变化后才创建新版本。已经确认的
版本不会被新草稿静默覆盖。已经在旧报告中使用过的经验仍可“再次选入报告”，每个新报告版本都会
单独记录引用轨迹。

## 3. 状态与权限

知识资产状态：

```text
draft -> confirmed -> archived
   \-----------------> archived
```

- `draft`：待复核，不能作为历史经验被引用。
- `confirmed`：人工确认，可进入推荐或作为已复核报告版本。
- `archived`：停止使用，不再允许新报告引用。
- 管理员和分析员可以生成、确认、归档及记录复用决定。
- 只读账号只能查看，不能执行上述写操作。

旧版 `Case.features.intelligence.experience_card` 继续只读兼容。新生成内容以独立知识资产版本为准；
存在独立版本后，检索不会把旧 JSON 草稿误当成已确认资产。

## 4. 数据对象

- `knowledge_assets`：资产类型、来源案件、版本、内容、证据引用、源数据签名、状态和复核记录。
- `knowledge_reuse_records`：来源经验卡、目标案件、目标报告版本、采纳/排除/引用决定、用途和适用性说明。

迁移版本：`f6c8d2e4a913`。升级前必须备份数据库，然后执行：

```bash
cd backend
alembic upgrade head
```

两张表只存内网业务知识和审计记录，不向模型外发。关闭 Agent Lab 不会删除或禁用知识资产；
知识资产页面使用确定性案件研判服务，不依赖外部模型、Redis 或 Agent Worker。

## 5. 接口

```text
GET  /api/knowledge/assets
POST /api/knowledge/cases/{case_id}/experience-assets
POST /api/knowledge/cases/{case_id}/report-snapshots
POST /api/knowledge/assets/{asset_id}/review
GET  /api/knowledge/cases/{case_id}/reuse-recommendations
POST /api/knowledge/reuse-decisions
GET  /api/knowledge/reuse-records?target_case_id={case_id}
```

报告快照最多引用 10 张经验卡。接口会再次校验资产存在、类型正确、状态为 `confirmed`、未归档且
来源不是当前案件。前端按钮状态不是安全边界。

## 6. 验收门槛

代码级验收：

```bash
sh scripts/verify-knowledge-assets.sh
```

现场业务验收至少记录：

- 选择不少于 10 起已复核历史案件生成经验卡；
- 使用不少于 5 起目标案件验证推荐结果；
- 经验卡事实和证据引用覆盖率 100%；
- 未确认或已归档经验进入报告 0 次；
- 重复生成产生重复版本 0 次；
- 复用操作导致案件字段变化 0 次；
- 业务人员对推荐适用性、报告节省时间和最终采纳率签字确认。

代码测试和演示样本不能替代上述真实业务验收。

## 7. 回退

应用可直接回退到 v2.5，但应保留两张知识资产表，避免丢失复核和引用轨迹。只有在完成备份、确认
没有需要保留的 v2.6 数据后，才能执行数据库降级。紧急情况下优先停止知识资产写操作并使用现有
案件、地图、报告和 Agent 稳定链路，不删除资产版本或复用记录。
