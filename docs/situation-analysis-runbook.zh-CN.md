# 双域态势研判工作台运行与验收手册

> 适用版本：AICommander `v3.0.0-stable`
> 功能定位：从新增案件和地图井点中形成新的态势结果，不做多 Agent 重复审核。

## 1. 日常使用流程

1. 在“研判—态势研判”或首页“双域态势研判”进入工作台。
2. 选择 7、14、30 或 90 天窗口；系统自动与紧邻的等长上一窗口比较。
3. 需要限定辖区时填写区域关键词；井点半径按业务场景选择 1—20 公里。
4. 点击“生成态势研判”，先看案件增减、历史聚集热点、井点空间参考和坐标就绪率。
5. 只处理系统突出显示的最多三项核查重点，点击查看数据依据与适用边界。
6. 需要形成材料时导出一页 Markdown 简报；需要核对来源时再进入单案证据图谱。

## 2. 计算口径

| 项目 | 口径 |
| --- | --- |
| 当前窗口 | 截止时间向前指定天数，包含截止时点 |
| 上一窗口 | 当前窗口之前紧邻的等长时间段，不与当前窗口重叠 |
| 热点变化 | 当前窗口聚集案件数减去上一窗口同半径案件数 |
| 井点关注度 | 本期邻近案件数、较上期变化、高产井标记和坐标核验状态的确定性组合 |
| 手法变化 | 当前窗口与上一窗口相同作案手法标签的数量差 |
| 数据版本 | 时间范围、筛选条件及参与计算的案件和井点结果生成的 SHA-256 摘要 |

关注度只是帮助排序的工作指标，不是犯罪风险预测。空间接近不能证明案件与井点存在事实关联。

## 3. 数据与权限边界

- 接口只有 `GET /api/situation/overview`，不提供配套写入、确认或调度接口。
- 只读取案件时间、地点、类型、手法、设施和坐标，以及活动井点的必要地图字段。
- 不查询或返回人员姓名、电话、证件号、车牌和案件描述全文。
- 不调用 OpenAI、DeepSeek 或其他外部模型，不向外网发送案件和井点数据。
- 结果不自动生成串案结论、巡逻任务、处置指令或正式报告结论。
- 当前窗口无匹配案件时返回明确空态，不生成泛化建议。

## 4. 页面结果

- 五项摘要：本期案件、变化量、热点数、井点参考数、坐标就绪率。
- 四步运行轨迹：锁定范围、识别增量、双域空间计算、生成简报。
- 双域时空态势沙盘：案件、历史聚集热点、井点和空间参考虚线。
- 今日优先核查：最多三项，包含数据依据、发现、建议动作和边界。
- 一页研判简报：事实摘要、研判发现、建议核查和使用边界。

## 5. 发布前专项验收

在仓库根目录执行：

```bash
./scripts/verify-situation.sh
```

脚本检查增量窗口、热点、井点、证据与链条边界，全新 SQLite 迁移，前端呈现、类型和生产构建，以及生产
编排和脚本格式。完整 stable 发布还需执行全量测试、生产依赖审计、PostgreSQL 迁移和隔离部署演练。

## 6. 测试部署现场验收

- 准备至少 30 起跨两个等长时间窗口的脱敏案件，并包含至少 10 起带坐标案件。
- 选择至少 5 口重点井，其中包含高产井和未核验井点，核对关注顺序是否便于实际工作。
- 分别运行 7 天、30 天、90 天及一个区域关键词场景，人工复算案件数量与变化量。
- 调整井点半径，确认空间参考随范围变化，且页面始终不表述为事实关联。
- 记录至少 20 次使用的人工耗时、系统耗时、建议采纳数和新发现线索数。
- 模拟态势接口故障，确认案件录入、地图、报告和今日工作台继续可用。

本手册和自动化结果只能证明代码级与隔离环境就绪，不能替代目标服务器部署、真实数据适用性核验和业务签字。
