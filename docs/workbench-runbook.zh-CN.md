# AICommander v2.8 今日研判工作台运行手册

## 1. 建设目标

今日研判工作台不是新的案件库，也不是自动处置 Agent。它把现有案件数据质量、经验卡和研判报告状态
组合成一条日常可完成的工作流，并为每起案件只给出一个明确下一步：

`数据核验 → 经验生成/复核 → 报告生成/复核 → 当前闭环`

工作台只做分流、进度提示和效率度量，不自动修改案件事实、坐标、经验卡状态或正式报告。

## 2. 角色与数据边界

| 角色 | 查看任务 | 开始/完成任务 | 效率数据范围 |
| --- | --- | --- | --- |
| 管理员 | 是 | 是 | 全组聚合 |
| 分析员 | 是 | 是 | 仅本人聚合 |
| 只读账号 | 是 | 否 | 不采集、不展示 |

`workbench_task_sessions` 只保存用户标识、任务类型、来源类型/编号、内部页面路径、开始结束时间和页面
跳转次数。写入前会删除 URL 查询参数，并拒绝外部 URL、协议相对 URL、反斜杠和控制字符。该表禁止
保存姓名、电话、证件号、完整案情、真实井名、精确坐标或模型输入输出。

## 3. 日常操作

1. 从顶部“总览 → 今日工作”进入 `/workbench`。
2. 先处理“优先”任务；点击队列后，右侧显示事实状态、业务影响、下一步和依据编号。
3. 分析员或管理员点击“开始处理/开始复核”。相同任务重复点击会恢复原会话，不重复计数。
4. 页面顶部出现“进行中”条，可跨页面处理、返回工作台、主动完成或放弃。
5. 同一用户开始另一任务时，上一活动任务自动标记为放弃，确保任一时刻只有一个活动会话。
6. 管理员看全组 30 日聚合，分析员只看本人。样本不足 20 次时统一显示“需累计样本”，不能宣称已
   证明节时或效率提升。

## 4. 分流机制

- 坐标、核心字段缺失，质量评分低于 70，或质量缺项非空：进入“数据核验”。
- 数据可研判但没有经验卡：进入“经验生成”。
- 最新经验卡未确认：进入“经验复核”。
- 经验卡已确认但没有版本化报告：进入“报告生成”。
- 最新报告未确认：进入“报告复核”。
- 最新经验卡和报告均已人工确认：计入“当前闭环”，不再生成待办。

工作台不以 Agent、Redis 或外部模型是否可用作为案件主流程前置条件。Agent 待审批数仅作旁路提示。

## 5. 接口

- `GET /api/workbench/today`：返回角色范围内的任务摘要、阶段计数、唯一下一步和活动会话。
- `POST /api/workbench/sessions`：开始或恢复任务；只允许管理员、分析员。
- `GET /api/workbench/sessions/active`：读取本人当前活动任务。
- `POST /api/workbench/sessions/{id}/events`：记录内部页面切换、完成或放弃；重复完成保持幂等。
- `GET /api/workbench/metrics?days=30`：返回角色隔离的非敏感聚合指标。

## 6. 部署与回滚

升级前先备份数据库，然后执行：

```bash
cd backend
venv/bin/python -m alembic upgrade head
venv/bin/python -m alembic current
```

预期迁移版本为 `a7d9e1f2b304`，并存在 `workbench_task_sessions` 表。代码级专项验收：

```bash
./scripts/verify-workbench.sh
```

若工作台接口异常，可暂时从导航隐藏入口或回滚前端；案件、地图、报告和 Agent 接口不依赖工作台返回。
如需数据库降级，应先导出效率聚合证据，再由维护人员执行 Alembic 降级。任务会话不含正式业务修改，
删除该表不会改变案件、井位、经验卡或报告内容。

## 7. 测试环境验收门槛

- 每起案件同时只出现一个下一步任务。
- 同一任务重复开始不重复建会话，完成事件重复提交不重复计数。
- 只读账号不能开始任务或读取效率指标。
- 分析员不能看到其他人的聚合，管理员只能看到汇总，不展示个人案情。
- 外部 URL 和带敏感查询参数的路径不得原样入库。
- 工作台不可用时，案件录入、地图展示和报告流程仍可使用。
- 累计至少 20 次真实任务后，才能讨论完成率、平均耗时和平均跨页是否达到业务目标。
