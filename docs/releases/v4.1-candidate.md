## 部署配置

完整导出API使用 `docker-compose.document-renderer.yml`，与 `docker-compose.production.yml` 同时加载。
该覆盖文件只更换API镜像；Worker/Beat保留轻量镜像。默认部署脚本仅接受一个Compose文件，
不能仅运行默认脚本就声称启用了完整导出环境。

在联网制包环境构建并检查两份Compose合并配置，随后导出全部所需镜像，通过受控路径运入内网。
最终发布时APP_VERSION、源码VERSION和镜像标签必须一致；候选标签不可充当Stable标签。
运行时不得安装字体、浏览器或办公软件。完整导出镜像已带Noto字体、Node、Chromium、LibreOffice。

内网部署已准备好配置、密钥文件、镜像和升级前备份后，按以下顺序执行（会修改目标部署，非只读检查）：

```sh
# 先按运维手册填写并校验.env.production，记录升级前版本。
sh scripts/preflight-production.sh
sh scripts/backup-production.sh
docker compose --env-file .env.production -f docker-compose.production.yml -f docker-compose.document-renderer.yml run --rm --no-deps --pull never backend alembic upgrade head
docker compose --env-file .env.production -f docker-compose.production.yml -f docker-compose.document-renderer.yml up -d --no-build --pull never --wait
```

以上为已有PostgreSQL/Redis运行中的升级路径；全新安装需先按运维手册初始化核心依赖。
若开启Agent Lab，所有相关Compose操作还需带`--profile agent-lab`；关闭智能能力不影响案件保存。
不要将密钥、完整展开的Compose配置、业务地图包或演练数据库提交GitHub。
