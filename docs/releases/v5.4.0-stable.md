# v5.4.0-stable：重点设施与区域综合研判

本版完成 5.x 路线图的设施与区域侧贯通，以 `v5.3.0-stable` 为上一恢复点。本说明对应源码与隔离验证范围，不代表目标服务器已经部署、真实模型已经接通或正式业务效果已经验证；GitHub 发布状态以最终 PR、CI 和 Release 为准。

## 日常使用变化

- 从案件候选、案件地图、辖区地图和大屏按同一稳定设施编号打开综合档案。生产属性与台账来源、有明确记录的案件关联、空间邻近案件、待核验候选、事件、历史成果、入口道路、技防和历史条件分开展示。
- “附近发生案件”不提升为设施涉案事实；系统候选不转为人工确认。入口关联核验、道路连接和通行条件分别保留；技防资料缺失不等于没有技防。
- 区域条件对照读取全部授权匹配案件的有效保存画像，展示可参考案例、相似条件、差异及资料缺口，不重新抽取所有原文，不生成犯罪风险分或发案预测。历史案例为有限例示，设施分页不缩减参与对照的历史范围。
- 案件、区域条件对照、时空视图和辖区底座共享辖区、半开时间窗及案件、设施、事件选择。时间分桶使用北京时间，案件与独立事件分别统计；案件专有筛选未应用到区域统计时明确提示。
- 大屏普通入口默认滚动最近七天，自动更新不会把首次进入时刻永久固定为截止时间；显式共享窗口保持原条件。只有用户明确选择“全部授权历史”才保留该模式，不静默替换为最近七天。
- 区域案件和事件地图点位各最多展示 500 条，并标明截断；全库总量、时段与月度统计不以展示样本代替总体。缺失、过期、受限和读取失败分别显示，不以旧缓存或零风险替代。
- 新导入的同名不同编号设施不再按名称误合并。既有疑似误合并资料不自动猜测拆分，保留管理员核验处理；独立事件、已有专题、会议、报告和正式记录继续保留。

## 接口与运行方式

新增两个只读接口：

- `GET /api/facility-analysis/assets/{id}`：按稳定设施编号读取当前授权资料，可带 `start_date`、`end_date`。
- `GET /api/facility-analysis/region`：按 `operational_area_id`、时间窗和设施分页读取区域对照、统计与时间线。

读取采用起始时刻包含、截止时刻不包含的时间口径。每次读取重新核验当前授权，受限资料不暴露摘要或数量。页面打开、档案刷新和上述 GET 不触发业务写入、模型分析或道路重算。

本版仅新增派生表 `facility_derived_summaries`，保存设施目录摘要、内容指纹、变更原因和版本，不另建资产主库。普通 Celery 默认队列每 60 秒执行一批最多 25 个设施的保守巡检；只有内容或算法版本变化才增加摘要版本。该周期不是全库完成时限，也不宣称精准增量。

跨案关联、画像、道路及成果证据不缓存在全局设施摘要中，而是在读取时按当前权限复用已有资料组装。后台摘要未形成或待更新时明确展示状态，不阻断案件保存，也不要求普通用户额外启动 Agent。本能力不依赖 `ENABLE_AGENT_LAB`、可选 Agent Worker 或模型服务。

## 验证与能力边界

逐项门槛、测试、浏览器、数据库组件、性能和恢复证据见 [v5.4 收口记录](../validation/2026-09-25-v54-closeout.md)。最终发布以该记录及对应提交的 CI 结果为准，不在本说明中把局部检查扩写为正式业务验收。

离线地图资源、路由引擎和检索依赖未变，复用既有有效验证证据，不重复下载、制图或编译。本版道路展示复用已保存依据，不新增可通行承诺，也不还原真实行驶轨迹。资料来源缺失、历史条件过期或画像校验失败时保留缺口；条件相似不能成为当前案件事实。

真实模型未接通仍标记未启用；确定性设施与区域功能无需模型才能运行。目标服务器性能、现场资料质量及实际研判效果分别确认，不能由本机或合成样本结果替代。

## 升级步骤

1. 保留 v5.3 源码或镜像及兼容备份；在切换前备份最新数据库、原始案件与事件、生产资料、地图目录及配置密钥。GitHub 发布不自动操作业务数据库。
2. 沿用当前 PostGIS、pgvector 和离线运行组件，不替换数据库大版本或复用不兼容数据目录。地图、路网与检索资源无需因本版升级重建。
3. 在独立副本执行 `alembic upgrade head`，从 `e83f42c97ab3` 升至 `f94a53da8bc4`。该迁移仅新增 `facility_derived_summaries` 及索引，不自动改写原始案件、事件或生产台账。
4. 统一配置 `APP_VERSION=5.4.0-stable`、`ALEMBIC_TARGET=head`；API、普通 Celery Worker、Beat 和各可选 Worker 使用同一版本。目录巡检由已有默认队列处理，无需另开 Agent 队列或配置模型。
5. 按既有部署流程完成预检和迁移后，核验登录、案件保存与导入、核心地图报告，以及“案件候选 → 设施档案 → 来源案件”“地图设施 → 条件对照与事件时间线”。检查授权撤回、同名不同编号、资料更新和北京时间跨日统计，后台摘要待形成不应阻断读取主链路。

## 停用与回退

- 设施目录巡检是可重建派生维护。暂停该任务不会删除原始资料，档案按当前授权资料读取并明确摘要时效；不要为停用本能力关闭其他日常业务所需的普通 Worker。
- 应用回退与数据库恢复分开。先停止新版本写入并备份升级后的完整数据库和文件；将兼容 v5.3 的备份恢复到另一个数据库，旧代码只连接该兼容库，不直接连接未经验证的新结构。
- 保留升级后的原库与备份，禁止用旧备份覆盖升级后新增的案件、事件和生产资料。新增原始数据须经受控导入和逐项核对后迁回，派生摘要不代替原始业务记录。
- 本版迁移拒绝直接 `downgrade` 删除派生版本；使用上述独立兼容备份恢复路径。隔离恢复演练不能替代部署前的实际业务备份。
