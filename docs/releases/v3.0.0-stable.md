# AiCommander v3.0.0-stable 发布说明

发布日期：2026-09-08

## 发布定位

`v3.0.0-stable` 不增加质疑、复核或对抗 Agent，而是把分散的案件变化、历史热点和重点井空间分析组织成
可直接使用的“双域态势研判工作台”。系统比较相邻时间窗口，只突出最多三项核查重点，并生成一页研判简报。

## 核心变化

- 新增只读 `GET /api/situation/overview`，支持 7—90 天窗口、区域关键词、热点半径和井点半径。
- 新增当前窗口与紧邻上一窗口的案件数量、案件类型、作案手法和相对集中时点对比。
- 新增历史聚集热点变化，计算同半径上一窗口案件数和变化量。
- 新增重点井关注顺序，综合本期邻近案件、窗口变化、高产井标记和坐标核验状态。
- 每次最多生成三项核查重点，每项带案件/井点编号、发现、建议动作和适用边界。
- 新增离线双域时空态势沙盘、相邻窗口走势、手法变化、井点清单和 Markdown 简报导出。
- 当前窗口没有案件时不生成热点、井点排序或泛化建议。
- 更新后续路线，明确不建设多 Agent 反复审核同一数据的流程。

## 数据与系统边界

- 态势功能只有读取接口，不修改案件、井点、链条、知识资产或正式报告。
- 不查询或返回人员姓名、电话、证件号、车牌和案件描述全文。
- 历史聚集与空间接近不构成犯罪预测，也不能证明案件与井点存在事实关联。
- 不自动形成串案结论、巡逻任务或处置指令。
- 不依赖 OpenAI、DeepSeek 或其他模型 API；Agent Lab 和 Agent Worker 仍可保持关闭。

## 验证结果

- 后端 315 项全量测试、64 项双域态势/热点/链条/证据专项回归全部通过。
- 前端 25 个测试文件共 109 项全量测试、14 项关键呈现专项、TypeScript 类型检查和生产构建通过。
- Python 和前端生产依赖审计未发现已知漏洞。
- SQLite 与 PostgreSQL 全新数据库均迁移到 `a7d9e1f2b304`；v3.0 没有新增表或改变原表含义。
- 真实浏览器验证登录、首页与研判导航、默认 30 天窗口、三项核查重点、沙盘、井点排序、版本号和站内 GET 请求。
- 隔离生产部署验证服务健康、Agent 关闭、自动冒烟、内部端口限制和 43 表备份恢复。

## 未替代的现场验收

源码、本机测试、浏览器样例和隔离容器演练不代表目标服务器已部署或系统已正式投产。目标服务器仍需完成
备份迁移、单位网络与 HTTPS、权限抽查和核心回归；业务人员还需使用真实脱敏案件验证态势口径、关注顺序、
简报价值和实际节时效果，并形成签字记录。

## 升级与回滚

升级前先备份 PostgreSQL，部署时继续执行 `alembic upgrade head`。本版本没有新迁移，最终版本仍为
`a7d9e1f2b304`。回滚到 `v2.9.0-stable` 不需要清理正式案件、井点、链条、Agent 或知识资产数据。
