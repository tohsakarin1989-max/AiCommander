# v9.5.0-stable：实际保卫台账适配

基线为 v9.4.0-stable。本版根据本地只读核对的实际台账，优化案件导入、来源管理、规则整理及材料内容，不新增业务 Agent、不修改原始案件事实。完成范围是**本类台账的端到端适配**，不是“所有业务数据已经全面自动分析”。验证及未覆盖范围见 [发布验证记录](../validation/2026-10-09-v95-release.md)。

## 交付内容

### 原台账可以按原有结构导入

- 在案件批量导入中显式选择“保卫案件年度台账”；通用导入仍执行原有严格表头校验。
- 识别年度标题及表头，保留重复备注和无表头补充列，并按原列位置区分。
- 首个备注用于案件原文；“系统案件类型”和另一个表达协作方式的“案件类型”不再混用。
- 保留原上传文件、工作表、物理行号和全部非空原列值；案件详情“来源修订”可直接展开原始行。
- 原件和原行随失败重试保留，成功行不重复创建。原件撤销后，列表及单条引用隐藏复制的原始行内容。
- 年份、月日与原文日期冲突仅提示；没有单位的回收列不默认吨，空白不自动成为零。

### 现场发现、作案过程和处置结果分开

- 分别识别发现／查获、案发、报送／接报时间；不把首个日期统称案发，不跨相对日期套用前一事件时刻。
- 油量必须局部关联油品与环节；排除车辆载重、罐体容量、范围、上下界及约数，不把回收／移交量直接填为通用涉油量。
- 人员、车辆和油品处置绑定各自对象；计划、否定、拒绝、未获同意或未知反馈不变成已完成。
- 明确并列的“车辆及人员”等对象共用同一处置动作时分别保留候选，不只取最后一个对象；名单等资料不等于人员或车辆本身，待移交及将移交不当成已完成。
- 保留行政拘留、治安拘留等原词，不把移交公安解释成公安立案或办结。
- 本地规则和模型候选共用二次角色核对；这不等于已经验收真实模型理解效果。

### 页面与材料使用同一现场处置画像

- 在既有语义画像中单列发现、查获、回收、移交和检斤片段，记录肯否、不确定、环节数量及原文位置。
- 各环节数量不相加、不折算净油、不当损失量；回收队等单位名、抽油机等设施名不当作行为。
- 处置片段不进入作案手法相似评分，避免“都移交过”被当成犯罪条件相同。
- 页面和 Word/PDF 共用的内容模型读取同一画像及引用。原文缺少的事实仍未知，不为报告补造。

## 使用步骤

1. WPS `.et` 先另存为 `.xlsx`，保留原始文件作为业务原件。
2. 进入案件导入，选择“保卫案件年度台账”和实际工作表，检查预览及日期、单位提示。
3. 确认已有依据的字段；未知内容可保持空白，不能为通过导入猜测填写。
4. 导入后从案件“来源修订”查看原行，从已有画像查看现场处置片段；需要时再取用材料。

本预设不把年度序号当作跨文件稳定案件编号。相同原文件可以幂等重传；不同修订文件若无稳定来源身份，**不能**自动更新同一案件。

## 升级、索引与恢复

- 无新增数据库迁移、依赖或环境开关；数据库迁移头仍为 `v94o01`。从 v9.4 升级前照常备份数据库、原件及配置，替换相容应用及后台消费者。
- 语义规则使用独立版本 `local-events-9.4-field-1`，不是产品发布号。旧画像／索引通过已有版本检查显示需更新；本版发布不自动对现有业务库批量回填。需要重建时使用既有管理员入口。
- 地图源、PostGIS、Valhalla、离线地图包和文档转换引擎未改变，不重复制图或构建路由。
- 保留 v9.4 应用恢复点。回退前另行备份升级后新增案件、原件和人工修订，停止新消费者后再切换；不要通过还原旧备份丢掉新资料。
- 虽无表结构变化，旧应用不具备新预设和新来源展示／画像语义；回退后这部分能力将不可用。新生成资料应保留，不删除来源记录或派生成果来伪装兼容。

## 不计入本版完成的能力

- 人数、车数、处置人数和原表回收统计列完整保留为来源，但尚未增加对应全库统计指标或逐人逐车档案。
- `.et` 原生读取、无稳定键的跨修订自动合并、自动确定冲突日期及单位，均未交付。
- 无可靠坐标、可信入口和路网时不承诺道路、盗取来源或真实路径分析。
- 目标服务器部署、真实内网模型、目标服务器 PDF 转换及员工实际效率仍单独验收；本地和 CI 通过不代表已经正式投产。
- 真实样本原件、案情、人员信息及本地业务样本统计不随公开源码发布。合成回归没有使用真实记录。
