# v8.4.0-stable：有限信息下的参考、关注与变化解释

日期：2026-10-08。当前源码已收口至 **v8.4.0-stable**，版本、迁移及验证见 [实施记录](../validation/2026-10-08-v8x-implementation.md)。本次按用户授权统一发布8.x最终源码与README；标签、提交和在线检查以GitHub实际发布记录为准。源码发布不代表已部署真实业务环境。

## 交付内容

本轮覆盖8.0—8.4业务工作包，不推翻既有案件、地图、专题、会议和报告。

| 工作包 | 实际变化 |
| --- | --- |
| 8.0 | 日常录入围绕发现/接报和本单位处置；显式未知及旧反馈来源；简要资料可保存、检索、成文；不适用的深入分析不排队；台账同因问题预览后批量修正 |
| 8.1 | 相似参考与明确差异对照；最多三项；设施/区域四层依据及明确同源去重；完整/增量台账期间和缺席待核 |
| 8.2 | 发现、案发、录入三种时间轴；补录、更正、撤回与版本说明；同周期数据和条件变化用于大屏、简报、答案材料 |
| 8.3 | 同输入最多三套条件，比较生产期间、已登记车型、入口连接或道路额外排除；后台分批和显式续试；真实道路硬限制不放宽 |
| 8.4 | 历史参考、区域/设施关注、近期变化三个规则入口；回答完整度、证据、反向情况、缺口和版本；单个澄清续跑；冻结答案与地图用于页面及Word/PDF |

没有把记录少、无匹配、分析不适用或服务故障混成一个“无问题”。不因工具成功就宣布问题已回答，不自动确认来源、轨迹、链条或执行任务。

## 使用方式

- 员工正常录入实际掌握内容，案件详情中查看历史参考与适用性；无需管理Agent或挑选整批资源。
- 案件、设施档案、区域页面可带当前对象进入助手的明确业务问题；无对象时只澄清一个关键条件。
- 日常大屏默认最近30个完整业务日的发现/查获口径；案发和录入可显式切换。旧报表原口径保留。跳到旧区域资料页明确表示全历史资料，不悄悄将发现时段解释成案发时段。
- 有依据且已完成道路比较的案件可展开条件比较；旧图无保留原始源包时道路额外排除显示未具备条件，不用软避让或直线替代。
- 正式自由问句能力仍由真实内网模型配置决定；本次三个规则入口独立可用，不新增模型供应商绑定。

## 数据迁移与运行

唯一新增迁移：`v75r01 → v80f01`，为 `cases` 增加可空JSON `feedback_known_fields`。旧布尔值/原文不改写、不新增伪造案件修订；服务端在后续明确提交时才记录来源语义。

升级前按现有内网主手册保全数据库、来源原件、地图卷和配置；先在独立库执行 `alembic upgrade head`。应用、普通Worker、道路Worker、前端应使用同一相容版本，沿用既有Outbox、查询Worker与Beat，不新建Agent集群。

新配置无需模型密钥。已有数据库需继续使用固定版本PostgreSQL16/PostGIS/pgvector；本次不更换地图或路由引擎、不重新下载地图或编译依赖。生产配置、离线镜像和字体/渲染器仍按实际批准清单提供。

正常路网发布开始保留经过授权过滤的源包及校验信息，用于严格情景子图。必须备份道路目录的 `.sources`，不能作为临时缓存清除；旧图不会凭版本升级自动补齐。私有情景图不发布成默认图，故障不替换基准图。

首次上线v7.5交付包独立保留，不自动将其固定镜像、验证记录或现场确认升级成8.4。8.4源码不是完整离线镜像交付包。

## 回退与兼容

1. 保留v7.5源码标签和升级前的相容数据库/原件/地图备份；先备份升级后的新增案件、生产资料和人工判断。
2. 在独立库/目录恢复相容备份，核对后切换应用和所有消费者，禁止覆盖现用库或清空新增业务数据。
3. 已产生明确反馈来源标记时，迁移主动拒绝删列降级；不能直接让旧版解释新语义。
4. 完整/增量台账声明写在原有导入元数据中，旧v7.5导入代码不认识该保留字段；回退必须使用相容备份或经验证的兼容适配，不能只换二进制。
5. 历史成果读取继续重核当前授权；不同地图快照不拼成一张“当前地图”。无法安全读取时明确受限/过期，不泄露旧内容或数量。
