# v7.0.0-stable：可靠首用与内网启用

日期：2026-09-30。**源码已收口为 v7.0.0-stable；未自动提交或发布 GitHub，未宣称现场投产。** 本版只交付 7.x 路线图中的 v7.0，不包含 v7.1—v7.5 的全部深化；不推倒重建，不删除现有案件、设施、专题、地图、材料、会议和人工历史。

## 日常可用变化

1. 首页直接提供“录案件、查案件、查井场、取材料”。工作台读取失败时仍可进入这些独立功能。查井场按名称或台账编号在授权范围内先筛选再分页，不局限于页面已加载设施。
2. 新增管理员“首次启用”：厂区创建/更名/默认设置、账号资料范围、已发布地图与首批台账状态。选定厂区随地图和台账入口传递。账号创建与显式范围同事务保存，更换默认厂区不会调整已有账号。
3. 新增案件安全保存：明确失败保留输入，离开/取消有提醒；不确定的新增提交锁定原输入与凭证，可查结果或原请求重试，成功直接打开本案。不会因超时换一个凭证重复建案。
4. 时间筛选同时覆盖精确时刻和相交的案发区间，未知时间不被猜成具体日期。区间仅表示可能落入窗口，可同时命中相邻窗口，不把窗口计数相加当成去重总量。日统计以北京时间统计精确时刻，并保留区间/未知分类。修复未知案发时间导致区域设施图层失败；小时、月份和时空桶不再强制给不确定时间分配日期。
5. 来源修订和附件支持完整游标翻页，切换案件清除前案内容；材料阅读/来源回跳保留目录条件，文件名包含标题、日期和版本。失败行修正输入不会被新回执悄悄清空；新导入模板明确北京时间，历史模板不自动改义。
6. 内网部署按启用能力校验镜像、架构、文件摘要及运行依赖。预构建模式禁止自动下载和构建，7.x 不再绕过 PostGIS/pgvector 检查。预检和实际部署从同一批准配置读取版本、数据库镜像与能力开关，防止被终端旧变量覆盖；报告模式补齐轻量消费者镜像的构建。新增完整恢复对象清单与当前版短手册。

权限编辑额外防护：读取失败/旧缓存刷新中不能保存授权；提交附打开表单时的预期范围，服务端锁定账号行后核对，其他管理员已修改则返回冲突，不覆盖新范围。管理员角色本身可管理全部厂区，界面明确说明，不能用厂区选择伪装限域管理员。

## 接口与兼容

- `POST /api/cases/` 可选 `Idempotency-Key`：按登录用户和凭证唯一，绑定输入；同凭证不同输入为 409。案件、来源、后台事件和回执同事务。旧无凭证客户端继续兼容。
- `GET /api/cases/submissions/{key}` 仅查询本人当前可访问的提交；`unconfirmed` 不能解释为“没有保存”，也不能据此换凭证。删除或失去权限不会重新创建案件。
- `GET /api/cases/{id}/sources` 增加引用游标与附件过滤，原版本游标保留。
- 创建账号支持显式 `area_scopes`；空数组表示不分配厂区，省略时保留旧客户端默认行为。修改范围支持 `expected_scopes` 冲突保护，新界面始终发送。
- `/api/jurisdiction/assets` 新增有界 `keyword`，按设施名/台账编号筛选，保持原授权检查。
- 数据库只增加 `case_submission_receipts`，唯一迁移头为 `v70s01`，前驱 `v65r01`。不自动改写原案件字段。

## 升级与首次启用

主入口：[当前内网启用与恢复手册](../current-intranet-operations.zh-CN.md)。旧运维记录保留作历史参考，不照抄旧版本号和迁移头。

1. 保留 v6.5 相容应用、数据库、原件、地图及配置恢复点；保护用户其他未提交修改，不以清空数据库完成升级。
2. 准备 PostgreSQL 16/PostGIS/pgvector 与同版后端、前端、Worker、Beat。按需准备中文导出、地图构建、路由或模型依赖。普通核心录入不依赖模型。
3. 对既有数据库停止写入和消费者，完成一致备份，在隔离目标执行 `alembic upgrade head` 并核对 `v70s01`；新安装使用已确认的空目标初始化。不能用自动建表代替迁移。
4. `APP_VERSION=7.0.0-stable`；内网使用 `DEPLOY_IMAGE_MODE=prebuilt`，填写 `OFFLINE_DELIVERY_MANIFEST` 与 `OFFLINE_DELIVERY_ROOT`。`ENABLE_DOCUMENT_EXPORT`、`ENABLE_MAP_BUILD` 只按已交付能力开启，仍保持旧执行模块关闭。
5. 部署预检通过后再切换本次同版服务。管理员进入 `/settings/setup` 配置厂区与账号范围，确认地图及首批台账，用普通业务账号完成录入、查回、设施地图、材料导出检查。

离线运行基底若来自较早版本，必须逐项检查当前依赖，不能跳过 `pip check`。本机隔离构建发现旧镜像缺少 pgvector/numpy，已在构建侧准备公开依赖后断网更新应用层；没有在内网运行时临时联网，也没有重编 Valhalla。

## 回退

回执表为空时可回退该新增迁移；回执非空时主动拒绝直接降级，防止丢掉防重复保存依据。不得删回执或删新案件绕过保护。

需要回 v6.5 时，先保全升级后的数据库、原件、地图和人工记录，再在新库/新目录恢复与 v6.5 相容的完整备份，核对后切换。升级后新增资料另行保护并受控迁回；不能让旧程序直接访问不相容的新库，也不能只恢复数据库却宣称地图/配置/密钥已恢复。
