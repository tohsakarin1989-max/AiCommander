# AiCommander v2.3.0-stable 发布说明

发布日期：2026-09-07

## 版本定位

`v2.3.0-stable` 将案件数据管家接入真实录入与批量质检流程，并完整继承 v2.2 地图数据管家。
本版本仍以确定性内网规则为主，不要求 OpenAI 或其他模型 API；Agent Lab、外部模型和正式数据写入
默认全部关闭。

案件数据管家始终只读。它只能检查用户明确选择的案件，输出完整性、一致性、坐标、时间、疑似重复、
数据缺口和证据索引，不生成案件字段候选写入，也不能自动修改案件、人员、车辆、坐标或研判结论。

## 主要更新

- 新增保存前服务端质量预检，与后端案件质量规则使用同一口径。
- 预检只返回评分、缺项、提醒和人工确认边界，不创建案件、不写入人员车辆台账。
- 预检异常时允许人工确认后继续走原案件保存接口，核心录入不依赖 Agent Worker、Redis 或模型服务。
- 新增案件数据管家指定人员试用控制，仅启用中的管理员或分析员可进入名单。
- `assist` 模式同时开放地图与案件数据管家；双域研判和证据报告仍保持影子/实验能力。
- 案件任务必须明确选择真实案件，不能混入地图资源，单次默认最多 30 起。
- 案件页新增“管家质检”入口，可按当前筛选范围分批提交只读任务并查看完整运行轨迹。
- Agent 运行中心新增案件试用状态、复核案件数、失败数、证据覆盖率和管理员一键停用。
- 一键停用会取消活动案件任务并保留审计轨迹，正式案件数据不发生变化。
- 地图候选审批白名单保持不变；全局写入开关不会赋予案件数据管家写入能力。

## 新增接口

```text
POST /api/cases/quality-preview
GET  /api/agent-case-steward/status
PUT  /api/agent-case-steward/control
POST /api/agent-case-steward/suspend
```

既有案件保存、批量复核和 `/api/agent-runs` 接口保持兼容。案件管家控制接口只在 Agent Lab 已启用时
开放；调整试用范围和一键停用仅管理员可执行。

## 默认生产配置

```text
ENABLE_AGENT_LAB=false
AGENT_MODE=off
AGENT_MUTATIONS_ENABLED=false
AGENT_CASE_PILOT_MAX_CASES=30
AGENT_MAP_PILOT_MAX_ASSETS=100
AGENT_PROVIDER=deterministic
AGENT_MODEL=
AGENT_USE_EXTERNAL_MODEL=false
AGENT_EXTERNAL_DATA_POLICY=redacted_only
AGENT_SDK_TRACING_ENABLED=false
```

升级后不会自动开放案件或地图试用。隔离环境切换到 `assist` 后，仍需管理员分别指定试用人员并主动
开启对应数据管家。案件只读试用无需开启 `AGENT_MUTATIONS_ENABLED`。

## 数据库与回退

本版本复用已有 `system_configs` 和四张 Agent 运行表，不新增数据库表或字段。案件试用开关和名单使用
系统配置表持久化；缺少配置时按关闭状态处理。Alembic 目标版本仍为 `c3a8d4f2b711`。

需要紧急回退时，可先在 Agent Lab 分别一键停用案件和地图试用，再将全局开关恢复为 `off` 并停止
Agent Worker。无需删除 Agent 表，也不得删除运行轨迹和审批证据。

## 现场验收边界

代码发布不等同于实际试用完成。以下材料仍需在目标环境留痕：

- 指定案件试用人员、试用时间段和复核责任人；
- 不少于 30 起脱敏案件的预检与批量质检结果；
- 人工处理耗时、Agent 辅助耗时、发现问题数和人工采纳率；
- 预检异常、Redis 中断、Worker 重启、断网和一键停用演练；
- 案件自动写入 0 次、未经审批地图写入 0 次、敏感字段外发 0 项；
- 连续五次竞赛演示记录。

未完成上述现场门槛时，本版本可作为前期测试部署和竞赛冻结代码，不得表述为已完成正式业务验收。
