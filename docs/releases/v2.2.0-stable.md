# AiCommander v2.2.0-stable 发布说明

发布日期：2026-09-04

## 版本定位

`v2.2.0-stable` 将 v2.1 的 Agent Runtime 推进为可供指定人员实际试用的“地图数据管家”。
本版本仍坚持内网规则优先，不要求 OpenAI 或其他模型 API；Agent Lab、外部模型和正式数据写入
在默认生产配置中全部关闭。

地图数据管家只处理用户明确选择的有效地图资源，形成带证据的质量问题和候选修正。候选修正仅限
未核验资源的名称首尾空格清理，以及使 Point 几何与已经录入的经纬度一致；不修改经纬度，不修改
已核验资源，不修改案件或研判结论。

## 主要更新

- 新增指定人员试用控制，只有启用中的管理员或分析员可进入试用名单。
- 修正真实登录主体身份读取，任务发起人、审批人和事件轨迹使用实际 `user_id`。
- `assist` 模式只开放地图数据管家，必须明确选择仍有效的地图资源，单次默认最多 100 项。
- 新增持久化的开启、候选写入暂停和试用名单配置，缺少配置时按关闭状态处理。
- 新增管理员一键停用：取消活动中的地图任务、使待审批候选失效，同时保留完整审计记录。
- 审批前再次校验全局写入保护、动态暂停状态和原任务发起人是否仍在试用名单；校验失败不消耗审批。
- 新增试用任务数、完成数、失败数、候选数、待审批数、执行数、驳回数、人工采纳率和证据覆盖率。
- 前端改为从真实地图资源中选择检查范围，显示试用状态、验收指标和管理员控制区。
- 暂停候选写入时仍允许规则质检和查看历史；批准按钮会隐藏，管理员仍可驳回候选。
- 增加地图管家权限、范围、身份、暂停、幂等和指标回归；Agent 验收脚本纳入新测试。

## 新增接口

```text
GET  /api/agent-map-steward/status
PUT  /api/agent-map-steward/control
POST /api/agent-map-steward/suspend
```

既有 `/api/agent-runs` 接口保持不变。地图管家控制接口只在 Agent Lab 已启用时开放；调整试用范围
和一键停用仅管理员可执行。

## 默认生产配置

```text
ENABLE_AGENT_LAB=false
AGENT_MODE=off
AGENT_MUTATIONS_ENABLED=false
AGENT_MAP_PILOT_MAX_ASSETS=100
AGENT_PROVIDER=deterministic
AGENT_MODEL=
AGENT_USE_EXTERNAL_MODEL=false
AGENT_EXTERNAL_DATA_POLICY=redacted_only
AGENT_SDK_TRACING_ENABLED=false
```

升级到 v2.2 后不会自动开放试用。即使运维人员将全局模式切换为 `assist`，仍需管理员在系统内指定
试用人员并主动开启地图数据管家，候选写入才可能进入人工审批链路。

## 数据库与回退

本版本复用已有 `system_configs` 和四张 Agent 运行表，不新增数据库表或字段。Alembic 目标版本仍为
`c3a8d4f2b711`。升级前照常备份 PostgreSQL 并执行 `alembic upgrade head`。

需要紧急回退时，管理员可先在 Agent Lab 点击“一键停用试用”，再将全局环境开关恢复为 `off` 并
停止 Agent Worker。无需删除 Agent 表，也不得删除运行轨迹和审批证据。

## 现场验收边界

代码发布不等同于实际试用完成。以下材料仍必须在目标环境留痕：

- 指定人员名单、试用时间段和审批责任人；
- 不少于 100 个脱敏地图资源的质检结果与人工复核记录；
- 人工处理耗时、Agent 辅助耗时、有效问题数和人工采纳率；
- 一键停用、Redis 中断、Worker 重启和断网演练；
- 未经审批写入 0 次、敏感字段外发 0 项、坐标异常均为“待核验”；
- 连续五次竞赛演示记录。

未完成这些现场门槛时，本版本可作为前期测试部署和竞赛冻结代码，不得表述为已完成正式业务验收。
