# v6.1.0-stable：资料与案件骨架

日期：2026-09-27。本版按[未投产阶段重构方案](../superpowers/specs/2026-09-27-predeployment-refactor-review.md)推进资料采集、类型化数据、来源留痕和案件档案，不包含后续 v6.2—v6.5。

这是本地源码交付说明，不代表 GitHub 已发布、目标服务器已部署或正式业务效果已验收。

## 本版解决什么

- **不知道准确时间也能记录。** 区分精确时刻、时间区间和未知，保留“昨晚”等原文与发现时间。不用今天、零点或当前年份补造案发时间；未知时间单列，不混入精确周期统计或奖金季度。
- **油量必须有明确口径。** 数值、单位、测量环节、方法、时间和含水率口径分别保存。升、千克、立方米、吨和未知单位不直接相加；缺少转换条件时不换算，也不按吨生成大油量标签或奖金。
- **一个案件可以有多种地点。** 案发、发现、原文提及、来源候选和保管位置分开，支持点、线、面。只有唯一、明确的案发点投影为主坐标；区域或未知地点不使用中心点，不残留旧精确点。
- **人员车辆只维护一套正式明细。** 新录入以子表为准，旧 JSON 仅保留原始资料，不与子表相加，也不作为第二套可编辑事实。
- **缺项提示更合理。** 格式有效性、资料完整性和能力资料准备度分开，最多显示三项优先缺口。“未发现车辆”“未抓获人员”不被当成已存在对象；未生成报告、经验卡不表示案件未办结。
- **一个稳定案件档案。** 概览、来源与明细、关联地图、研判成果、业务材料各就其位。统一“记录资料”入口保留案件、独立事件和独立线索的不同身份；旧首页回到工作台，退出手工会话壳，历史业务记录不删除。
- **修改有来源版本。** 案件及相关明细变更在同一事务生成来源修订和变更记录，后台投递状态独立。相同数据不重复生成修订；内容改回旧值仍是新的修订，不冒用旧画像版本。事件转案件一次提交、重复请求不重复建案，保留原事件来源快照。
- **原件与登记目录分清。** 可上传 PDF、PNG、JPEG 小型原件（单文件不超过 4 MiB），保存摘要、版本引用和内容校验；下载重新检查案件权限。仅登记路径的历史材料明确为“目录记录”，不读取服务器任意路径、不冒充原件可用。

质量中的“能力准备度”只评价输入资料，不代替道路、模型或队列的运行健康。模型仍可关闭，以上新增骨架不依赖外部模型。

## 数据与接口

迁移头：`v60c01 → v61s01`，文件 `backend/alembic/versions/v61s01_case_source_foundation.py`。

新增或扩展：类型化地点、测量、来源修订、来源关联、原件、出处引用、业务变更与投递状态；案件画像绑定具体来源修订。现有原文、历史人工确认和报告保留。旧单位无法核定时是 `unknown`，不根据数值猜单位；来源历史从实际写入开始记录，不伪造升级前修订。

主要读取入口位于 `/api/cases/{id}` 下：`locations`、`measurements`、`sources`、`sources/{revision_id}`、`source-references/{reference_id}`。原件上传使用 `evidence-files`，下载使用 `source-references/{reference_id}/file`，撤销可用性使用 `source-references/{reference_id}/revoke`。历史版本读取仍按当前辖区权限检查。

原件目前保存在数据库中，随数据库备份恢复；读取列表不加载正文。首期只做类型、大小和摘要校验，**不是恶意文件扫描、OCR 或真伪鉴定**。下载采用附件方式，不在页面执行原件。

## 初始化或升级

### 没有待保留数据的新环境

提供 `backend/init_fresh_db.py`，必须显式指定目标并确认其为空。例如仅用于新建的本地测试库：

```bash
cd backend
venv/bin/python init_fresh_db.py \
  --database-url sqlite:////tmp/aicommander-v61-new.db \
  --confirm-empty-target
```

有表或视图时拒绝运行；不会从现用配置偷偷选择数据库，不删除或迁入任何旧资料。PostgreSQL 目标应由管理员新建并具备既有 PostGIS、pgvector 依赖。初始化仍使用权威迁移链，**不是已经压缩历史迁移或删除所有旧表**；首次账号初始化沿用原部署流程。

### 保留当前测试、演示或业务资料的环境

1. 备份数据库、配置、公共地图和持久化文件，确认可恢复；保留当前版本包。
2. 暂停写入及后台消费者，在隔离副本执行 `alembic upgrade head` 并核对迁移头 `v61s01`。
3. 同步更新前后端和 Worker，再开放录入；不要让旧程序写入新数据契约。
4. 如需补齐旧画像，使用既有管理员分批回填入口。旧 JSON 明细没有被批量猜测合并；有价值的旧资料应明确映射后再导入。
5. 核验未知时间保存、明细、来源版本、材料权限和地图显示，再对外提供测试服务。

本轮只在隔离 SQLite 和本机可丢弃 PostgreSQL 完成迁移及恢复验证，没有执行现用数据库升级。

## 回退与未完成边界

- 禁止就地降级删除新来源、测量和原件。迁移主动拒绝 downgrade，要求使用兼容备份。
- 回退至 v6.0 应恢复到独立兼容库，完整保留升级后数据库，再导出、核对新增原始案件、事件、线索、测量和材料；不得直接覆盖当前库。
- 公共地图、路网引擎没有变更，不重新下载或构建；本版不宣称新增道路覆盖。
- 独立事件/线索保留各自业务身份，本版来源版本以案件及其关联资料为中心，不宣称已经实现全系统事件溯源。
- 设施身份与历史有效期、深层过程理解、片段检索、条件对照和统一材料中心留给后续版本。
- 真实模型、现场负载和业务效果分别记录。本轮未建立冻结 v6.0 环境的保存 P95 对比，不能复用旧基准声称本版性能门槛已通过。
