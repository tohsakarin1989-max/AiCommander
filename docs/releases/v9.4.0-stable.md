## 员工与管理员如何使用

1. 日常在“录案件”写已掌握的简要经过；等到“已暂存”回执后，可在“我的草稿”继续。断网时尚未得到确认的输入不会伪称已保存。
2. 案件列表按发现、案发或录入口径筛选；“导出筛选明细”导出整个授权筛选结果，可选择白名单列及表头，不受当前页大小限制。
3. 同一来源的后续案件表，填写稳定来源键、源版本，并映射外部记录键。无稳定键的旧方式仍可新增，不按相似描述猜测合并。
4. 地图管理员首次按真实工作表确认模板，以后复用；普通台账处理进入后台，可离页。完整批次失败保持旧设施可见，修正原表后整批重传。
5. 材料阅读器选择用途与章节，直接取用现有冻结材料；来源、版本、边界及必要反向依据不能被配置隐藏。
6. 系统设置默认显示实际启用能力。仅有模型登记记录或地图发布记录，不等于已经现场验证可用。

## 迁移与后台任务

新增迁移链：`v80f01 → v91s01 → v94o01`。

- `v91s01`：`case_import_source_records`，按厂区/来源/外部记录键唯一，保存源版本及实际采用字段基线。
- `v94o01`：`output_templates`，保存范围内白名单输出配置与版本。
- 地图后台作业复用 `MapIngestRun`、暂存 claim 与现有设施版本，不建立第二套设施主库。

升级前备份数据库、原件、地图和配置；在隔离库执行 `cd backend && alembic upgrade head` 后再切换相容应用及消费者。禁止向现有生产库运行合成验证脚本。

普通 Celery Worker 必须加载 `app.tasks.map_ingest_tasks`，并消费既有 `map_build` 队列；Beat 每 10 秒投递 `aicommander.map_ledgers.process_next`。没有消费者时任务保留排队状态，不让网页等待大表完成，也不伪称已采用。沿用查询与案件 Outbox 任务，不增加 Agent 集群。

本次不更换 PostgreSQL/PostGIS/pgvector、Valhalla、底图或模型供应商，不重复下载地图或编译路由引擎。不需要新增模型密钥。

## 恢复与数据保护

1. 保留 v8.4.0-stable 和升级前相容备份；回退前先另行保全升级后新增原始案件、原件、生产资料和人工修订。
2. 新来源身份或输出模板已使用时，迁移拒绝直接删除非空新表。不得绕过保护强行删表。
3. 在新库恢复相容备份并核对，停掉新版本消费者后切换相容应用；不要把旧程序直接指向含新语义的当前库。
4. 需保留升级后新增业务资料时，应先制定与验证转接/回灌清单；本发布不承诺把新来源身份无损解释为旧代码语义。
5. 完整台账未采用的暂存内容不能变成现行生产资料；取消不悄悄删除已生效记录。

## 明确限制

- 本版是规则业务能力的源码 Stable。真实内网模型增强、任意自然语言理解和模型辅助录入效果未验收，保持未启用/待验；没有用聊天模型或模拟响应替代。
- 单位正式样表尚未提供，通用或自定义输出配置不宣称符合正式报送格式。
- 可信历史读取先覆盖三类明确业务问题；缺乏完整冻结证据的旧材料和复杂道路任务继续严格失效，不把当前数据反填为过去事实。
- 案件表导出上限为 50000 条，超过明确要求缩小范围；不静默截断或伪称全库导出成功。
- 案件来源冲突不自动覆盖：修正源表/源版本后重新预览，原失败批次保留；不使用旧失败行“首次建案”重试。
- 完整生产台账有异常需修正原表/模板后重新提交；不将少数成功行提前发布为完整台账。
- 未经核验的高斯投影及本地坐标组合明确禁用，使用经确认坐标模板或已转换标准资料；放大底图不增加来源精度。
- 浏览器、合成资料、真实本地数据库/渲染器证据不替代目标服务器、两市全域性能或员工实际效率评估。
