# v5.2.0-stable：道路与生产条件融合研判

本次收口范围是用户调整后的 **v5.0—v5.2 源码升级**，不包含 v5.3 专题与周期材料、v5.4 设施综合档案。上一已提交恢复点为 `v4.5.0-stable`（`4eb95330f47eeb0466c35703e63137765ed3a96c`）。不补造 v5.0/v5.1 标签，不自动提交、推送或创建 GitHub Release。

## 用户可使用的变化

- 日常工作入口整合，案件工作界面集中读取原始资料、画像、历史参考、地图与已有成果；不因没生成经验卡、报告而判定案件未完成。旧深链接、独立事件、会议和人工判断保留。
- 案件语义增加有原文出处的事件片段，明确肯定、否定、不确定和缺失。案件与已确认经验使用同一授权历史检索，覆盖早期资料；中文词项与结构条件可离线运行。内网模型和语义向量按配置可选，未接通不冒充已启用。
- 道路计算前移：从授权地图召回设施，核对稳定编号、生产属性、历史条件和可信入口，再分批计算道路并排序。后台最多召回 100 个设施，最终最多展示三项，不只给旧前三补画路线。
- 候选说明道路距离、绕行、条件差异、证据和缺项；硬限制不被加分覆盖，未知入口不使用中心点代替，路由故障不回填直线距离。可展开同一冻结入口的真实参考路径。
- 案件界面与报告使用同一候选、入口和版本；旧空间候选折叠保留。地图/路网/历史资料与算法版本变化通过原授权后台任务刷新，保留取消与失效边界。
- 管理员可归档固定设施池，与保留的旧来源算法对照；原文后来变化不改变固定输入，撤权后仍不能访问。未标注、失败和覆盖不完整不计为正确样本，规则支持度不称准确概率。

## 升级与交付

1. 保留上一 Stable 源码和相容数据库备份，另存升级时最新原始案件、事件、生产资料与地图包清单。当前工作区还包含先前 UI、权限和演示维护，不自动将其全部归为 5.x 新功能或提交。
2. 在允许联网的制包区构建目标架构依赖和应用镜像；内网不在线下载模型、地图、字体或运行库。可选模型另行打包，默认关闭。已有地图和路由引擎不要求重新下载或编译。
3. 数据库镜像必须同时包含 PostGIS 和 pgvector。按 [本地历史检索部署说明](../local-history-embedding.zh-CN.md) 制包、核对镜像/包摘要，填入 `.env.production` 的 `POSTGIS_IMAGE`。不再默认使用缺少向量扩展的旧镜像；只接受不可变摘要，预检不自动下载。
4. 从旧数据库逻辑备份恢复到独立新卷，不能把旧 Alpine 数据目录直接挂到 Debian 镜像。先在副本执行 `alembic upgrade head`，目标 `d72e31b86fa2`。v5.0/v5.2 无额外业务表迁移；v5.1 新增 `c61d20a75e91` 词项/断点与 `d72e31b86fa2` 派生向量表。原始案件语义不变。
5. 部署配置 `APP_VERSION=5.2.0-stable`、`ALEMBIC_TARGET=head`。先完成镜像预检、迁移和副本验收，再按既有受控停写步骤切换。没有自动修改本机运行中的示范或业务服务。
6. API、画像/检索 Worker、道路 Worker、Beat 使用同一版应用。历史索引由后台持久断点逐批补齐；道路升级任务每五分钟登记，只有保留原始授权、仍有效且未取消的任务进入新计算。首次资料不足明确显示等待或部分完成，不新增一线必需操作。
7. 核对登录与权限、案件保存/导入、地图、报告、工作台、历史检索、路由故障与核心业务不受影响。真模型能力保持未启用，直到完成真实服务与断公网依赖验证。

## 停用与回退

- 只停用智能能力时，先停止对应后台消费者，撤销可选模型配置，保留普通案件和地图链路。已冻结历史成果仍按当前权限读取，不删除原始资料。
- 应用回退与数据库恢复分开处理。停止新版本写入，先再次备份新库和升级后的原始业务数据；在另一个库恢复与 v4.5 匹配的旧备份，再连接旧代码。**不能把旧应用直接指向未经兼容验证的新库，也不能直接恢复旧库覆盖新增案件。**
- 新版备份包含升级后数据，应独立保留。需要将新资料带回旧版时，先通过旧版支持的受控导入核对编号、字段、关联和数量，未完成核对前不切换业务。派生索引可以重建，原始事实不能丢弃。
- 本轮合成演练已验证新旧备份恢复到不同数据库，新版原始案件逐行全字段一致；新版备份校验为 `82714ce43bb4cc8ce6ae14c88edff9c457f173ff1abf47ad3336478c255b8b6e`。临时容器已清理；这是演练证据，不是用户业务备份。
