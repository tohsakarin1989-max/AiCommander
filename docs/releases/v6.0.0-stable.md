# v6.0.0-stable：主链与成果归一

日期：2026-09-27。范围：6.x 路线图的第一个版本，不包含 v6.1—v6.5。

本文件描述本地源码交付；GitHub 发布、目标服务器部署与正式业务效果分别核实，不能由版本号推定。

## 用户可见变化

- **案件只读一套当前画像。** 案件工作界面复用已保存的标准画像、处理卡与成果，不因打开页面重新抽取原文、生成经验卡或发起道路计算。旧详情接口保留为适配入口。
- **候选、地图、报告与助手同源。** 道路计算完成后，把原基础成果和冻结道路附件组合成新成果；不改写旧成果。没有有效道路结果时明确等待，不把空间接近解释成道路可达。
- **新增资料确实影响派生结果。** 案件线索和相关字段变化通过事务事件触发后台处理；旧推断按来源标记过期，已人工确认的关系保留，并提示其依据已变化。案件保存不再同步执行旧链条扫描。
- **人工确认对应具体内容。** 经验状态按具体资产版本判断，旧 JSON 卡保留历史来源，不把一次确认复制到新草稿。没有经验卡或报告不是案件未办结。
- **移除容易误导的旧分数。** 辖区旧风险分、条件组综合风险停止新增输出；保留生产资料、独立事件、反馈、历史成果及人工登记等级。邻近村屯不再单独触发新的囤储候选；附近有摄像头不等于已核实覆盖。
- **统计不受当前分页影响。** 报告与事件由后端按授权范围聚合，明确截止时刻和计数口径；失败不显示为零。
- **日常助手和实验开关分离。** 可单独停止新查询，已授权历史、导出、取消和过期清理仍可用。规则降级完成与模型成功分别记录，不因升级自动接通模型。

## 成果与权限边界

当前组合结构为 `case-result-composition-6.0.0-1`，兼容读取旧 `case-result-4.1.0-1`。组合只引用基础成果和道路附件，附件仍引用原基础输入；不会反向修改父对象或重复触发同输入道路任务。

当前选择绑定主体、授权范围、来源、车辆假设、算法、路网和通行条件。其他用户或其他权限分支的组合不能用于补位；该分支未就绪时返回部分成果。访问历史组合仍重新检查当前权限。基础空间结果仅保留作明确标注的历史/基础参照。

模型未配置、道路资料不全、队列中断和计算失败分别显示，不编造候选或把未知当成无问题。原始案件事实、人工确认和历史报告不被后台自动覆盖。

## 从 v5.4 升级

1. 先备份数据库、配置及地图/报告等持久化文件，记录当前应用包、迁移头和备份校验。不要把当前整个未提交工作区直接当成可发布包。
2. 沿用具备 PostGIS 与 pgvector 的现有数据库环境，不更换地图包或路由引擎。新增迁移文件为 `v60c01_chain_source_versions.py`，实际迁移头由 `f94a53da8bc4` 升到 `v60c01`，只为 `chain_links` 增加三个可空来源/算法版本字段。
3. 先迁移，再启动同版本后端、普通 Worker、Beat，以及环境原本需要的道路和可选查询 Worker。旧链条没有来源版本时不伪装当前推断；人工确认记录不删除。
4. 标准画像结构升级为 `6.0.0`。管理员使用既有 `POST /api/admin/case-profiles/backfill?limit=100&after_id=0` 分批回填；每次将响应 `next_after_id` 作为下一次 `after_id`，直到为空。回填只排队，继续观察后台完成状态，不把接口返回等同于画像已生成。普通用户无需新增操作。
5. 旧 JSON 经验卡保留原文和审核记录，没有在本版批量迁成新资产；无法确认同内容时不猜测合并。新确认使用具体版本入口；旧仅凭案件 ID 的确认不默选最新草稿。
6. 核对运行状态、案件工作界面、历史成果及管理员后台状态，再开放日常使用。

部署沿用[运维手册](../server-deployment-runbook.zh-CN.md)。本轮没有执行以上现场部署步骤。

## 配置与队列

新增可选 `ENABLE_INTELLIGENT_QUERY`：留空继承原 Lab 启用规则；`false` 停止新查询；`true` 独立开启查询，不开启实验 Lab 或写入权限。所有相关进程需使用一致配置并重建/重启。

普通队列增加链条事件消费和查询过期清理，关闭实验 Worker 不会关闭普通业务管线。已运行任务不是修改环境变量后立即中止，应使用取消入口或既有停机流程。

完整开关语义见[运行开关说明](../runtime-feature-switches.zh-CN.md)。实际 `.env` 和模型凭据本轮未修改。

## 验证与未验证

验证范围、准确结果、迁移与性能证据见[实施验证记录](../validation/2026-09-27-v60-implementation.md)。本版使用隔离合成数据验证代码和本机组件，未把模拟模型、生成文档或源码构建当作实际模型、目标服务器、真实业务验收。

## 回退

- 立即止损可先关闭新查询/相关后台消费者，保留案件与地图核心读取；不要删除事件、队列、派生记录或原始事实来“恢复”。
- 不支持就地数据库降级：迁移明确拒绝删除版本列。应用回退必须使用与旧版本兼容的独立恢复库；升级后的当前库先完整保留。
- 若需回到 v5.4：在独立环境恢复升级前兼容备份，核验后再切换。升级后新增案件、线索、事件、生产资料与人工判断须先导出、核对并迁入兼容环境；完成前不得用旧备份覆盖当前业务库。
- 发布包应保留 v5.4 恢复点及本版迁移、备份校验和验证记录。本次没有提交、推送、打标签或发布 GitHub Release。
