# AiCommander v2.6.0-stable 发布说明

发布日期：2026-09-08

## 版本定位

`v2.6.0-stable` 在 v2.5 统一 Agent 运行中心基础上，把现有即时研判报告、经验卡和历史案例检索
升级为可用于实际测试的知识资产闭环。核心变化不是增加模型依赖，而是让每份经验和报告具备固定版本、
人工复核状态、证据引用和复用轨迹。

本版本默认仍由内网确定性服务生成报告和经验卡，不需要 OpenAI 或其他模型 API，不依赖 Redis 或
Agent Worker。历史相似只用于已发生案件复盘，不形成犯罪预测、串并案确认、巡逻指令或案件字段修改。

## 主要更新

- 经验卡从 Case JSON 草稿升级为独立版本资产；相同源数据重复生成幂等，源案件变化后创建新版本。
- 案件研判报告可以保存为快照版本，固定当时的事实、推断、建议、信息缺口和证据索引。
- 经验卡和报告均采用 `draft -> confirmed -> archived` 受控状态，确认前校验源数据未变化和证据引用存在。
- 经验卡签名覆盖案件字段、证据、车辆/人员信息、条件标签、空间上下文和相似案例依赖；生成结果不会
  反向进入下一轮标签提取，避免派生文本自我放大。
- 只推荐已人工确认且未归档的其他案件经验卡，同时展示相似度、适用依据、差异风险和历史决定。
- 研判人员必须明确选择“采纳”或“不适用”；只有主动选中的经验会进入报告参考章节。
- 报告只引用经验卡和来源案件，不复制历史结论；报告仍需人工确认后使用。
- 新增复用轨迹，记录来源资产、目标案件、目标报告、决定、用途和适用性边界，重复请求不会重复落库。
- 管理员和分析员可以生成与复核，只读账号只能查看；旧版经验卡接口继续兼容但写操作也受权限保护。
- 案件研判页面增加经验卡版本、历史优秀案例推荐、报告快照版本和复用轨迹展示。

## 新增接口

```text
GET  /api/knowledge/assets
POST /api/knowledge/cases/{case_id}/experience-assets
POST /api/knowledge/cases/{case_id}/report-snapshots
POST /api/knowledge/assets/{asset_id}/review
GET  /api/knowledge/cases/{case_id}/reuse-recommendations
POST /api/knowledge/reuse-decisions
GET  /api/knowledge/reuse-records?target_case_id={case_id}
```

接口及业务操作详见 [知识资产运行与验收手册](../knowledge-asset-runbook.zh-CN.md)。

## 数据库与升级

新增迁移 `f6c8d2e4a913`：

- `knowledge_assets`：经验卡和案件报告版本、内容、证据、源签名与复核记录。
- `knowledge_reuse_records`：采纳、排除及报告引用轨迹。

升级前先完成数据库备份，再执行：

```bash
cd backend
alembic upgrade head
```

旧版 `Case.features.intelligence.experience_card` 保留兼容，不做破坏性迁移。生成首个 v2.6 独立版本后，
检索以独立资产状态为准，不会把新的未复核草稿误当成已确认经验。

## 安全与边界

- 未确认、已归档、本案自身或不存在的经验资产不能进入报告。
- 报告最多引用 10 张经验卡；前后端均以服务端状态校验为最终边界。
- 案件事实或报告统计范围变化后，旧草稿必须重新生成，不能强行确认。
- 复用决定只写审计轨迹，不修改目标案件、地图数据和正式结论。
- 所有知识资产留在内网数据库；本版本没有新增对外模型数据传输。
