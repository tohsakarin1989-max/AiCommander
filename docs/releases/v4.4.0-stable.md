# AiCommander v4.4.0-stable 发布准备

状态：功能已实现，分版本发布待完成。当前收口分支版本为4.5.0-rc.1，
本文件不是GitHub发布、目标服务器投产或真实业务成效证明。

## 本版业务变化

- 态势比较使用相同辖区、等长完整周期，案件按案发时间、处理进度按成果生成时间分别统计。
- 汇总手法、地点条件、道路来源及通行条件、技防摘要变化；数据缺失或版本不一致时明确不可比较。
- 每期最多三项关注建议，变化不足不强行给出泛化建议，不创建巡逻、调查或处置任务。
- 方案比较使用真实位置、设施范围和道路矩阵，区分已覆盖、未覆盖及重复覆盖。
- 有厂区边界和PostGIS时计算裁剪后的覆盖面积与重叠；缺视场/遮挡资料时仅称名义覆盖。
- 道路比较复用现有机动车引擎和通行权限，进入专用队列，可查看进度、取消及恢复。
- 历史方案保存输入摘要与地图版本，读取时再次核验权限与来源，过期结果不冒充当前可用。

## 数据与兼容

增量迁移：`93e6a20fd53b → a4f7b31ec64a → b508c42fd75b`。

- `situation_briefs`增加比较快照。
- 新增`spatial_coverage_comparisons`保存派生方案比较。
- 不覆盖正式案件、井位和原始生产台账。
- 当前交互比较有资源及目标数量上限；超限明确拒绝，不能据此声称任意规模或目标服务器性能已验证。

## 部署步骤

1. 维护窗口内备份数据库、地图/路网目录、配置及原有密钥，记录旧版镜像摘要。
2. 使用与发布提交一致的组合运行镜像，不能只更新前端或借用旧应用层。
3. 在独立环境应用上述增量迁移，核对迁移头和核心案件链路。
4. 按实际需要启用独立道路Worker；地图/道路/模型故障不得影响正常案件录入。
5. 核对案例详情、态势比较、覆盖方案、报告与权限，再进行受控业务切换。

首次部署保持Agent默认关闭。现场模型配置、TLS、目标服务器体验与业务效果单独记录，
不把本机合成测试当作现场验证。

## 回退

先停止新增写入和后台任务，再保留升级后数据库及地图目录的完整备份。
旧版程序只连接另库恢复的v4.3兼容备份，不能直接访问未经验证的新结构。
升级后新增原始案件不能丢弃，须受控留存并核对迁回；禁止直接删表充当回退。

## 验证状态

已有实际PostGIS覆盖面积/去重/边界裁剪、真实后台道路矩阵及独立备份恢复证据。
页面部分交互使用合成浏览器响应；这不替代整版生产镜像和完整展示验收。
累计回归和剩余门槛统一见[4.x收口核对](../validation/v4.5-closeout-audit.md)。

下一版v4.5负责固定输入评测、反馈校准、增量重算、运维及竞赛交付收口，不再增加业务智能体。
