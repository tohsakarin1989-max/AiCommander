# AiCommander v3.6.0-stable 发布说明

发布日期：2026-09-10

## 发布定位

将 v3.1—v3.6 的六阶段能力统一冻结为一次 Stable 发布。优先保证日常可用：用户正常录入案件，后台自动完成治理和研判，不再为 Agent 手工选择案件、井点和半径。保留 v3.0.0-stable 为回滚基线。

## 核心能力

- 地理底座：地图来源、Excel/CSV 模板、坐标转换、异常隔离、厂区权限与要素版本。
- 真正离线地图：受控公共更新包、完整瓦片验包、生产图层快照、内网瓦片服务、发布与回滚。
- 案件零操作治理：事务 Outbox、异步标准画像、最多三项关键缺失、历史回填、幂等和中断恢复。
- 自动双域研判：自动绑定案件画像与地图版本，每案最多三项区域级候选；同时展示支持证据、反向证据或信息缺口。
- 态势参谋：每日/每周部署参考、技防聚合摘要、最多三项建议和反馈，不创建执行任务。
- 统一治理：算法和范围策略版本、评测、受影响网格增量重算、覆盖对比沙盘、管理员运行中心。

## 安全与降级

原始案件和精确生产坐标不发送外部模型；默认不依赖模型 API。正式案件事实不会被后台 Agent 自动覆盖，候选不会自动变成正式结论或执行任务。厂区读写权限贯穿案件、地图、画像、成果与反馈。

地图没有有效快照时明确提示，不偷偷回退公网。模型故障保留规则结果；Redis 中断时案件保存与核心接口仍可用，Outbox 恢复后继续处理。地图构建失败继续使用上一有效版本。

- 连续五轮自动业务彩排，覆盖模型超时、Worker 暂停恢复、领取后重启和幂等重放；证据与反向证据覆盖率 100%，正式数据改写及执行任务创建均为 0。

详细地图包、镜像 ID、源码指纹和运行证据保存在受控内网目录，不上传公开 GitHub；公开版本只包含代码、测试和通用说明。自动演练不是现场人工讲解或真实业务成效证明。

## 部署与迁移

应用版本设为 `3.6.0-stable`，`ALEMBIC_TARGET=head`，最终迁移为 `a3e6b7c8d940`。按 `.env.production.example` 使用固定摘要 PostGIS 16 镜像，不再使用普通 PostgreSQL 镜像。升级前备份数据库、配置、密钥和离线地图文件。

迁移顺序：`a7d9e1f2b304 → b8f1c2d3e405 → c9a2d3e4f506 → d0b3e4f5a617 → e1c4f5a6b728 → f2d5a6b7c839 → a3e6b7c8d940`。

新增配置与安全默认值集中于 `.env.production.example`：旧公网地图、外部地理查询、巡逻物化与旧业务模块关闭；`MODEL_DATA_EGRESS_POLICY=local_only`，`ENABLE_AGENT_LAB=false`、`AGENT_MODE=off`、`AGENT_MUTATIONS_ENABLED=false`。地图、案件后台管道和定时简报由现有 Celery 与独立 Beat 调度，不要求开启旧 Agent Lab。

地图包独立受控交付，由管理员导入并发布。新增接口覆盖地图来源/模板/快照、案件画像/管道/候选、技防摘要、部署反馈和运行治理；健康入口为 `/health/maps`、`/health/case-pipeline`、`/health/agents`、`/health/tech-defense`。

回滚不能只切代码：在维护窗口停写，恢复升级前数据库及对应地图文件、配置，切回 v3.0 标签并按旧版手册重建验证。不要直接对正式业务库执行未经验证的降级。

## 发布后继续确认

30 天试用、固定数量业务样本和目标服务器测试不再阻塞源码 Stable。目标服务器的网络、HTTPS、目标架构、终端性能和现场备份恢复仍需确认；真实台账、坐标控制点、候选命中率和建议实用性随业务数据持续积累。当前不宣称已经正式投产，也不把合成样本成绩包装成真实业务效果。
