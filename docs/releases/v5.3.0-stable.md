# v5.3.0-stable：专题研判与周期材料

本版完整覆盖 5.x 路线图的 v5.3，以 `v5.2.0-stable` 为恢复点；不包含 v5.4 设施综合档案。本说明对应源码发布，不代表目标服务器已经部署或正式业务效果已经验证。

## 日常使用变化

- “案件研判 → 专题研判”将相似条件案组、关联图谱、地图时间线和专题报告放在同一工作界面。旧独立事件、会议、报告、图谱入口和历史资料保留。
- 按手法、油品、设施、地点、时间窗口等组合检索全部授权画像；肯定、否定、不确定、矛盾、缺项分别统计，代表案例分页不改变总体。
- 从研判助手保存已执行的查询条件，或直接建立专题；后台定期检查资料变化，保留历史版本。普通用户无需逐案选择、重新提取全部案情或重复生成已有道路依据。
- 同一修订复用历史案例、已确认经验、既有案件成果、道路附件及日周态势。图表、地图和导出引用同一批来源，原文后来更新不会改写已冻结依据；读取仍核验当前权限。
- Word/PDF 按需导出，包含总体、典型/反向案例、信息缺失、版本和边界。日周材料作为同辖区背景，不与专题条件统计相加。
- 无变化不新增修订或待办；可以暂停/恢复、保存备注和继续追问。分析案组只是共同条件，不自动建立正式串并案、团伙或执法任务。

## 验证与能力边界

详细逐项对照、测试、浏览器、性能及组件证据见 [v5.3 收口记录](../validation/2026-09-21-v53-closeout.md)；开发过程的历史失败和补充记录保留在 [实施记录](../validation/2026-09-21-v53-topic-progress.md)。

已验证授权全库分页、语义表述分离、历史引用和撤权、地图版本冻结、真实 Word/PDF、PostgreSQL 并发/暂停、真实 Redis 与默认队列 Beat/Worker、队列恢复、新旧库独立备份恢复。冻结本机 2000 案件/画像生成约 1.43 秒；相同环境保存 P95 中位数相对 v5.2 未超过 5% 退化门槛。该结果不是目标服务器性能承诺。

不新增依赖下载、地图制包或路由引擎编译。已有 Valhalla、离线底图、字体和检索依赖沿用 v5.2 验收边界。真实模型未接通则明确未启用；模型规划注入测试不是模型能力验收，规则专题不依赖模型。真实业务准确率、现场网络和服务器吞吐仍分别确认。

## 升级步骤

1. 保留 v5.2 源码/镜像及兼容备份；保存升级时最新数据库、原始案件/事件/生产资料、地图目录/清单及配置密钥。实际部署仍使用受控备份与维护窗口，不由 GitHub 发布自动操作业务库。
2. 沿用同时包含 PostGIS 和 pgvector 的固定摘要镜像；不能换回旧纯 PostGIS 镜像或直接跨发行版复用数据目录。参见 [历史检索离线说明](../local-history-embedding.zh-CN.md)。
3. 在独立副本执行 `alembic upgrade head`，从 `d72e31b86fa2` 升至 `e83f42c97ab3`。本版仅新增 `analysis_topics`、`topic_snapshots` 两张派生表，不改写案件事实，也无需重建地图/道路。
4. 统一配置 `APP_VERSION=5.3.0-stable`、`ALEMBIC_TARGET=head`。API、普通 Celery Worker、Beat 和各可选 Worker 使用同一版本；完成已有部署预检、备份和迁移流程后再切换。
5. 专题调度使用**默认 Celery 队列**，由标准部署中的 `celery` 和 `celery-beat` 处理；不依赖可选 `agent-worker`、`ENABLE_AGENT_LAB` 或外部模型。Beat 每 15 秒领取一个到期专题；活跃专题默认每 6 小时检查。创建/刷新只保存持久请求，队列故障不丢请求。
6. 查询/导出是只读；Word 使用已有本地渲染器，PDF 需要现有本地转换服务。配置按既有 `docker-compose.document-renderer.yml`，不可用时明确失败，不影响案件保存。
7. 副本验收登录、案件保存/导入、核心地图/报告以及创建专题→自动生成→历史修订→Word/PDF。自然语言入口仍沿用已有模型配置与出域限制，不能用公网模型接收原始案情。

## 停用与回退

- 暂停某专题会使其未完成任务失效，保留历史成果；恢复后只处理持久请求。不需要关闭整个 Agent 系统，也不删除原始资料。
- 代码回退和数据恢复分开：先停止新版本写入、备份升级后的完整数据库和文件。将兼容 v5.2 的备份恢复到**另一个数据库**，旧代码只连接该兼容库；升级后的原库与备份受控保留。
- 禁止恢复旧备份覆盖升级后新增案件、事件或生产资料。新增原始数据须经受控导入、逐项核对后迁回；专题派生记录不冒充原始业务数据。
- 迁移脚本拒绝直接删除专题历史的 `downgrade`。真实合成演练已验证旧库独立恢复、新库全字段原始记录一致；演练备份不代替用户实际业务备份。
