# v6.2.0-stable：生产对象与可计算地图

日期：2026-09-27。范围以[未投产重构路线](../superpowers/specs/2026-09-27-predeployment-refactor-review.md)的 v6.2 为准。本说明为本地源码交付，不表示 GitHub 已发布、现用数据库已升级或目标服务器已部署。

## 本版可以怎样使用

1. **同一设施跨台账识别。** 保留现有设施稳定编号。相同来源的明确编号改名后仍指向同一对象；同名不同编号不自动合并。管理员可在设施档案核对目标、填写依据后绑定或撤销来源对应；原台账与决定历史保留。没有明确编号的资料标记待核，不凭名称猜身份。
2. **分别查看业务有效时间与系统收到时间。** 设施档案可选择“业务有效时点”和“系统已知截止”。迟到的更正不会改写当时已知结果；缺少有效期资料显示未知，不拿今天的属性填补过去。所有时间存 UTC，界面输入、显示北京时间。
3. **知道地图还缺哪些计算资料。** 辖区底座内的管理员清单按设施核对来源、坐标、入口、连接、通行许可、路网与地图版本。可直接打开原资料维护入口，不另建一张地图。资料就绪不等于存在实际路径；本页不调用路由引擎，不把直线距离当道路距离。
4. **从设施查看有材料依据的案件关系。** 在原“有明确记录的案件关联”中按需登记，选择案件和已有出处，明确是提及、案发地点或查获地点。与邻近、系统候选分栏；原文更新或材料不可用会提示重新核对。可撤销，历史依据仍保留，不自动形成正式串并案或实际盗取来源结论。
5. **跳转不丢时点与来源线索。** 沿用共享区域上下文，传递设施、案件、统计窗口、资料时点及原成果引用；网址参数不授予权限，当前账号、辖区与道路许可仍由后端分别核验。

v6.1 同时补齐未知时间关联读取，以及设施历史对照中地点、测量、来源明细的变化识别。案件录入主流程不增加必需操作；普通读取不生成修订、不触发分析。

## 数据与接口

迁移链：`v61s01 → v62i01 → v62f01`。

- `FacilitySourceIdentity` 与追加式 `FacilityIdentityDecision`：来源编号、原设施、明确绑定与撤销。
- `JurisdictionAssetVersion`：原始有效期、系统获知时间、来源身份和决定引用；旧历史仅标记 `observed_only`，不伪造生效日期。
- `CaseFacilityAssociation`：案件、设施、来源修订、出处、登记人和撤销记录。只记录材料关系，不改案件原始事实。
- 现有地图声明保留来源身份；设施、地图快照、道路仍是不同对象，不另建资产主库，不换路由引擎。

主要接口（均在 `/api/facility-analysis`）：

| 接口 | 用途 |
| --- | --- |
| `GET /assets/{id}?valid_at=…&known_at=…` | 档案、来源身份、双时间资料和计算准备 |
| `GET /readiness` | 管理员按辖区分页查看计算资料缺口 |
| `GET /identities?source_id=…` | 管理员查询指定来源的身份对应 |
| `POST /identities/{id}/bind`、`/revoke` | 明确绑定或撤销，依据、幂等键与前一决定版本必需 |
| `GET/POST /assets/{id}/case-links` | 读取/登记材料关联 |
| `POST /case-links/{id}/revoke` | 撤销人工材料关联，保留记录 |

原始来源尚无决定时 `previous_decision_id` 为 null；后续操作须匹配实际前一决定。撤销后再导入进入隔离，不自动恢复旧绑定。身份决定与台账导入使用统一区域锁顺序。

已撤销、过期或未来生效的来源不能靠旧地图快照继续作为新分析的已核验候选。计算发布前重新检查来源；历史冻结成果保持原样。历史资料查看只覆盖已登记版本，不表示能够还原案发时道路实际通行。

## 初始化、升级与回退

新环境继续使用 `backend/init_fresh_db.py --database-url <明确目标> --confirm-empty-target`，非空目标拒绝运行；不会自动选用现用库或清空数据。初始化到权威迁移头 `v62f01`。

保留资料的测试环境：

1. 保存 v6.1 程序包，备份数据库、地图文件、配置与其他持久化文件并确认可恢复。
2. 暂停业务写入和消费者，先在隔离副本执行 `alembic upgrade head`，核验迁移头 `v62f01`。
3. 同步更新后端、前端和 Worker，再核验案件保存、设施档案、来源绑定/撤销和地图读取。
4. 不自动回填未知的历史有效期、不迁移旧原文为猜测事实；从真实下一次导入/人工维护开始建立可靠版本。

迁移拒绝破坏性降级。需要回退时将 v6.1 兼容备份恢复到独立库，完整保留 v6.2 库及新增案件、原件、生产资料、身份决定和人工关联。不能用旧程序直接写新库，也不能覆盖升级后的原始资料。
