# AiCommander v2.9.0-stable 发布说明

发布日期：2026-09-08

## 发布定位

`v2.9.0-stable` 把系统从“给出下一步”推进到“看清下一步依据”。新增单案证据走廊，把案件原始记录、
材料元数据、链条背景、重点井空间参考、Agent 派生成果和人工复核知识资产组织成可追溯路径；断开的
引用不会被隐藏，空间接近和未确认推断不会被包装成事实。

## 核心变化

- 新增只读 `GET /api/graphs/evidence/{case_id}`，支持限定井点半径和上下文数量。
- 新增案件主体、原始来源、双域背景、派生分析、复核成果、断链缺口六层证据走廊。
- 新增稳定来源摘要；相同数据和查询范围重复读取时 `data_version` 一致，来源变化后自动变化。
- 新增断链复核队列，覆盖缺字段、缺坐标、失效知识引用、失效 Agent 引用、未确认链条和未核验井点。
- 同一井点的空间邻近路径和 Agent 来源引用合并为统一节点，避免重复呈现。
- 材料统一使用内部编号展示；自由文本按本案登记身份标识以及手机号、证件号、车牌格式再次脱敏。
- 图谱不返回材料正文、文件路径、人员/车辆身份字段或精确井点坐标；Agent 成果不返回提示词和正文。
- 前端新增图谱状态、可追溯率、分层开关、节点/连线检查器、断链定位、证据摘要导出和工作台入口。
- 新增专项运行手册和 `scripts/verify-evidence-graph.sh`，并把脚本语法检查纳入 GitHub 质量门禁。
- 更新 v2.9—v3.0 路线：下一阶段建设可重放证据孪生和只提出问题、不自动下结论的质疑智能体。

## 验证结果

- 后端：303 项测试通过，其中证据图谱专项 7 项、链条回归 4 项通过。
- 前端：24 个测试文件、104 项测试通过，其中证据图谱呈现专项 4 项通过。
- TypeScript 类型检查和 Vite 生产构建通过；仅保留既有的大分块体积提示。
- Python 生产 `requirements.txt` 重新解析审计、前端生产依赖离线审计均未发现已知漏洞。
- SQLite 与 PostgreSQL 全新数据库均迁移到 `a7d9e1f2b304`；v2.9 没有新增表或改变原表含义。
- 真实浏览器验证案件导航、工作台入口、六层图谱、断链队列、版本信息和图谱 GET 请求均正常。
- 脱敏响应核验未发现材料路径/正文、人员姓名、电话、证件号、车牌或精确井点坐标。
- 隔离生产五服务健康，Agent 保持关闭；自动冒烟、内部端口限制、PostgreSQL 备份及 43 表恢复通过。

## 不依赖外部模型

证据图谱由内网数据库查询、确定性空间计算和引用校验生成，不需要 OpenAI、DeepSeek 或其他模型 API。
已有 Agent Lab 和外部模型仍默认关闭；图谱失败不会影响案件、地图、报告、知识资产和今日工作台。

## 未替代的现场验收

本发布说明确认源码、本机测试、真实浏览器脱敏样例和隔离容器演练结果，不代表目标服务器已部署或系统
已正式投产。目标服务器仍需完成数据库备份与迁移、单位网络与 HTTPS、权限抽查和核心业务回归；指定
业务人员还需用真实脱敏案件核对证据路径、空间参考表达和断链建议，并形成签字记录。

## 升级与回滚

升级前先备份 PostgreSQL，部署时仍执行 `alembic upgrade head`。本版本没有新迁移，最终版本仍为
`a7d9e1f2b304`。证据图谱没有写入端点；回滚到 `v2.8.0-stable` 不需要清理正式案件、井点、链条、
Agent 或知识资产数据。
