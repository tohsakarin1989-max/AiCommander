## 交付内容

- 同一来源复用已保存模板，支持工作表、表头及完整生产字段说明，结构或单位变化先提示。
- 写入前查看“新增、更新、未变、待对应、冲突、失败”和旧新差异；执行时重新核验，避免旧预览覆盖新资料。
- 坐标及坐标系、含水率及口径、产量及单位/周期按完整字段组处理，保留来源和有效期，不拼接不相容字段。
- 最近批次可找回，异常行追加修订，成功行不用重新导入。同值接收不重复增加设施业务版本。
- 台账原件、工作表、行列和模板快照可追溯；整份原件仅地图管理员可下载。历史未记录的信息不伪造补齐。
- 有写入权限的员工可就设施来源标注资料问题，不直接改写正式设施，不创建执行任务。
- 地图分片继续上传、验包状态和失败原因接入现有页面；失败不替换现用地图。
- 案件地点、油量等明细保留稳定身份，来源修订与未来内容复用摘要分开；本版未据此声称已完成模型结果复用。

操作说明见[台账整理简明指引](../map-ledger-quickstart.zh-CN.md)。已有案件、地图、设施身份核对和历史材料保留，不新增通用数据治理平台或每行审批流程。

## 迁移与权限

本工作包迁移节点为 `v72m01`，前驱 `v71d01`，扩展现有模板、批次、声明，新增字段组采用记录；最终 v7.5 迁移头以统一发布说明为准。SQLite 的十张明细/来源表启用防 ID 重用，保留记录、外键与原件；PostgreSQL 沿用序列。历史缺失的身份不能由迁移补造。

台账来源、原件、混合字段组及问题标注读取均核验当前权限；来源停用或移出当前范围后不保留摘要和数量泄漏。台账导入权限没有因此下放给普通只读账号。

## 升级和回退

1. 先保存相容应用、数据库、原件、地图与配置恢复点；在隔离副本升级，不覆盖现用数据库。
2. 升级时 API、Worker、Beat 和前端使用同一工作包。没有新引入地图源、路由引擎或大型依赖，不重复下载制图。
3. 核对既有案件、设施和原件仍可读，再用合成台账检查首次导入、变化、原样重传与异常续做。
4. 已有新字段组采用记录或新格式批次时，迁移拒绝直接降级删列。需要恢复旧版时，保全升级后新增案件、台账原件、修订和人工说明，恢复至独立相容库再验证切换；不要删除记录绕过保护。

SQLite 批量改表使用迁移连接暂时切换外键执行，并在前后核对全部外键；应用连接继续开启外键。该机制不是业务运行时关闭约束，失败时应停止迁移并使用已核对的恢复副本。
