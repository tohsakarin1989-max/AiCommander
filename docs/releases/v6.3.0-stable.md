# v6.3.0-stable：案件过程、片段检索与候选条件

日期：2026-09-27。范围为[未投产重构路线](../superpowers/specs/2026-09-27-predeployment-refactor-review.md)的 R07—R09。**本地源码已收口为 `6.3.0-stable`，版本配置、README、部署默认值及前端标识已同步。** 不是 GitHub 发布或目标服务器部署声明。

## 用户能直接使用什么

1. **案件过程有出处。** 在案件详情“过程与关联”中查看有原文依据的动作、时间表达、涉及对象、明确的来源/去向表述、油品数量和有限先后关系。每个片段关联来源修订与字符位置；结构化地点和测量属于案件背景，没有依据不自动挂到某个环节。肯定、否定、不确定及冲突分开，缺项不新增必填操作。
2. **历史参考命中具体片段。** 后台为关键表述、过程片段、已确认经验建立可重建索引。结构条件、词项、本地语义各自召回后融合；长案情不只展示开头。页面、助手和查询材料共用实际命中原文与版本。没有索引、索引过期、达到预算、模型未启用分别说明，少量历史参考不冒充全库统计。
3. **设施候选能说明理由。** 精选仍最多三项，但全部召回设施保存“当前计算条件排除、明确不符、资料未知、条件支持”。说明可信入口、通行约束、案发时有效生产资料及历史条件；没有过去资料不拿当前台账补齐。未取得道路路径属于未知，不等于现实不可达。
4. **补充资料的作用可解释。** 列出最多三类关键依赖，说明哪些设施判断受入口、车辆或测量资料影响，不自动新增待办。与前一份可比冻结成果比较条件、出处及名次；同时变化的案情、算法或路网单独列明，不承诺准确概率或单因素因果。
5. **页面与材料共用同版依据。** 过程、全池条件及变化随原有成果冻结并用于 Word/PDF 内容投影，不在查看或导出时重跑分析。来源内容改动再改回，也按实际修订区分；旧结果保留但不冒充最新。

本版没有新增 Agent、知识库操作页或审批链；没有自动确认盗取来源、囤储点、住址、实际轨迹及正式案件关系。附近村屯或道路不自动成为转移端点。

## 数据与运行

- 新迁移：`v62f01 → v63h01`。仅新增派生片段及结构/词项索引，复用 pgvector，不改变原始案件表语义。
- 画像结构 `6.3.0`，过程 `case-process-6.3-1`；老画像和无过程的冻结成果继续可读，不补造旧来源版本。
- 历史查询 `case-history-6.3-fragments-1`，保留父来源身份与旧链接，新增命中片段、三路名次、索引覆盖和实际候选复核量。
- 条件对照 `facility-conditions-6.3-1`，旧道路附件外壳继续读取。v5.2 评分器保留用于原冻结评测重放，当前计算使用 v6.3。
- 普通 Worker/Beat 消费来源变更和轮询建立索引，不要求开启 Agent Lab；保存事务不等待嵌入、模型或道路计算。经验撤销即时失效，查询及历史读取重新核验当前权限与来源。
- 本地语义模型未配置时，只提供结构条件和词项检索；规则过程不等于完整语言理解。合成向量和当前聊天模型均不计作系统真实模型验收。

## 升级与回退

1. 保存 v6.2 程序、数据库、原件、生产资料和地图备份；先在隔离副本演练，不清空现用库。
2. 停止旧应用写入及消费者，执行 `alembic upgrade head`，确认单一头 `v63h01`。后端、前端、Worker 与 Beat 必须同步更新。
3. 恢复普通后台消费者。画像按新规则版本重建，片段按来源版本增量生成；初始无索引应显示待建，不把历史资料当作不存在。管理员可使用既有回填/失败重试入口，一线用户无需逐案启动。
4. 核对保存、过程出处、历史参考、撤权、设施条件、同版材料和地图读取。地图包、路由引擎及模型包本版不重新下载或替换。
5. 回退优先将 v6.2 兼容备份恢复到独立库，完整保留 v6.3 库及之后新增原始案件、原件、生产资料和人工决定。`v63h01` 的降级只删除可重建片段/倒排索引，不删除原始事实；必须停止新应用并核定其他派生数据/应用兼容性，不能把单步降级当完整应用恢复。
