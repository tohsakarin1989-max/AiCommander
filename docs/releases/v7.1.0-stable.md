状态更新：2026-10-08。用户已明确“接受例外并发布”，本工作包随 [v7.5.0-stable](v7.5.0-stable.md) 统一交付，不代表曾单独建立 v7.1 标签或发布。本次仅接受严格编辑 P95 25.107→27.165 毫秒（+8.20%，+2.058 毫秒）的单版例外；原定 5% 门槛及失败证据保留，不改称性能通过。远端发布状态以 GitHub Release 为准，源码交付不等于现场部署。

本工作包对应 [7.x 路线图](../superpowers/specs/2026-09-30-v7x-upgrade-roadmap.md) A02—A06，不包含后续台账整理、历史条件和材料深化的全部内容。以下保留 2026-10-05 的实现和验证记录。

## 员工可用变化

1. 常用案件字段优先，补充字段按需展开。已有涉油数量、人员、车辆、处置及其他独有字段保留；未知时间、模糊区间和未定位地点不靠猜测补全。
2. 可显式保存本人私有草稿，重新登录后继续填写。草稿不是案件，不进入统计、画像、普通目录或后台分析；敏感正文不默认写入浏览器永久存储。默认保留 7 天，单位可配置 1—90 天。
3. 新录入界面使用固定提交凭证，失败保留输入，结果不明时核对原请求；草稿转正式与来源、事件及回执同事务。另一个页面提交不同内容不能被当成本页成功。只确认请求不产生新案件。
4. 编辑时记录打开表单的来源版本；同事已修改时展示差异，保留本页输入，由员工比较后决定。不再静默覆盖；旧无版本客户端继续兼容，不声称所有旧调用都具备此保护。
5. 选择授权设施可复用已有名称和可靠位置信息，需用户明确确认；同名设施仍按编号区分，不自动填写案发时间、油量或人员。公共参考点不冒充核验井位。
6. 最近导入批次可找回失败行继续修正，复用已有工作表、字段映射及北京时间模板。成功行不因续做而重复建案；没有测量逐行重复数量时显示未知，而非虚构“重复 0 行”。
7. 文字辅助显示原文引用和定位状态，否定、不确定与矛盾不转成肯定事实。规则辅助与实际内网模型分别标注；提取值仍须人工核对。

这些是源码功能变化，不是“员工已节省多少分钟”的实测结论。真实任务的操作时间、求助与返工仍待观察，不以自动生成数量代替使用价值。

## 旧功能承接

| 原入口或结果 | 本版承接 | 保留边界 |
| --- | --- | --- |
| 单案/批量预处理、批量复核、旧后台任务名称 | 同一案件源修订 → 持久事件 → 标准画像 | 管理员维护权限不扩大，原文和人工标签不覆盖 |
| 原有自由摘要、推断与建议 | 可选的内网模型版本化补充 | 与规则画像分层；无可信模型明确未启用，不冒充已具备模型效果 |
| `Case.features`、历史任务与已确认经验 | 维护页历史区、原有历史读取 | 不批量删除，不用旧无版本 JSON 冒充当前画像 |
| 原预处理批量脚本 | 可续跑的现有事件补齐入口 | 不直接更新 SQLite JSON，不再产生另一套当前结果 |
| 案件、地图、大屏、专题、会议和材料 | 保留原业务路径及权限 | 读取不发起新分析，未出报告不等于案件未完成 |

消费者及验证详情见 [预处理收敛记录](../validation/2026-10-05-v71-preprocess-unification.md)。模型调用完成后重新核验账号、辖区、原始修订和配置，迟到或撤权后的结果不发布；模型故障不否定已完成的规则画像。

## 新接口与迁移

- `/api/case-drafts`：本人私有草稿列表及保存、读取、删除、提交。当前账号角色、写入范围和到期时间共同控制访问。`POST /{id}/submit` 的 `confirm_only=true` 只确认同一请求已完成，不消费仍活跃的草稿。
- `/api/cases/{id}/edit-snapshot`：一致的编辑快照及严格版本比较保存。冲突返回 409，不能靠忽略令牌静默覆盖。
- `GET /api/case-imports/batches`：当前权限内先过滤再分页，返回处理统计和是否可以续做，不暴露原始行内容。
- 当前及历史预处理读取增加新鲜度、来源修订和模型补充状态，原画像读取结构兼容保留。
- 本工作包迁移节点 `v71d01`，前驱 `v70s01`；最终 v7.5 迁移头以统一发布说明为准。只新增 `case_drafts`、`case_preprocess_supplements` 及其约束/索引，不改写正式案件数据。

## 升级、运维与回退

1. 先保留 v7.0 相容应用、数据库、原件、地图及配置恢复点；既有工作区修改另行保全。按[当前主手册](../current-intranet-operations.zh-CN.md)在停止写入后捕获一致备份。
2. 在隔离副本迁移 `v70s01 → v71d01`，检查原始案件仍在；正式切换时 API、Worker、Beat、前端必须同版。内网仍使用批准的预构建镜像，不临时下载依赖。
3. `CASE_DRAFT_RETENTION_DAYS` 默认 7、允许 1—90。到期立即禁止恢复，Beat 每小时调度物理清理；后台停机时清理延后但不会恢复访问。数据库备份里的草稿按独立保管制度处理，不能声称清理任务同步销毁备份。
4. 路由引擎、地图来源和离线资源没有变化，复用有效证据。更换应用层仍须核对当前源码版本及迁移头；旧应用镜像不能冒充新版镜像。
5. 草稿或补充表非空时，迁移主动拒绝直接降级删除。需回 v7.0 时保全升级后的新增案件、原件、草稿和人工记录，在新库恢复相容备份并验证后切换；不删除草稿或新案件绕过保护，不让旧应用直接使用不相容新库。
