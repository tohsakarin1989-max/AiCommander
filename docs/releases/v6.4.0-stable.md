# v6.4：持续问题与业务助手

日期：2026-09-30。实施范围为当前未投产重构路线的 R11—R12 及 R08 全量统计续跑。本地里程碑随 v6.5 统一交付，不单独创建远端 Release；最终状态以 v6.5 验证记录和实际发布为准。

## 日常业务变化

- 助手增加六个可直接执行的业务预设：范围统计、案件过程、已有成果解释、设施档案、历史有效生产资料、登记资源覆盖情景比较。不要求先配置模型，不把预设称为模型自主推理。
- 回答从实际工具返回值组织数字、证据、信息缺口和边界；工具轨迹、取消、预算和实际计量保留。自然语言规划只有可信内网模型接通后才启用，不使用当前聊天模型冒充系统模型。
- 可从案件、设施和查询保存持续问题；支持固定和滚动时间窗、不可变条件版本及历史成果。设施专题统计只使用有效明确关联，不把附近案件或撤销关联当作已关联案件。
- 长统计分块保存进度，后台可续跑；数据、定义或权限变化会使旧工作片失效，不混用多版输入。部分结果不声称完整统计。
- 工作台只显示最多三项实质变化。范围变化和同案资料补齐分开，不把后台重试、时钟变化或移走未知样本当作资料改善。

## 运行与兼容

新迁移 `v63h01 → v64t01`：专题条件版本、实际依赖、全局来源修订和工作片。复用已有任务、事件和成果表，不另建业务 Agent 网络。

普通 Worker/Beat 每 15 秒推进专题；与 Agent Lab 无关。新查询由 `ENABLE_INTELLIGENT_QUERY` 管理，并使用既有专用队列。所有进程必须更新至同一源码和迁移版本。查询和专题接口读取不启动新业务分析。

PostgreSQL 使用写入前的共享事务锁与来源序列、短时间独占发布校验；来源写入之间不因全局版本行串行争锁。SQLite 保留其单写者机制，仅为本地测试回退。依赖不明确时保守重算，不宣称精准增量。

来源校验、授权、工具声明、截止时间、重试/取消和计量共用运行契约，但不把所有业务 Worker 强行合成一个状态机，也不扩大实验工具权限。SQL 中断已在 SQLite 和真实 PostgreSQL 验证；模型及本地推理的现场时延另行确认。

## 迁移与回退

1. 保留 v6.3 应用、数据库、原件、生产资料、地图及模型包的相容备份，先使用隔离副本演练。
2. 暂停旧写入和消费者，执行 `alembic upgrade head`；在最终 v6.5 交付包中头版本为 `v65r01`，会顺序经过 `v64t01`。
3. 重启后端、普通/专用 Worker 与 Beat，核对保存、专题接单/续跑、撤权、固定版本读取。
4. `v64t01` 不允许自动破坏性降级：条件和人工备注属于用户资料。回退时保全升级后的完整库，在独立库恢复相容备份，单独核对升级后新增原始资料后再切换。
