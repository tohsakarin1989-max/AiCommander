## 日常业务变化

- 当前案件与历史案件可对照具体环节、相似条件、差异和适用限制，每一侧均保留原文位置及版本。否定、不确定和反向条件不转为肯定事实。
- 关键补充最多三项，说明资料缺口影响哪些候选；没有计算依据时不虚构收益，不增加案件保存必填项。
- 原文相同可复用既有向量，但新修订的来源身份和引用仍独立。一个案件索引失败不会阻断后续案件，连续失败保留可恢复记录。
- 道路分析分为扫描、入口核验和道路批次，已完成部分持久保留；预算用尽等待下一片，不误报失败。权限、来源、图网或有效期变化时停止旧续跑，建立新版本任务。
- 页面展示实际处理数量，不伪造完成百分比或全域最优。依赖目前采用授权范围保守重核，包含未入选及新增设施、新路网；不称精准空间增量。
- 管理员可查看派生任务积压和明确失败，并按原授权重试；同一请求不重复排队。普通员工无需管理后台任务。

## 升级与回退

从上一公开版完整迁移：`v65r01 → v70s01 → v71d01 → v72m01 → v74n01 → v74c01 → v75h01 → v75r01`。涉及提交回执、私有草稿/预处理补充、台账计划与字段来源、专题通知、材料目录投影、向量复用及明确重试唯一索引；保留原始案件、原件和历史人工判断。

先按[当前内网主手册](../current-intranet-operations.zh-CN.md)停写并保全数据库、原件、地图、密钥及相容镜像，再在隔离目标核对迁移与恢复。应用、普通 Worker、道路 Worker、Beat、前端同时使用相容版本；重启 Beat 加载新增的每分钟依赖巡检。生产镜像须固定 PostgreSQL 16/PostGIS/pgvector，示例清单占位值不能当作已交付资源。

`CASE_DRAFT_RETENTION_DAYS` 默认 7、允许 1—90；过期草稿立即不可读，后台清理不等于备份清理。关闭智能能力仍保留核心业务；管理员恢复入口不启动未授权的模型或道路能力。完整中文导出须配套本版本渲染器、字体及离线依赖。

不新增地图/路由引擎/模型下载，不改变原始案件事实。保留旧设施作业读取；缺少新冻结依赖的旧任务停止旧格式续算，交由当前委托巡检建立新版本任务，不把格式差异当成无限普通失败。

向量复用表可重建；人工重试回执不可清空来绕过降级保护。已有回执时数据库拒绝移除唯一性约束。回退恢复到独立相容库，保护升级后新增案件、资料和人工判断，不让旧代码直连不相容新库。
