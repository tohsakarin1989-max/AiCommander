# AiCommander v2.0.3-stable 发布说明

## 定位

本版本是面向前期测试部署的当前稳定代码基线，替代 `v2.0.2-stable`。Agent Lab 继续
默认关闭，不参与核心系统就绪判定，也不会修改正式案件、井位和研判结论。

## 补丁修复

- 会话令牌只接受规范 Base64URL 编码，拒绝文本不同但可解码为同一签名字节的非规范表示。
- 将会话令牌篡改测试改为确定性修改有效签名字节，并增加非规范编码回归用例。
- 消除约 1/16 概率触发的安全测试随机失败，避免发布门禁因随机令牌末位而波动。

## 稳定能力

- 案件录入、导入、保存前预检、批量复核、待办分流和报告主流程。
- 真实案件、事件、重点井与高关注井地图展示，以及链条和时空研判能力。
- 管理员、分析员、只读账号三级权限，会话保护、登录锁定和写操作审计。
- PostgreSQL 16、Redis 7、后端、Celery、前端五服务生产编排。
- 数据库增量迁移、升级前备份、非破坏性恢复核验、健康检查和回滚手册。
- 独立 Agent Runtime、轨迹、成果物和审批底座；发布态全部关闭。

## 发布门槛

- 后端：222 项测试通过；会话令牌专项测试连续重复 50 轮通过。
- 前端：18 个测试文件、78 项测试通过；TypeScript 类型检查和生产构建通过。
- 生产 Compose 和全部部署脚本静态检查通过。
- 隔离五服务部署、Agent 关闭态、接口冒烟、数据库迁移、备份和恢复演练通过。

可重复执行完整隔离演练：

```bash
sh ./scripts/rehearse-release.sh
```

## 现场验收边界

`stable` 表示代码与部署链路达到受控测试部署门槛，不等同于正式投产验收。目标服务器
网络与 HTTPS、现场备份证据、指定用户试用、业务耗时和问题率基线仍须在部署后记录。
首次部署必须保持：

```dotenv
ENABLE_AGENT_LAB=false
AGENT_MODE=off
AGENT_MUTATIONS_ENABLED=false
```
