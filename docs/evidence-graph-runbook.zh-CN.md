# 单案证据关系图谱运行与验收手册

> 适用版本：AICommander `v2.9.0-stable`
> 功能定位：只读组织证据路径、发现断链，不代替案卷核验和人工结论。

## 1. 日常使用流程

1. 从“今日研判工作台”的案件任务点击“查看本案证据图谱”，或在案件导航进入“证据图谱”。
2. 选择单起案件和井点参考半径。系统只读取该案件及限定范围内的已有数据。
3. 先看“图谱状态”和“可追溯率”，再沿案件主体、原始来源、双域背景、派生分析、复核成果、断链缺口逐层查看。
4. 点击节点查看来源编号和安全摘要；点击连线查看关系口径、置信度和证据引用。
5. 按“断链复核队列”返回原业务页面补资料或复核。图谱本身不提供修改、确认、删除或自动补证入口。

## 2. 状态口径

| 状态 | 含义 | 使用要求 |
| --- | --- | --- |
| 原始记录 / 已核验来源 | 来自现有案件字段、材料元数据或已核验地图对象 | 仍应以原始业务材料为准 |
| 人工确认 | 现有业务流程中已确认的链条或知识资产 | 可作为已复核成果展示 |
| 待人工确认 / 待人工复核 | 未确认链条、知识草稿或 Agent 派生分析 | 不得表述为事实 |
| 仅作参考 | 案件与井点的限定半径空间接近 | 不能证明案件与井点存在事实关联 |
| 证据缺口 | 核心字段、坐标或引用缺失 | 进入人工复核队列 |
| 降级结果 | Agent 在模型故障等条件下形成的保底成果 | 必须结合轨迹和来源复核 |

## 3. 数据和安全边界

- 接口为 `GET /api/graphs/evidence/{case_id}`，没有配套写入接口。
- 默认井点参考半径 5 公里，可选范围 0.5—20 公里；空间关系只返回距离区间所需结果，不返回精确井点坐标。
- 只展示案件材料的标题、类型、采集时间和敏感标记，不读取或返回材料正文和文件路径。
- 人员和车辆身份字段只用于遮蔽自由文本中的误填标识，不作为图谱节点或详情返回；手机号、证件号和车牌另有通用格式脱敏兜底。
- Agent 成果只展示类型、运行编号、版本、状态和来源签名，不返回成果正文、提示词或模型响应。
- 相同来源数据和查询范围应生成相同 `data_version`；`generated_at` 仅表示本次读取时间。
- 图谱不可用时不影响案件、地图、报告、知识资产、今日工作台和 Agent 核心流程。

## 4. 断链复核规则

- 案件发生时间、类型、地点或坐标缺失：标记关键缺口。
- 设施类型或作案手法缺失：标记一般复核项。
- 知识资产或 Agent 成果任一来源编号无法解析：单独生成失效引用缺口。
- 已确认知识资产没有任何可解析来源：标记关键断链，暂停作为完整证据路径使用。
- 未确认链条关系：保留为假设并进入复核队列。
- 未核验井点：只作为低置信空间参考并进入复核队列。

## 5. 发布前专项验收

在仓库根目录执行：

```bash
chmod 0755 scripts/verify-evidence-graph.sh
./scripts/verify-evidence-graph.sh
```

脚本检查后端图谱与链条边界、版本契约、全新 SQLite 迁移、前端分层规则、类型检查、生产构建和生产编排。
完整稳定版还需执行全量测试、生产依赖审计、PostgreSQL 迁移和隔离生产演练。

## 6. 测试部署现场验收

- 选择至少 5 起有材料、有坐标、有知识资产的脱敏案件，逐项核对来源路径。
- 选择至少 2 起缺坐标或含失效引用的案件，确认断链队列能明确指出问题且不自动修改数据。
- 对同一案件连续读取两次，确认数据版本一致；修改测试数据后版本必须变化。
- 临时停止图谱接口或模拟读取失败，确认案件录入、地图、报告和工作台继续可用。
- 由业务人员签字确认空间参考、推断和人工结论在视觉和文案上没有混淆。

本手册和自动化结果只能证明代码级与隔离环境就绪，不能替代目标服务器部署、真实数据核验和业务签字。
