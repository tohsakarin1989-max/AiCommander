# v5.1 本地历史检索：离线部署候选说明

本说明是开发候选能力的配置与恢复路径，不是 Stable 发布或现场模型验收报告。未配置模型时继续使用结构条件和中文词项检索；案件保存不等待嵌入。

## 数据库先决条件

迁移 `d72e31b86fa2` 接在 `c61d20a75e91` 后，增加派生向量表。PostgreSQL 必须同时具备 PostGIS 与 pgvector；SQLite 的 JSON 向量只用于本地测试。旧的纯 PostGIS 镜像不能直接运行新迁移。

`scripts/Dockerfile.postgis-vector` 提供镜像构建入口，固定 pgvector 基础镜像摘要；PostGIS 系统包在构建时解析，交付前还需冻结最终镜像摘要和包清单。v5.2 已移除不含 vector 的旧镜像默认值，`POSTGIS_IMAGE` 必须显式配置为受控导入镜像的 `repository@sha256:<摘要>` 或本机 `sha256:<image ID>`，不能只写可变标签。

在联网制包区按目标服务器架构构建镜像、记录包清单，用 `docker image inspect` 记录不可变镜像 ID，导出镜像包并记录包 SHA-256。受控导入内网后核对摘要，再将实际 ID 填入配置。当前本机已验证的镜像 ID 为 `sha256:52a58988963cd4d838f4bb62ca111aa9525a63a7563970bca1f657ec1bc2cbfa`（arm64），不适用于未经验证的其他架构，也不冒充公共镜像仓库地址。

部署预检通过 `scripts/check-postgres-image.sh` 在无网络、无业务卷、只读临时容器中核对 PostGIS 与 vector 扩展文件。缺镜像或任一扩展即停止，且不会下载。扩展文件检查不代替真实数据库迁移；迁移和另库恢复证据见 v5.2 收口记录。旧环境升级应恢复到新数据库卷，不将 Alpine 原卷直接交给 Debian 镜像。

升级时先备份旧库，在新镜像的独立数据库中恢复并迁移，再验证案件、地图和检索。不要把 Alpine 数据卷直接挂到 Debian 候选镜像冒充升级成功。停写切换与迁移后新增业务数据的保护沿用部署手册。

## 模型包与运行依赖

模型来源、许可、精确版本和维度须明确。管理员先在允许联网的构建环境准备模型文件，使用 `scripts/package-local-embedding.py` 制包，参数包含 `--source`、`--output`（绝对路径）、`--model-id`、`--source-revision`、`--license-record`、`--dimension`。工具不联网、不修改源目录、不覆盖已有输出。

只接受白名单结构的 SentenceTransformer 模型及 safetensors 权重，拒绝软链接、远程自定义代码和 pickle 权重。制包返回清单 SHA-256；这证明包结构与文件一致，**不证明模型推理或中文业务效果通过**。输出维度由实际模型装载再次核验，不由 hidden size 猜测。

可选依赖为 `backend/requirements-embedding.txt`。后端镜像构建参数 `INSTALL_LOCAL_EMBEDDING=true` 才安装它，默认仍为 false。模型文件不打入源代码，也不在请求时下载。构建后的镜像、模型包及其清单一并经受控路径导入内网；联网构建区不接触案件、生产坐标和内部资料。

`docker-compose.local-embedding.yml` 是可选叠加配置，供后端 API、普通后台任务及智能查询 Worker 使用同一模型版本：

- `LOCAL_EMBEDDING_HOST_DIR`：批准的绝对模型目录，UID 10001 可读；只读挂载，缺目录时不自动创建。
- `LOCAL_EMBEDDING_MANIFEST_SHA256`：受控交换时核定的清单摘要，不接受启动时自动信任目录内容。
- `APP_VERSION`：明确候选镜像版本；不要用旧 Stable 标签覆盖新代码。

在原生产 Compose 后追加该配置；若还启用 Word/PDF 渲染配置，应让本配置排在最后，保留 document-renderer 构建目标并使用统一带嵌入依赖的镜像。只检查合并配置不会启动或替换服务。模型配置不改变旧 `ENABLE_VECTOR_DB=false`，新检索不使用旧 Chroma 内容。

旧 `VectorDBService` 已改为同一数据库索引的只读兼容层，不再初始化 Chroma。旧直接增删改方法不执行写入；后台重建从业务源生成当前索引。旧 `ENABLE_VECTOR_DB` 只保留给旧结论生成的可选相似证据分支，不再控制案件保存后的索引或触发模型同步计算。旧 Chroma 目录暂保留作为历史文件，不自动清理。

## 运行与真实性边界

- 文件校验失败、模型未安装或维度不匹配：返回 `unavailable`，继续词项查询。
- 没有配置：返回 `not_enabled`，不尝试导入模型或联网。
- 当前来源还没有对应模型版本的向量：返回 `partial` 和实际完成范围，不能据此断言没有相关案件。
- 向量只在当前授权、当前来源摘要、当前模型版本及同维度集合内做精确余弦计算。名次融合不是概率；否定信息不因语义接近变成肯定事实。
- 长文本分片后聚合，超过明确预算时报错，不悄悄截断。规则画像仍是确定性兜底，不把嵌入检索等同深层案件理解。
- 案件保存复用同事务的画像 Outbox，标记检索待更新；后台每批优先处理这些案件，再继续全库游标扫描。索引确认与派生写入同事务，失败回滚不丢事件；不改变画像任务的状态。没有新案件事件的历史资料、经验变化及模型换版由轮询兜底，延迟取决于完整周期。读接口仍核对最新来源。

正式启用前需用实际模型完成断公网装载、中文同义与否定、完整长文本、资源占用及业务页面查询验收。模拟模型与人工向量只能验证接口和数据库计算，不代替这些步骤。

## 停用与回退

先停相关后台进程，撤销可选模型配置并重启对应服务；词项查询继续可用，原始案件不改变。模型版本变化后重新构建派生向量，不覆盖历史业务事实。

仅回退 `d72e31b86fa2` 会删除可重建向量表，保留词项索引、原始案件和共享扩展；需先停新版本读写路径，不能让仍运行的新代码访问已删表。整个应用回退必须使用相容数据库或备份恢复方案，不能用单表回退替代全版本恢复。

参考：本地模型参数依据 [SentenceTransformer 官方接口](https://www.sbert.net/docs/package_reference/sentence_transformer/model.html)，向量类型与精确距离依据 [pgvector Python 官方实现](https://github.com/pgvector/pgvector-python)。固定依赖与真实运行是否兼容仍以项目验证结果为准。
