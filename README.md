## 主要能力

- 案件录入、批量导入、保存前预检和信息质量检查
- 案件标签、相似条件、时空规律和区域画像
- 案件关系图谱、链条线索及人工确认
- 单案证据走廊、来源追溯、断链复核和重点井空间参考
- 相邻窗口增量研判、热点变化、重点井关注顺序和一页简报
- 多模型圆桌研判、结论复核和报告生成
- 待办中心、批量复核、版本化经验卡和历史优秀案例复用
- 今日研判工作台、唯一下一步分流、跨页任务续办和非敏感效率度量
- 井点、管线、技防设施等辖区业务底座
- 用户、角色、会话、审计和加密模型配置

## 技术栈

- 后端：Python 3.12、FastAPI、SQLAlchemy、Alembic、Celery
- 前端：React 18、TypeScript、Ant Design、ECharts、Vite 8
- 生产数据：PostgreSQL 16、Redis 7
- 生产入口：Nginx、Docker Engine、Docker Compose Plugin

## 本地开发


访问：

- 前端：<http://localhost:3000>


## 生产部署

当前源码版本为 **v5.2.0-stable**，范围为日常业务整合、统一历史检索、道路与生产条件融合研判。
升级必须使用同时具备 PostGIS 和 pgvector 的数据库镜像，不可直接沿用旧纯 PostGIS 默认镜像。
功能、验证边界、迁移和保护新增原始数据的回退步骤见 [v5.2 发布说明](docs/releases/v5.2.0-stable.md)。
源码版本不代表目标服务器已部署，真实内网模型未验证时仍显示未启用。

开发用 `docker-compose.yml` 包含源码挂载和热重载，不能用于服务器生产上线。生产部署使用：

```bash
sh ./scripts/init-production.sh
sudo sh ./scripts/deploy-production.sh
```

生产版本包含：

- 模型与系统密钥加密存储和掩码返回
- SQLite 到 PostgreSQL 的受控数据迁移脚本
- HTTPS 反向代理样例、部署预检、升级前自动备份、迁移版本健康检查
- 日志轮转和固定基础镜像 digest

## 可选 Agent Lab

“油盾·双域研判智能体”作为独立可选辅助层，默认关闭，不参与核心系统就绪判定。默认由内网规则引擎运行，
不需要模型密钥，也不会向外部发送数据。当前提供案件数据质检、
地图数据质检、双域融合研判、证据成果物、运行轨迹和管理员审批；Agent 不直接修改案件，地图候选也只有
在 `assist` 模式、写入开关和人工审批同时满足时才能通过现有业务服务执行。
v2.6 完整继承两个数据管家、双域融合研判和统一 Agent 运行中心：按近 30 天汇总任务完成率、
降级次数、总耗时/P95、模型耗时、Token 和估算成本，运行详情可回溯到单次模型计量记录。双域任务必须
同时明确选择案件和有效地图资源，单次默认最多 10 起案件、100 项资源；只生成案件—生产目标距离、
历史聚合热点、事实、推断、建议、信息缺口和证据索引，不预测犯罪、不自动确认串并案、不自动派发
巡逻，也不生成正式数据写入操作。系统默认仍不需要 OpenAI 或其他模型 API；经安全评审后可选择
OpenAI Agents 适配器，或复用系统模型注册表接入 OpenAI 兼容网关和 Anthropic，模型故障由内网规则接管。

## 报告与知识资产闭环

案件研判工作台可以把即时经验卡和研判报告保存为独立版本。经验卡必须人工确认后才能进入历史案例
推荐；系统按时间、空间环境、车辆工具、现场薄弱点和发现方式召回相似经验，并同时展示适用依据与
差异风险。研判人员明确标记“采纳”后，经验只会作为引用写入新的报告草稿，不复制旧案结论，也不
修改当前案件。每次采纳、排除和报告引用都保留可回溯记录。详细流程见
[知识资产运行手册](./docs/knowledge-asset-runbook.zh-CN.md)。

## 今日研判工作台

`v2.8` 新增“今日研判工作台”，按案件当前数据质量、经验卡和报告版本状态，为每起案件只生成一个
明确下一步。分析员可从工作台开始任务，跨页面继续处理并主动标记完成或放弃；管理员查看全组聚合，
分析员仅查看本人聚合，只读账号不采集工作会话。效率记录只包含任务类型、内部页面、开始/结束时间和
页面跳转次数，不保存案情正文、人员信息、井名、坐标或 URL 查询参数。工作台不可用时，案件、地图、
报告和 Agent 主流程仍可独立使用。操作与验收方法见
[今日研判工作台运行手册](./docs/workbench-runbook.zh-CN.md)。

## 单案证据关系图谱

`v2.9` 新增只读“证据走廊”，把案件原始字段、登记材料元数据、链条背景、重点井空间参考、Agent
成果和知识资产按层组织。未确认链条、空间接近、规则派生和人工确认成果使用不同状态表达；失效引用、
缺少核心字段、无坐标和未核验井点进入断链复核队列。接口不返回材料文件路径、正文、人员身份、电话、
证件号、车牌或精确井点坐标，也不新增修改、确认或自动补证能力。操作与验收方法见
[单案证据关系图谱运行手册](./docs/evidence-graph-runbook.zh-CN.md)。

## 双域态势研判工作台

`v3.0` 新增只读态势工作台，把当前 7—90 天窗口与紧邻的等长上一窗口比较，识别案件数量、类型、
作案手法和相对集中时点变化，计算历史聚集热点及重点井空间关注顺序。系统只突出最多三项带证据编号的
核查重点，并生成可导出的一页 Markdown 简报；无数据时不制造建议。功能不依赖外部模型，不做犯罪预测、
自动串案或巡逻调度。操作与验收方法见
[双域态势研判工作台运行手册](./docs/situation-analysis-runbook.zh-CN.md)。

部署开关、数据出域、故障降级、评测 Harness 和八周验收门槛见
